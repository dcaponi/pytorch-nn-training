GPT: A Decoder-Only Model

Remove the encoder. Remove cross-attention. What stays is a stack of causally masked transformer blocks that predict the next token. Make that several thousand times larger, and it is each large language model that you have used. This chapter builds one. Then it examines the two things that separate a trained model from a useful one: how you sample from it, and how fast you can do that.

Why the encoder was optional

Chapter 09 needed two stacks because it had two sequences: an English source to read and a French target to write. Cross-attention connected them.

Text continuation has only one sequence. The context is the prefix of the text that you generate, and causal self-attention already reads it. There is no second sequence. Thus cross-attention has nothing to attend to, and the encoder has no input. Both disappear, and the architecture becomes simpler, not more complex.

Key concept The last row is why language models scale and translation models do not. Parallel corpora are expensive and limited. Raw text is neither. Each position in each document is a free supervised example. Because of the causal mask, a document of 1,000 tokens gives 1,000 examples in one parallel forward pass. The only limits are compute and data. Under exactly that condition, scaling laws become interesting.

Pre-norm, and why this differs from Chapter 08

Chapter 08 used post-norm, as in the original 2017 paper. GPT-2 and later models use pre-norm, and so does the notebook here:

$$\text{post-norm:}\quad x \leftarrow \operatorname{LN}\big(x + F(x)\big) \qquad\qquad \text{pre-norm:}\quad x \leftarrow x + F\big(\operatorname{LN}(x)\big)$$

The difference is what the residual path goes through. In post-norm, each skip connection goes through a normalization. Thus the "clear path" for gradients has an interruption at each layer. In pre-norm, the path really has no interruption. From the loss to layer 1, the gradient can move by pure addition.

The practical results are large. Pre-norm trains deep stacks without learning-rate warmup. It tolerates higher learning rates, and it is much less likely to diverge. With careful tuning, post-norm sometimes gets slightly better final quality. That is why the original paper used it. But almost no model trained since 2019 uses it.

Three details in the model

Learned positional embeddings

GPT does not use the fixed sinusoids of Chapter 08. It uses an ordinary nn.Embedding(block_size, n_embd), and gradient descent selects the position codes. This is simpler, and it works at least as well. But it sets an absolute limit on the context length. There is no embedding vector for position block_size. Thus a longer input does not become slowly worse. It gives an error.

That hard limit is why the extension of the context window of a trained model is a research problem, not a configuration change. It is also why rotary embeddings (RoPE) have mostly replaced both approaches in current models. RoPE encodes relative position. It rotates $Q$ and $K$ inside each attention layer.

Weight tying

self.lm_head.weight = self.tok_emb.weight

The input embedding maps token → vector. The output head maps vector → token scores. These are two inverse views of one relation, so they share a matrix. This saves $V \times d$ parameters. That is very few at $V = 73$ characters, but approximately 38 million at a vocabulary of 50k and $d = 768$. It also usually improves perplexity. It does not only save memory. The symmetry is real. It is not a convenient trick.

Depth-scaled initialization

Each block adds to the residual stream. With $N$ blocks, each one adds independent noise, so the variance of the stream increases linearly with depth. To cancel this, scale the initialization of the residual projections by $1/\sqrt{2N}$. Then the activations stay in the same range at layer 1 and at layer 48.

A one-line sanity check worth building the habit around The first loss of a correctly initialized model must be almost exactly $\ln(V)$, the loss of a uniform distribution. The 73-character model of the notebook starts within a few thousandths of $\ln 73 = 4.290$. (The exact value changes a little with the seed.) If the initial loss is much higher, the model starts confident and wrong, not uniformly uncertain. Almost always, this means that the standard deviation of the initialization is too large. This check costs one forward pass. It finds a full class of bugs before you waste an hour on training.

Decoding: where the character of the output is decided

Training decides what the model believes. Sampling decides what it says. The same model can give anything from robotic repetition to incoherence, and only this choice causes the difference.

Temperature divides the logits before the softmax. It reweights the full distribution, but it never cuts it off. Each token keeps some probability. Thus, over hundreds of steps, the model will eventually sample from the absurd tail. Increase the temperature, and watch the flat tail rise.

Top-k keeps the $k$ tokens with the highest probability and normalizes again. It cuts the tail, which fixes that problem. But it uses a fixed pool size that ignores the context. Set $k = 5$ in the widget. Then think of two situations. After "the", the model is really uncertain across dozens of possible nouns. After "Alice was beginning t", it is 99% certain of "o". Top-k treats both in the same way.

Nucleus sampling (top-p) keeps the smallest set of tokens whose cumulative probability is more than $p$. The pool adapts. It is wide where the model is uncertain, and narrow where the model is confident. Decrease $p$ to 0.9, and watch the pool size change as you also change the temperature. That is why top-p at 0.9, with a temperature of approximately 0.8, is the default almost everywhere.

Greedy decoding and the repetition trap If you always take the argmax, generation is deterministic. For open-ended generation, that is fatal. When the model comes back to a state that it visited before, it must give the same continuation forever. The notebook sample at $T = 0.1$ shows this clearly: "the was to go the trees the was on the same to the…". Compare translation, where beam search (a more thorough relative of greedy) really helps. Translation has approximately one correct answer. Storytelling does not. If you search harder for "the most likely continuation", you find bland text.

The KV cache

The simple generation loop of Chapter 09 wastes work. At step $t$, it runs the full model over all $t$ previous tokens. But their keys and values do not change, because the causal mask makes sure that the representation of a past token never depends on a future one.

A KV cache stores $k$ and $v$ for each layer, and it adds one column at each step. Thus each step processes exactly one token. Generation divides into two phases. Production inference servers describe it in exactly this way:

  • Prefill: run the full prompt through in one batched pass, and fill the cache. This phase is limited by compute. It is parallel and efficient.
  • Decode: one token at a time. Read the cache and extend it. This phase is limited by memory bandwidth. It is sequential, and almost all the time of a long generation goes here.
Key concept — a result the notebook gets "wrong"

On the 0.8M-parameter model of the notebook, the KV cache measures slower than the loop without the cache. That is a real result, not a broken implementation. It teaches more than a clean speedup would.

Count operations, not seconds. Without the cache, each new token pushes 128 positions through the stack. With the cache, it pushes one. The cache does approximately two orders of magnitude less arithmetic. But at this size, each GPU kernel launch costs more than the arithmetic that it does. The version without the cache does its 128 positions in one well-batched call. The cached version makes the same number of very small calls, which are mostly overhead.

The algorithmic saving is real, and it increases linearly with context length. Whether you can see it depends on whether your kernels are large enough to be larger than their own launch overhead. At production scale they are, by a very large amount. That is why each serving stack uses a cache. Optimization results that are true asymptotically but reverse at small scale are common. This is a cheap way to learn not to trust a single benchmark.

The cache also costs memory. It holds $2 \times n_{\text{layer}} \times n_{\text{head}} \times T \times d_k$ floats for each sequence. That increases linearly with context, and with the number of concurrent users. For a large served model, the KV cache, not the weights, decides how many requests you can serve at the same time. That is why methods that make it smaller get so much attention: multi-query attention, grouped-query attention and cache quantization.

What this model is, and is not

The model of the notebook gets to a validation loss of approximately 1.51 nats. That is a perplexity of 4.5, against a uniform baseline of 73. It has learned spelling, capital letters after full stops, matched quotation marks, and the dialogue punctuation of Carroll. It has learned very little about meaning. That is exactly what 145k characters of training data predict.

The gap between this model and a frontier model is only a matter of quantity. A frontier model has more parameters, much more data, and subword tokenization instead of characters. It also has a post-training phase (instruction tuning, RLHF or DPO) that this course does not cover. The architecture in the notebook is the real architecture. Think about that for a moment. It is really surprising, and it is why the scaling-law literature reads the way it does.

By hand — exercise 10.1

Do causal attention and next-token prediction from start to end, on a three-token sequence with $d_k = 1$ (so each vector is one number).

tokens: "the" "cat" "sat" queries: q = [1.0, 2.0, 1.0] keys: k = [1.0, 1.0, 2.0] values: v = [0.0, 4.0, 8.0] d_k = 1, so the scale factor is 1/√1 = 1 — no scaling to apply. e^0 = 1.000 e^1 = 2.718 e^2 = 7.389 e^{-1} = 0.368
  1. Calculate the full $3 \times 3$ score matrix $q_i k_j$.
  2. Apply the causal mask, then apply softmax to each row.
  3. Calculate the attention output at each of the three positions.
  4. The output of position 3 goes into a language-model head with weight $W = [0.5, -0.5]^\top$ and no bias. This gives two logits for a vocabulary of two words, {"down", "up"}. Calculate the logits and the predicted distribution.
  5. The true next word is "up". Calculate the loss and the gradient on both logits.
Worked solution

1. Entry $(i,j) = q_i k_j$:

k=1.0 k=1.0 k=2.0 q=1.0 1.0 1.0 2.0 q=2.0 2.0 2.0 4.0 q=1.0 1.0 1.0 2.0

2. Mask all entries above the diagonal. Then apply softmax to each row over the entries that stay.

row 1: [1.0, −∞, −∞] → [1.000, 0, 0] row 2: [2.0, 2.0, −∞] → e^2, e^2 tie → [0.500, 0.500, 0] row 3: [1.0, 1.0, 2.0] → [2.718, 2.718, 7.389] / 12.825 → [0.212, 0.212, 0.576]

3. The weighted sums of $v = [0, 4, 8]$:

out₁ = 1.000(0.0) = 0.000 out₂ = 0.500(0.0) + 0.500(4.0) = 2.000 out₃ = 0.212(0.0) + 0.212(4.0) + 0.576(8.0) = 5.456

Position 1 can only return its own value, as exercise 06.1 showed. Position 3 uses itself most (0.576) because its key is the largest. But it really mixes in the earlier context.

4. Apply the head to the scalar 5.456:

z = [0.5 × 5.456, −0.5 × 5.456] = [2.728, −2.728] difference = 5.456, so softmax([2.728, −2.728]) = softmax([5.456, 0]) e^5.456 ≈ 234.1, e^0 = 1 → sum 235.1 ŷ = [0.9957, 0.0043] ("down" 99.6%, "up" 0.4%)

5. The truth is "up", index 1, so $y = [0, 1]$:

L = −ln(0.0043) = 5.45 nats ∂L/∂z = ŷ − y = [0.9957 − 0, 0.0043 − 1] = [+0.996, −0.996]

The loss is 5.45 nats, against a uniform-guess baseline of $\ln 2 = 0.69$. The model is confident and badly wrong. Thus the gradient is close to its maximum magnitude of 1. This is the $\hat{y} - y$ cancellation doing exactly what it was designed to do. No saturation term slows the correction. Note also that the two gradients sum to zero, for the same reason as in exercise 00.21.

By hand — exercise 10.2

Do the sampling arithmetic. Which tokens really stay after each strategy?

probabilities over six tokens, already softmaxed at T = 1: the 0.40 a 0.25 my 0.15 one 0.10 seven 0.07 purple 0.03
  1. Which tokens stay with top-k at $k = 3$? What is the probability of "the" after normalization?
  2. Which tokens stay with top-p at $p = 0.8$? Show the running cumulative sum.
  3. Now suppose that the model is much more certain, with probabilities $[0.97, 0.01, 0.01, 0.005, 0.003, 0.002]$. Which tokens stay with top-k at $k = 3$? Which stay with top-p at $p = 0.8$?
  4. Use part 3 to state, in one sentence, what top-p gives you that top-k cannot.
Worked solution

1. The three highest: the, a, my, with a total of $0.40 + 0.25 + 0.15 = 0.80$. After normalization, "the" becomes $0.40 / 0.80 = \mathbf{0.50}$. Note that the cut makes the tokens that stay more likely. That is a second effect of both methods, and people often miss it.

2. Add from the top until the sum gets to 0.8:

the 0.40 cumulative 0.40 a 0.25 cumulative 0.65 my 0.15 cumulative 0.80 ← reaches p, stop here one 0.10 excluded

These are the same three tokens. On this distribution, the two methods agree by chance.

3. Top-k with $k=3$ keeps the, a, my. That is still exactly three. The second and third have probability 0.01 each, which the model considers almost impossible. Top-p with $p=0.8$ stops at the first token, because 0.97 is already more than 0.8. Thus the pool is {the} alone.

4. Top-p changes the pool size to match the real confidence of the model, wide when the model is really uncertain and as narrow as one token when it is not. Top-k always keeps the same number of candidates. Thus, depending on the distribution, it either lets in almost impossible tokens or discards real ones.

In the wild

Here is the same model in the ecosystem that people will really give you: 

from transformers import GPT2Config, GPT2LMHeadModel

model = GPT2LMHeadModel(GPT2Config(
    vocab_size=50257, n_positions=1024,
    n_embd=768, n_head=12, n_layer=12))

out = model(input_ids, labels=input_ids)   # out.loss is the shift, done for you
model.generate(ids, do_sample=True, temperature=0.8, top_p=0.9,
               use_cache=True)             # your sampling loop and KV cache

Match it to what you built. GPT2Block is your Block. use_cache is your CachedAttention. labels= does the same one-token shift. The config fields are the hyperparameters that you selected by hand. GPT-2 is this notebook at 124M parameters. Think about that. The gap is scale, data and a BPE tokenizer, not architecture.

The library is useful at inference. It gives batched generation, beam search, stopping criteria, quantized loading, and a KV cache that is correct at the boundaries where yours is not (see the block_size assertion in the notebook). Use it. But know what each argument does, because that separates configuring a model from understanding one.

Feel for the numbersMust do

The numbers for language models cover many orders of magnitude. Thus they are easy to quote and difficult to check. These reference values let you tell a possible claim from an impossible one.

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. A BPE model reports a validation loss of 3.0. What is the perplexity? What fraction of the chance-level perplexity is that?
  2. GPT-2 small (124M) trained on 300B tokens. Approximately how many FLOPs is that? Can one person afford it?
  3. Your character model reports a validation perplexity of 1.02. Are you happy?
Answers

1. $e^{3.0} = 20.1$, against a chance perplexity of 50,257. That is approximately 0.04% of it. The model went from fifty thousand possible next tokens to twenty.

2. $6 \times 1.24\times10^{8} \times 3\times10^{11} = 2.2\times10^{20}$ FLOPs. At a realistic 50 TFLOP/s sustained on one good GPU, that is approximately 50 GPU-days. It is expensive, but it does not need an institution. The same formula for a 70B model and 15T tokens gives $6\times10^{24}$. That is four orders of magnitude more, and far out of reach. With that one formula, you can tell the two situations apart without asking anyone.

3. No. Be alarmed. Perplexity 1.02 means that the model is almost perfectly certain of each next character, and no language model should be. Almost certainly, your validation set leaks into training, or you evaluate on the training split.

The habit. Change each loss to perplexity before you quote it, and always give the chance value next to it. A loss without its baseline is not a result.

What a good answer covers — open this afterwards, not before
  1. The encoder and the cross-attention sublayer are removed. What stays is causally masked self-attention and a feed-forward network.
  2. The target is the input shifted by one. Thus each position is both an input and a label at the same time.
  3. Thus the model needs no labeled pairs. Any text is training data, and that is the source of the scale.
  4. The causal mask makes it legitimate to score each position in one parallel pass, without a position seeing its own answer.
  5. Generation is the same type of process as in Chapter 09: one token at a time, with $O(L^2)$ wasted work if there is no cache.

Most common miss. An answer describes it only as a simpler architecture. The interesting result is economic. Without the encoder, "we need aligned sentence pairs" becomes "we need text". That is the reason these models became large.
