A Neural Network from Scratch

This chapter uses one network, four training examples and no framework. At the end of it, you will calculate a forward pass, a loss and each gradient in a two-layer network with only arithmetic. You will also know exactly which line of PyTorch replaces each step.

XOR: the smallest problem that needs a hidden layer

The exclusive-or function is the traditional first problem, and there is a good reason. It is the smallest dataset that a network without a hidden layer cannot learn. There is a proof of this.

$x_1$$x_2$$y$
000
011
101
110

Plot those four points. The two points with label 1 are on one diagonal. The two points with label 0 are on the other diagonal. A model of the form $\hat{y} = \sigma(w_1x_1 + w_2x_2 + b)$ can divide the plane with only one straight line. The decision boundary is exactly where $w_1x_1 + w_2x_2 + b = 0$. No straight line separates one diagonal from the other. More training does not help. It is a geometric impossibility. This observation stopped most neural network research in the 1970s.

The fix is a hidden layer. It is a first transformation that bends the space, so that a straight line works in the new coordinates. Learn this idea exactly, because each layer of each deep network does it.

Key concept A neural network is a stack of linear maps (matrix multiplications, Chapter 00) and elementwise non-linearities, one after the other. The linear maps rotate, scale and shear the space. The non-linearities fold it. When you repeat the two, they bend the input space until the classes become linearly separable. Then the last layer draws the straight line. Without the non-linearity between them, two linear maps become one linear map ($W_2(W_1x) = (W_2W_1)x$). Then the extra layer gives you nothing.
Example — watching the fold happen

Use two hidden units with these weights. Put all four XOR inputs through them. Unit 1 is on when "at least one input is on". Unit 2 is on when "both inputs are on".

unit 1: z = 20x₁ + 20x₂ − 10 unit 2: z = 20x₁ + 20x₂ − 30 x₁ x₂ │ z₁ a₁=σ(z₁) │ z₂ a₂=σ(z₂) │ y ──────┼─────────────────┼─────────────────┼──── 0 0 │ −10 0.00 │ −30 0.00 │ 0 0 1 │ 10 1.00 │ −10 0.00 │ 1 1 0 │ 10 1.00 │ −10 0.00 │ 1 1 1 │ 30 1.00 │ 10 1.00 │ 0

In the original coordinates, the two classes are on opposite diagonals, and no line separates them. In the new $(a_1, a_2)$ coordinates, there are three different points: $(0,0)$ for label 0, $(1,0)$ for label 1, and $(1,1)$ for label 0. The line $a_1 - a_2 = 0.5$ separates them cleanly. The hidden layer did not classify anything. It moved the points until a straight line was sufficient. Each hidden layer in each network does this.

Architecture and shapes

We use two inputs, four hidden units and one output. The network processes all four training examples at the same time, as a batch. Thus each operation is a matrix multiplication.

TensorShapeMeaning
$X$(4, 2)4 examples, 2 features each
$W_1$(2, 4)input → hidden weights
$b_1$(1, 4)hidden biases
$W_2$(4, 1)hidden → output weights
$b_2$(1, 1)output bias
$Y$(4, 1)4 targets

The shape of a weight tells you what a layer does. (2, 4) means "takes 2 features and makes 4". The batch dimension is always first, and it never changes. If you learn only one debug habit from this book, learn this one: when something breaks, print the shapes.

The forward pass

$$Z_1 = XW_1 + b_1 \qquad A_1 = \sigma(Z_1) \qquad Z_2 = A_1W_2 + b_2 \qquad A_2 = \sigma(Z_2)$$

That is four lines, and $A_2$ is the prediction. Before we look at the mechanics, learn the names. They are not arbitrary, and nothing later makes sense without them.

Why each layer has two names

A layer does two things. Each thing gets its own letter, because the backward pass needs both of them separately.

Z "pre-activation" what the matrix multiply produced, before anything was squashed Z1 = X W1 + b1 A "activation" the same numbers after the sigmoid A1 = sigma(Z1)

The subscript is the layer: $Z_1, A_1$ for the hidden layer, and $Z_2, A_2$ for the output. $A_2$ has a second name. It is also $\hat{y}$, the prediction, because there is nothing more to do to it.

Why keep both, and not overwrite one? Because the backward pass needs each one for a different reason. It needs $Z_1$ to find how steep the sigmoid was here, which is $\sigma'(Z_1)$. It needs $A_1$ because $A_1$ was the input to the next layer, and the gradient of a weight always comes from its input. If the forward pass discards either one, the backward pass must calculate it again. That is exactly why frameworks keep activations, and why memory increases with depth.

Two mechanisms inside those four lines need more explanation.

Every entry is a dot product

The matrix product $XW_1$ gives a (4, 4) result. Its entry $(i, j)$ is the dot product of the features of example $i$ with the weights of hidden unit $j$. That is all that a linear layer does: each output unit takes a weighted vote over all the inputs. Step through the widget below. See how each output cell comes from one row and one column.

Broadcasting the bias

$b_1$ has shape (1, 4), but the code adds it to a (4, 4) matrix. NumPy and PyTorch both stretch the length-1 dimension to match. They add the same bias vector to each row, so each example gets the same bias. That is what you want. Broadcasting is convenient, but it also causes many silent bugs. Suppose that you have a (4, 1) where you wanted a (1, 4). It broadcasts into a (4, 4) of incorrect values, and you get no error.

Sigmoid

$$\sigma(z) = \frac{1}{1 + e^{-z}} \qquad\qquad \sigma'(z) = \sigma(z)\big(1 - \sigma(z)\big)$$

The sigmoid changes any real number into a number in $(0, 1)$. Thus we can read the output as a probability, as Chapter 00 said we must. You can write its derivative with its own output. Thus, during backpropagation, you can use the value that you already calculated. You do not have to calculate an exponential again.

Move the input past $\pm 5$, and see the derivative curve become flat. That is saturation, and it is the main problem of the sigmoid. A unit far from zero stops learning. Each gradient that comes from above is multiplied by a very small number on its way down: 0.0066 at $z = 5$, and 0.000045 at $z = 10$. Note also that the maximum of the derivative is only 0.25. Stack ten sigmoid layers. In the best case, the gradient is multiplied by $0.25^{10} \approx 10^{-6}$ before it gets to the first layer. This is the vanishing-gradient problem. It is why ReLU and GELU replaced the sigmoid in all hidden layers. Change the selector above to compare them. Use the sigmoid only where you really need a probability: at the output.

The loss

The output is a probability, and the target is binary. Thus Chapter 00 already told us what to use: the Bernoulli negative log-likelihood.

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N}\Big[y_i \log a_{2,i} + (1-y_i)\log(1 - a_{2,i})\Big]$$
Numerical trap If the network gives exactly 0 or 1, this becomes $\log 0 = -\infty$, and your loss becomes nan. It stays nan, because nan goes into each gradient and weight after it. From scratch, the fix is to clip: np.clip(a2, 1e-7, 1 - 1e-7). BCEWithLogitsLoss in Chapter 02 removes exactly this hazard, because it never calculates the probability.

All of it, as one expression

Before you differentiate anything, look at the full calculation written one time. The four forward equations make the calculation easy, but they are not four separate functions. If you put each equation into the next one, you get one expression. That expression is what the loss really is:

$$\mathcal{L}(W_1, b_1, W_2, b_2) \;=\; \text{BCE}\Big(\; \sigma\big(\,\sigma(XW_1 + b_1)\,W_2 + b_2\,\big)\;,\; y \Big)$$

Read it from the inside to the outside. Each step of the forward pass is there, in sequence:

  1. Multiply the inputs by $W_1$ and add $b_1$.
  2. Apply the sigmoid.
  3. Multiply by $W_2$ and add $b_2$.
  4. Apply the sigmoid again.
  5. Compare with $y$.

Nothing is hidden and nothing is shortened. This one line is the network.

Now see what it tells you about differentiation. Exactly four things can change. Each one occurs exactly one time, and each one is inside a different number of operations. That count is all of backpropagation:

Thus $\partial\mathcal{L}/\partial W_2$ will be a short chain, and $\partial\mathcal{L}/\partial W_1$ will be a longer one. The difference between them is not a different idea. It is two extra factors, because $W_1$ is two operations deeper. Each formula in the next section applies that observation.

Backpropagation

We need $\partial\mathcal{L}/\partial W$ for all four parameter tensors. Chapter 00 did this calculation entry by entry, with real numbers, for an XOR network with two hidden units. Here the network has four hidden units, and the goal is code. Backpropagation is not a new theorem. It is the chain rule, applied in a specific sequence. It keeps intermediate results and uses them again, so that it does not calculate them two times.

Start at the output

The loss is the only value that we really care about. Thus the backward pass starts there and moves toward the input. The first question is the simplest possible question: if the prediction $a_2$ was slightly larger, would the loss increase or decrease?

That is only a derivative of the loss formula. Thus, take the loss for one example and differentiate it. Only two terms contain $a_2$:

$$\mathcal{L}_{\text{one example}} = -\Big[\,y\log a_2 \;+\; (1-y)\log(1 - a_2)\,\Big]$$

The derivative of $\log a$ is $1/a$. By the chain rule, the derivative of $\log(1-a)$ is $-1/(1-a)$. Thus:

dL/da2 = -[ y · (1/a2) + (1-y) · (-1/(1-a2)) ] = -[ y/a2 - (1-y)/(1-a2) ] put the two fractions over the common denominator a2(1-a2): = -[ y(1-a2) - (1-y)a2 ] / [ a2(1-a2) ] expand the top: y - y·a2 - a2 + y·a2 = y - a2 the y·a2 terms cancel = -( y - a2 ) / [ a2(1-a2) ] = ( a2 - y ) / [ a2(1-a2) ] <- flip the sign, tidier

The average over the $N$ examples in the batch puts a $1/N$ in front. That is the source of the factor: it is the "mean" in "mean loss", and nothing more. We also need the derivative of the sigmoid itself, from Chapter 00:

$$\frac{\partial \mathcal{L}}{\partial a_2} = \frac{1}{N}\left(\frac{a_2 - y}{a_2(1-a_2)}\right) \qquad \frac{\partial a_2}{\partial z_2} = a_2(1-a_2)$$

Now multiply them. The chain rule says to do this when you go one more step back: from the prediction $a_2$ to the number $z_2$ that made it. See what happens. The $a_2(1-a_2)$ in the denominator is exactly the $a_2(1-a_2)$ from the sigmoid. Thus they cancel completely:

$$\delta_2 = \frac{\partial \mathcal{L}}{\partial z_2} = \frac{1}{N}(a_2 - y)$$
What $\delta$ is, and why it gets a name

$\delta_2$ is not new notation without a reason. It is a short name for one specific quantity: the derivative of the loss with respect to the pre-activation of a layer, $\partial\mathcal{L}/\partial z$. It gets a name because all the other gradients in that layer come from it:

given delta for a layer, you immediately get: the weight gradient dL/dW = (what came in)^T · delta the bias gradient dL/db = sum of delta over the batch the PREVIOUS layer's delta_prev = (delta · W^T) * sigma'(z_prev)

Thus the backward pass is only this: calculate $\delta$ for the last layer, read its two gradients, and give a $\delta$ to the layer before it. Then do it again. Informally, $\delta$ is "how wrong the output of this layer was, measured in a form that the layer can use". That is why people often call it the error signal. For the output layer, it is exactly the prediction minus the target.

Key concept This is the same cancellation as the softmax/cross-entropy pair in Chapter 00. This is not a coincidence: sigmoid + BCE is the two-class special case of softmax + cross-entropy. The signal that starts the full backward pass is only prediction minus target. It has no saturation factor and nothing makes it smaller. If we used MSE, the $\sigma'(z_2)$ term would stay. It would slow learning exactly when the model is most wrong.

Gradients for the output layer

Because $z_2 = a_1W_2 + b_2$, and $\partial z_2/\partial W_2 = a_1$:

$$\frac{\partial \mathcal{L}}{\partial W_2} = A_1^{\top}\delta_2 \qquad \frac{\partial \mathcal{L}}{\partial b_2} = \sum_i \delta_{2,i}$$

Check the shapes, because they are the best proof that you wrote it correctly. $A_1^\top$ is (4, 4) and $\delta_2$ is (4, 1). Thus the product is (4, 1). That is exactly the shape of $W_2$, as a gradient must be. The bias gradient sums over the batch. The same $b_2$ broadcast to all four examples, so all four contributions add together.

Rule of thumb The gradient for a weight is always (what came in)ᵀ × (what must change at the output). Each backward formula in this book uses that pattern, also the formulas for attention.

What a gradient actually is

Be very exact about this point. When people start to type the code, this is where they stop. $\partial\mathcal{L}/\partial W_2$ is not a new type of object, and it is not one number. It is a matrix with exactly the same shape as $W_2$. The entry in row $j$, column $k$ is the ordinary partial derivative of the loss with respect to the one number in row $j$, column $k$ of $W_2$.

$W_2$ is (4, 1): four hidden units go into one output. Thus its gradient has four entries. Here they are in full:

[ W2[0,0] ] [ dL/dW2[0,0] ] W2 = [ W2[1,0] ] dL/dW2 = [ dL/dW2[1,0] ] [ W2[2,0] ] [ dL/dW2[2,0] ] [ W2[3,0] ] [ dL/dW2[3,0] ] shape (4, 1) shape (4, 1) <- always

Each of those four numbers answers one concrete question: if I make this one weight a very small amount larger, and change nothing else, does the loss increase or decrease, and how fast? That is all. The gradient is those four answers, in the same shape as the weights, so that you can subtract one from the other.

You could also calculate each entry from its definition. Entry $j$ of $\partial\mathcal{L}/\partial W_2$ adds two things over each example in the batch: how much the hidden activation $j$ of that example contributed, and how wrong the output of that example was:

$$\frac{\partial\mathcal{L}}{\partial W_2[j,0]} \;=\; \sum_{n} A_1[n, j]\;\delta_2[n, 0]$$

As a loop, this is what you would type if you did not know about matrix products: 

dW2 = np.zeros_like(W2)                 # (4, 1), same shape as W2
for j in range(4):                      # every hidden unit
    total = 0.0
    for n in range(4):                  # every example in the batch
        total += A1[n, j] * d2[n, 0]
    dW2[j, 0] = total

And this is the reason to write it with matrices: those two loops are a matrix product. The product of $A_1^\top$ and $\delta_2$ calculates exactly that sum, for all $j$ at the same time: 

dW2 = A1.T @ d2                         # identical numbers, one line
Key concept A matrix product is not a new idea that makes this more difficult. It is a short way to write "for each output, sum over the batch of (what came in) times (what must change)". Many backward formulas in this book look like $\text{something}^\top \times \text{something}$. You can always change one back into the loop above and check it entry by entry. When a gradient has the wrong shape, that is how you find the cause.

The bias works the same way, with one axis fewer. $b_2$ is one number that the code adds to the output of each example. Thus a small change to it affects all four examples, and its derivative is the sum of what each example wanted:

dL/db2[0] = d2[0,0] + d2[1,0] + d2[2,0] + d2[3,0] in code: db2 = d2.sum(axis=0) shape (1,) <- same as b2

Propagate to the hidden layer

The hidden activations affected the loss only through $z_2$. Thus the error goes back through $W_2$, and then through the hidden sigmoid:

$$\delta_1 = \big(\delta_2 W_2^{\top}\big) \odot \sigma'(Z_1) \qquad\text{where}\qquad \sigma'(Z_1) = A_1 \odot (1 - A_1)$$

$\odot$ is elementwise multiplication. The two factors have different jobs. $\delta_2W_2^\top$ divides the blame: a hidden unit with a large weight gets a large part of it. $\sigma'(Z_1)$ measures how responsive that unit was. A saturated unit has $\sigma' \approx 0$, so it gets nothing, however much blame it deserves.

$$\frac{\partial \mathcal{L}}{\partial W_1} = X^{\top}\delta_1 \qquad \frac{\partial \mathcal{L}}{\partial b_1} = \sum_i \delta_{1,i}$$

This is the same pattern, one layer lower. That is the full algorithm:

  1. Calculate $\delta$ at the top.
  2. Multiply by a weight matrix to move down one layer.
  3. Multiply by an activation derivative to go through a non-linearity.
  4. At each layer, collect a weight gradient. Then go back to step 2.

And once more, for the hidden layer

This repeats the steps on purpose, because this is where people stop. $W_1$ is (2, 4): two input features go into four hidden units. Thus its gradient has eight entries, one for each weight, in exactly that shape:

[ W1[0,0] W1[0,1] W1[0,2] W1[0,3] ] W1 = [ W1[1,0] W1[1,1] W1[1,2] W1[1,3] ] shape (2, 4) [ dL/dW1[0,0] dL/dW1[0,1] dL/dW1[0,2] dL/dW1[0,3] ] dL/dW1= [ dL/dW1[1,0] dL/dW1[1,1] dL/dW1[1,2] dL/dW1[1,3] ] (2, 4)

Entry $(i, j)$ asks the same concrete question as before: make a small change to the weight between input feature $i$ and hidden unit $j$; what happens to the loss? You calculate it in the same way, with a sum over the batch:

$$\frac{\partial\mathcal{L}}{\partial W_1[i,j]} \;=\; \sum_{n} X[n, i]\;\delta_1[n, j]$$ 
dW1 = np.zeros_like(W1)                 # (2, 4), same shape as W1
for i in range(2):                      # every input feature
    for j in range(4):                  # every hidden unit
        total = 0.0
        for n in range(4):              # every example in the batch
            total += X[n, i] * d1[n, j]
        dW1[i, j] = total

dW1 = X.T @ d1                          # the same eight numbers, one line

Compare the two results. The pattern is exact. For $W_2$, the input was $A_1$ and the thing that must change was $\delta_2$. That gives $A_1^\top\delta_2$. For $W_1$, the input was $X$ and the thing that must change was $\delta_1$. That gives $X^\top\delta_1$. It is the same sentence for a different layer. The only work specific to $W_1$ was the calculation of $\delta_1$. From the previous section, that is $(\delta_2W_2^\top)\odot\sigma'(Z_1)$: the two extra factors that the nesting diagram predicted.

Gradient descent

$$W \leftarrow W - \eta\,\frac{\partial \mathcal{L}}{\partial W}$$

Move each parameter a small step in the direction that decreases the loss. The learning rate $\eta$ sets the size of the step. It is the most important number in training.

Push Step and watch. At a small learning rate, the ball moves downhill reliably but slowly. Increase $\eta$ past approximately 0.5, and it goes too far. The gradient at the new point is larger and points back the other way. Each step goes farther out, and the loss goes to infinity in a few iterations. When the loss is nan five steps into training, this is usually the cause. A lower learning rate is usually the fix.

Note also that this landscape has two minima. The start point and the step size decide which one you get to. From the default start, a learning rate of 0.2 gets to the left minimum, and 0.3 gets to the right one. Real loss surfaces have very many minima. That is why weight initialization is important, and why two runs of the same code give different results. It is also why we initialize $W$ randomly and not at zero. If all the weights are the same, each hidden unit calculates the same thing and gets the same gradient. Thus the units stay the same forever. This failure is called symmetry, and random initialization does the symmetry breaking. Biases can start at zero, because the random weights already break the symmetry.

The training loop

for epoch in range(10000):
    # forward
    z1 = X @ W1 + b1
    a1 = sigmoid(z1)
    z2 = a1 @ W2 + b2
    a2 = sigmoid(z2)

    # loss (for monitoring; the gradients below are already differentiated)
    loss = -np.mean(y * np.log(a2) + (1 - y) * np.log(1 - a2))

    # backward
    d2 = (a2 - y) / len(X)          # (4, 1)
    dW2 = a1.T @ d2                 # (4, 1)
    db2 = d2.sum(axis=0, keepdims=True)
    d1 = (d2 @ W2.T) * a1 * (1 - a1)  # (4, 4)
    dW1 = X.T @ d1                  # (2, 4)
    db1 = d1.sum(axis=0, keepdims=True)

    # update
    W2 -= lr * dW2; b2 -= lr * db2
    W1 -= lr * dW1; b1 -= lr * db1

Ten thousand epochs seems like too many for four data points. The cause is the small gradients of the sigmoid and a modest learning rate. The structure is what is important: forward, loss, backward, update. Each training loop in the rest of this book has these four steps. Chapter 02 replaces the six backward lines with loss.backward(), and the four update lines with optimizer.step(). But the structure of the loop never changes again.

By hand — exercise 01.1

Put one training example through a 2→2→1 network. The numbers are chosen so that each sigmoid gives a value from the list.

x = [1, 0] y = 1 learning rate η = 0.5 W1 = [[ 0.5, -0.5], b1 = [0, 0] [ 0.5, 0.5]] (rows = inputs, cols = hidden units) W2 = [[1.0], b2 = [0] [1.0]] σ(0) = 0.500 σ(0.5) = 0.622 σ(-0.5) = 0.378 σ(1.0) = 0.731
  1. Do the forward pass: calculate $z_1$, $a_1$, $z_2$ and $a_2$.
  2. Calculate the BCE loss. Use $\ln 0.731 \approx -0.313$.
  3. Do the backward pass: calculate $\delta_2$, then $\partial\mathcal{L}/\partial W_2$.
  4. Calculate $\delta_1$ and $\partial\mathcal{L}/\partial W_1$.
  5. Apply one gradient descent step to $W_2$. Did the update move the prediction toward the target?
Worked solution

1. Forward. With $x = [1, 0]$, the second input adds nothing. Thus $z_1$ is the first row of $W_1$:

z1 = [1, 0] @ W1 + b1 = [0.5, -0.5] a1 = [σ(0.5), σ(−0.5)] = [0.622, 0.378] z2 = a1 @ W2 + b2 = 0.622(1.0) + 0.378(1.0) = 1.000 a2 = σ(1.000) = 0.731

2. Loss. $y = 1$, so only the first BCE term stays: $\mathcal{L} = -\ln(0.731) = \mathbf{0.313}$.

3. Output layer. With $N = 1$:

δ2 = a2 − y = 0.731 − 1 = −0.269 ∂L/∂W2 = a1ᵀ δ2 = [0.622, 0.378]ᵀ × (−0.269) = [[−0.167], [−0.102]]

Both values are negative. Thus both weights must increase. This makes sense: the prediction is too low, and both hidden units give positive values.

4. Hidden layer. First, send the error back through $W_2$:

δ2 W2ᵀ = −0.269 × [1.0, 1.0] = [−0.269, −0.269] σ′(z1) = a1 ⊙ (1 − a1) = [0.622(0.378), 0.378(0.622)] = [0.235, 0.235] δ1 = [−0.269, −0.269] ⊙ [0.235, 0.235] = [−0.0632, −0.0632] ∂L/∂W1 = xᵀ δ1 = [1, 0]ᵀ × [−0.0632, −0.0632] = [[−0.0632, −0.0632], [ 0.0000, 0.0000]]

The second row is exactly zero because $x_2 = 0$. An input that added nothing to the forward pass gets no gradient. This is not an approximation. It is the chain rule. It is also why the weights of a dead input feature never change.

Note also the magnitude. $\delta_1$ is 0.063 and $\delta_2$ is 0.269. That is 4.3 times smaller after one sigmoid. The factor of 0.235 is $\sigma'$ near its maximum of 0.25. Multiply it ten times, and you have the vanishing gradient problem in one number.

5. Update.

W2 ← W2 − 0.5 × [[−0.167], [−0.102]] = [[1.0 + 0.0835], [1.0 + 0.0510]] = [[1.0835], [1.0510]] new z2 = 0.622(1.0835) + 0.378(1.0510) = 1.0713 new a2 = σ(1.0713) ≈ 0.745

The prediction moved from 0.731 to 0.745, toward the target of 1. The loss decreases from 0.313 to $-\ln(0.745) = 0.294$. That is one step of learning, calculated fully by hand. In the next chapter, loss.backward(); optimizer.step() does exactly this for you.

By hand — exercise 01.2

This is a short proof with no arithmetic. Show that a network with no activation function cannot solve XOR, at any depth.

  1. Write the two-layer network without activations: $\hat{y} = (XW_1 + b_1)W_2 + b_2$. Expand it and collect the terms.
  2. What family of functions can the network express?
  3. In one sentence, explain why this rules out XOR.
Worked solution

1. Expand with the distributive law:

$$\hat{y} = XW_1W_2 + b_1W_2 + b_2$$

2. Let $W' = W_1W_2$ (one (2, 1) matrix) and $b' = b_1W_2 + b_2$ (one scalar). Then $\hat{y} = XW' + b'$. That is a normal linear model, and the hidden layer is gone. This is true at any depth, because a product of matrices is a matrix.

3. The decision boundary of a linear model is a straight line. The two classes of XOR are on opposite diagonals of a square, and no straight line separates them. Thus depth without non-linearity gives exactly nothing. The non-linearity is not a detail of the architecture. It is the architecture.

In the wild

Nobody writes the six backward lines in production code. After this chapter, you know exactly what the framework replaces: 

model = nn.Sequential(nn.Linear(2, 4), nn.Sigmoid(),
                      nn.Linear(4, 1))
loss = nn.BCEWithLogitsLoss()(model(X), y)   # replaces the loss + clipping
loss.backward()                              # replaces d2, dW2, db2, d1, dW1, db1
optimizer.step()                             # replaces the four updates

The framework gives you correct derivatives for any graph, fused and numerically stable kernels, and GPU execution. It hides three facts. First, $\delta_2$ is prediction minus target. Second, a saturated unit gets nothing. Third, a dead input feature never changes. With those three facts, you can debug a model that trains but does not learn. From the framework side, you cannot see them.

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. You write a 3-class network from scratch. The first loss that it prints is 1.099. Is that good or bad?
  2. You have ten sigmoid layers. What is the largest possible product of their derivatives? What does that tell you about training the first layer?
  3. The first loss on a 10-class problem is 6.9. What one thing is most probably wrong?
Answers

1. $\ln 3 = 1.0986$. That is exactly correct. The network is correctly confused, as an untrained network should be.

2. $0.25^{10} = 9.5\times10^{-7}$. And that is the best case, with $z = 0$ for each unit. The first layer gets a maximum of one millionth of the signal that the last layer gets. This is a limit, not a tendency. Thus no learning rate can fix it.

3. $\ln 10 = 2.30$. Thus 6.9 means that the network starts confident and wrong. It puts most of its probability on incorrect classes. Almost always, the initial weights are too large. A network that starts at 6.9 must use its first steps to cancel its own initialization.

The habit. Predict the first loss before you run anything. It is the cheapest bug detector in this book, and it costs one logarithm.

Explain this to your favorite LLM, in your own words: how does the backward pass work, and why is computing it right-to-left the thing that makes it affordable? Then ask it to correct you. Ask it to question each part where you were vague, not only the parts where you were wrong, because the gaps are in the vague parts. Do not use the word backpropagation at all.

What a good answer covers — open this afterwards, not before
  1. The forward pass calculates intermediate values and keeps them, because the backward pass needs them.
  2. The loss is one scalar. Each parameter has a partial derivative of that one number.
  3. When you apply the chain rule from right to left, you calculate each shared sub-expression one time, not one time for each parameter. That reuse is all of the saving.
  4. Each layer needs its own stored input to make its weight gradient. That is why memory increases with depth and batch size.
  5. It is the chain rule plus a strategy to keep intermediate results. It uses no new calculus.

Most common miss. An answer explains what the backward pass calculates, but not why the sequence is important. If your explanation is also true for a calculation of each partial derivative separately from the start, you described differentiation, not the backward pass.
