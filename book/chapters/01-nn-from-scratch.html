A Neural Network from Scratch

This chapter uses one network, four training examples and no framework. At the end of it, you will calculate a forward pass, a loss and each gradient in a two-layer network with only arithmetic. You will derive backpropagation and gradient descent with only the derivative rules from Chapter 00. You will also know exactly which line of PyTorch replaces each step.

XOR: the smallest problem that needs a hidden layer

The exclusive-or function is the traditional first problem, and there is a good reason. It is the smallest dataset that a network without a hidden layer cannot learn. There is a proof of this.

Plot those four points. The two points with label 1 are on one diagonal. The two points with label 0 are on the other diagonal. A model of the form $\hat{y} = \sigma(w_1x_1 + w_2x_2 + b)$ can divide the plane with only one straight line. The decision boundary is exactly where $w_1x_1 + w_2x_2 + b = 0$. No straight line separates one diagonal from the other. More training does not help. It is a geometric impossibility. This observation stopped most neural network research in the 1970s.

The fix is a hidden layer. It is a first transformation that bends the space, so that a straight line works in the new coordinates. Learn this idea exactly, because each layer of each deep network does it.

Key concept A neural network is a stack of linear maps (matrix multiplications, Chapter 00) and elementwise non-linearities, one after the other. The linear maps rotate, scale and shear the space. The non-linearities fold it. When you repeat the two, they bend the input space until the classes become linearly separable. Then the last layer draws the straight line. Without the non-linearity between them, two linear maps become one linear map ($W_2(W_1x) = (W_2W_1)x$). Then the extra layer gives you nothing.

Architecture and shapes

We use two inputs, four hidden units and one output. The network processes all four training examples at the same time, as a batch. Thus each operation is a matrix multiplication.

TensorShapeMeaning
$X$(4, 2)4 examples, 2 features each
$W_1$(2, 4)input → hidden weights
$b_1$(1, 4)hidden biases
$W_2$(4, 1)hidden → output weights
$b_2$(1, 1)output bias
$Y$(4, 1)4 targets

The shape of a weight tells you what a layer does. (2, 4) means "takes 2 features and makes 4". The batch dimension is always first, and it never changes. If you learn only one debug habit from this book, learn this one: when something breaks, print the shapes.

The forward pass

$$Z_1 = XW_1 + b_1 \qquad A_1 = \sigma(Z_1) \qquad Z_2 = A_1W_2 + b_2 \qquad A_2 = \sigma(Z_2)$$

That is four lines, and $A_2$ is the prediction. Before we look at the mechanics, learn the names. They are not arbitrary, and nothing later makes sense without them.

Why each layer has two names

A layer does two things. Each thing gets its own letter, because the backward pass needs both of them separately.

Z "pre-activation" what the matrix multiply produced, before anything was squashed Z1 = X W1 + b1 A "activation" the same numbers after the sigmoid A1 = sigma(Z1)

The subscript is the layer: $Z_1, A_1$ for the hidden layer, and $Z_2, A_2$ for the output. $A_2$ has a second name. It is also $\hat{y}$, the prediction, because there is nothing more to do to it.

Why keep both, and not overwrite one? Because the backward pass needs each one for a different reason. It needs $Z_1$ to find how steep the sigmoid was here, which is $\sigma'(Z_1)$. It needs $A_1$ because $A_1$ was the input to the next layer, and the gradient of a weight always comes from its input. If the forward pass discards either one, the backward pass must calculate it again. That is exactly why frameworks keep activations, and why memory increases with depth.

Two mechanisms inside those four lines need more explanation.

Every entry is a dot product

The matrix product $XW_1$ gives a (4, 4) result. Its entry $(i, j)$ is the dot product of the features of example $i$ with the weights of hidden unit $j$. That is all that a linear layer does: each output unit takes a weighted vote over all the inputs. Step through the widget below. See how each output cell comes from one row and one column.

Broadcasting the bias

$b_1$ has shape (1, 4), but the code adds it to a (4, 4) matrix. NumPy and PyTorch both stretch the length-1 dimension to match. They add the same bias vector to each row, so each example gets the same bias. That is what you want. (Chapter 00 explains the rule, and why the bias gradient becomes a sum.) Broadcasting is convenient, but it also causes many silent bugs. Suppose that you have a (4, 1) where you wanted a (1, 4). It broadcasts into a (4, 4) of incorrect values, and you get no error.

Sigmoid

$$\sigma(z) = \frac{1}{1 + e^{-z}} \qquad\qquad \sigma'(z) = \sigma(z)\big(1 - \sigma(z)\big)$$

The sigmoid changes any real number into a number in $(0, 1)$. Thus we can read the output as a probability, as Chapter 00 said we must. You can write its derivative with its own output. Thus, during backpropagation, you can use the value that you already calculated. You do not have to calculate an exponential again.

Move the input past $\pm 5$, and see the derivative curve become flat. That is saturation, and it is the main problem of the sigmoid. A unit far from zero stops learning. Each gradient that comes from above is multiplied by a very small number on its way down: 0.0066 at $z = 5$, and 0.000045 at $z = 10$. Note also that the maximum of the derivative is only 0.25. Stack ten sigmoid layers. In the best case, the gradient is multiplied by $0.25^{10} \approx 10^{-6}$ before it gets to the first layer. This is the vanishing-gradient problem. It is why ReLU and GELU replaced the sigmoid in all hidden layers. Change the selector above to compare them. Use the sigmoid only where you really need a probability: at the output.

The loss

The output is a probability, and the target is binary. Thus Chapter 00 already told us what to use: the Bernoulli negative log-likelihood.

$$\mathcal{L} = -\frac{1}{N}\sum_{i=1}^{N}\Big[y_i \log a_{2,i} + (1-y_i)\log(1 - a_{2,i})\Big]$$
Numerical trap If the network gives exactly 0 or 1, this becomes $\log 0 = -\infty$, and your loss becomes nan. It stays nan, because nan goes into each gradient and weight after it. From scratch, the fix is to clip: np.clip(a2, 1e-7, 1 - 1e-7). BCEWithLogitsLoss in Chapter 02 removes exactly this hazard, because it never calculates the probability.

All of it, as one expression

Before you differentiate anything, look at the full calculation written one time. The four forward equations make the calculation easy, but they are not four separate functions. If you put each equation into the next one, you get one expression. That expression is what the loss really is:

$$\mathcal{L}(W_1, b_1, W_2, b_2) \;=\; \text{BCE}\Big(\; \sigma\big(\,\sigma(XW_1 + b_1)\,W_2 + b_2\,\big)\;,\; y \Big)$$

Read it from the inside to the outside. Each step of the forward pass is there, in sequence:

  1. Multiply the inputs by $W_1$ and add $b_1$.
  2. Apply the sigmoid.
  3. Multiply by $W_2$ and add $b_2$.
  4. Apply the sigmoid again.
  5. Compare with $y$.

Nothing is hidden and nothing is shortened. This one line is the network.

Now see what it tells you about differentiation. Exactly four things can change. Each one occurs exactly one time, and each one is inside a different number of operations. That count is all of backpropagation:

Thus $\partial\mathcal{L}/\partial W_2$ will be a short chain, and $\partial\mathcal{L}/\partial W_1$ will be a longer one. The difference between them is not a different idea. It is two extra factors, because $W_1$ is two operations deeper. Each formula in the next section applies that observation.

Backpropagation

We need $\partial\mathcal{L}/\partial W$ for all four parameter tensors. This section derives each one with only the rules from Chapter 00, Part 2: the logarithm rule, the chain rule, the partial-derivative rules and the sum over paths. Backpropagation is not a new theorem. It is the chain rule, applied in a specific sequence. It keeps intermediate results and uses them again, so that it does not calculate them two times. After the derivation, a smaller XOR network does the same calculation with numbers, entry by entry.

Start at the output

The loss is the only value that we really care about. Thus the backward pass starts there and moves toward the input. The first question is the simplest possible question: if the prediction $a_2$ was slightly larger, would the loss increase or decrease?

That is only a derivative of the loss formula. Thus, take the loss for one example and differentiate it. Only two terms contain $a_2$:

$$\mathcal{L}_{\text{one example}} = -\Big[\,y\log a_2 \;+\; (1-y)\log(1 - a_2)\,\Big]$$

The derivative of $\log a$ is $1/a$. By the chain rule, the derivative of $\log(1-a)$ is $-1/(1-a)$. Thus:

dL/da2 = -[ y · (1/a2) + (1-y) · (-1/(1-a2)) ] = -[ y/a2 - (1-y)/(1-a2) ] put the two fractions over the common denominator a2(1-a2): = -[ y(1-a2) - (1-y)a2 ] / [ a2(1-a2) ] expand the top: y - y·a2 - a2 + y·a2 = y - a2 the y·a2 terms cancel = -( y - a2 ) / [ a2(1-a2) ] = ( a2 - y ) / [ a2(1-a2) ] <- flip the sign, tidier

The average over the $N$ examples in the batch puts a $1/N$ in front. That is the source of the factor: it is the "mean" in "mean loss", and nothing more. We also need the derivative of the sigmoid itself, from Chapter 00:

$$\frac{\partial \mathcal{L}}{\partial a_2} = \frac{1}{N}\left(\frac{a_2 - y}{a_2(1-a_2)}\right) \qquad \frac{\partial a_2}{\partial z_2} = a_2(1-a_2)$$

Now multiply them. The chain rule says to do this when you go one more step back: from the prediction $a_2$ to the number $z_2$ that made it. See what happens. The $a_2(1-a_2)$ in the denominator is exactly the $a_2(1-a_2)$ from the sigmoid. Thus they cancel completely:

$$\delta_2 = \frac{\partial \mathcal{L}}{\partial z_2} = \frac{1}{N}(a_2 - y)$$
What $\delta$ is, and why it gets a name

$\delta_2$ is not new notation without a reason. It is a short name for one specific quantity: the derivative of the loss with respect to the pre-activation of a layer, $\partial\mathcal{L}/\partial z$. It is a matrix with the shape of $z$: here (4, 1), one number for each example. Entry $n$ tells you how much the loss changes when $z_2$ of example $n$ increases by a small amount. (This is the $\delta$ of Chapter 00, with $Y = z$.) It gets a name because all the other gradients in that layer come from it:

given delta for a layer, you immediately get: the weight gradient dL/dW = (what came in)^T · delta the bias gradient dL/db = sum of delta over the batch the PREVIOUS layer's delta_prev = (delta · W^T) * sigma'(z_prev)

Thus the backward pass is only this: calculate $\delta$ for the last layer, read its two gradients, and give a $\delta$ to the layer before it. Then do it again. Informally, $\delta$ is "how wrong the output of this layer was, measured in a form that the layer can use". That is why people often call it the error signal. For the output layer, it is exactly the prediction minus the target.

Key concept This is the same cancellation as the softmax/cross-entropy pair in Chapter 00. This is not a coincidence: sigmoid + BCE is the two-class special case of softmax + cross-entropy. The signal that starts the full backward pass is only prediction minus target. It has no saturation factor and nothing makes it smaller. If we used MSE, the $\sigma'(z_2)$ term would stay. It would slow learning exactly when the model is most wrong.

Gradients for the output layer

Now go one step further back, from $z_2$ to the parameters. Look at one entry: $z_2$ of example $n$ is $\sum_j A_1[n,j]\,W_2[j] + b_2$. With the partial-derivative rules from Chapter 00, $\partial z_2[n]/\partial W_2[j] = A_1[n,j]$, because each other term is a constant. And $\partial z_2[n]/\partial b_2 = 1$. But each weight is used for all four examples, so it has four paths to the loss. The sum over paths adds them. The next section writes that sum entry by entry. The result is:

$$\frac{\partial \mathcal{L}}{\partial W_2} = A_1^{\top}\delta_2 \qquad \frac{\partial \mathcal{L}}{\partial b_2} = \sum_i \delta_{2,i}$$

Check the shapes, because they are the best proof that you wrote it correctly. $A_1^\top$ is (4, 4) and $\delta_2$ is (4, 1). Thus the product is (4, 1). That is exactly the shape of $W_2$, as a gradient must be. The bias gradient sums over the batch. The same $b_2$ broadcast to all four examples, so all four contributions add together. This is the rule from Chapter 00: the gradient of a broadcast is a sum over the stretched axis.

Rule of thumb The gradient for a weight is always (what came in)ᵀ × (what must change at the output). Each backward formula in this book uses that pattern, also the formulas for attention.

What a gradient actually is

Be very exact about this point. When people start to type the code, this is where they stop. $\partial\mathcal{L}/\partial W_2$ is not a new type of object, and it is not one number. It is a matrix with exactly the same shape as $W_2$. The entry in row $j$, column $k$ is the ordinary partial derivative of the loss with respect to the one number in row $j$, column $k$ of $W_2$.

$W_2$ is (4, 1): four hidden units go into one output. Thus its gradient has four entries. Here they are in full:

[ W2[0,0] ] [ dL/dW2[0,0] ] W2 = [ W2[1,0] ] dL/dW2 = [ dL/dW2[1,0] ] [ W2[2,0] ] [ dL/dW2[2,0] ] [ W2[3,0] ] [ dL/dW2[3,0] ] shape (4, 1) shape (4, 1) <- always

Each of those four numbers answers one concrete question: if I make this one weight a very small amount larger, and change nothing else, does the loss increase or decrease, and how fast? That is all. The gradient is those four answers, in the same shape as the weights, so that you can subtract one from the other.

You could also calculate each entry from its definition. Entry $j$ of $\partial\mathcal{L}/\partial W_2$ adds two things over each example in the batch: how much the hidden activation $j$ of that example contributed, and how wrong the output of that example was:

$$\frac{\partial\mathcal{L}}{\partial W_2[j,0]} \;=\; \sum_{n} A_1[n, j]\;\delta_2[n, 0]$$

As a loop, this is what you would type if you did not know about matrix products: 

dW2 = np.zeros_like(W2)                 # (4, 1), same shape as W2
for j in range(4):                      # every hidden unit
    total = 0.0
    for n in range(4):                  # every example in the batch
        total += A1[n, j] * d2[n, 0]
    dW2[j, 0] = total

And this is the reason to write it with matrices: those two loops are a matrix product. The product of $A_1^\top$ and $\delta_2$ calculates exactly that sum, for all $j$ at the same time: 

dW2 = A1.T @ d2                         # identical numbers, one line
Key concept A matrix product is not a new idea that makes this more difficult. It is a short way to write "for each output, sum over the batch of (what came in) times (what must change)". Many backward formulas in this book look like $\text{something}^\top \times \text{something}$. You can always change one back into the loop above and check it entry by entry. When a gradient has the wrong shape, that is how you find the cause.

The bias works the same way, with one axis fewer. $b_2$ is one number that the code adds to the output of each example. Thus a small change to it affects all four examples, and its derivative is the sum of what each example wanted:

dL/db2[0] = d2[0,0] + d2[1,0] + d2[2,0] + d2[3,0] in code: db2 = d2.sum(axis=0) shape (1,) <- same as b2

Propagate to the hidden layer

The hidden activations affected the loss only through $z_2$. Thus the error goes back through $W_2$, and then through the hidden sigmoid. Do it for one entry first. Two steps of the chain rule give it:

step 1, back through the product z2[n] = sum_j A1[n,j] W2[j] + b2: A1[n,j] occurs only in z2[n], where W2[j] multiplies it dL/dA1[n,j] = delta2[n] * W2[j] one path, one product step 2, back through the sigmoid A1[n,j] = sigma(Z1[n,j]): A1[n,j] depends only on Z1[n,j] delta1[n,j] = dL/dA1[n,j] * sigma'(Z1[n,j]) one path, one product

Step 1 for all entries at the same time is $\delta_2 W_2^\top$: it is the rule "multiply by the other factor, transposed" from the transpose section of Chapter 00. Step 2 is an entry-by-entry product, $\odot$. Thus:

$$\delta_1 = \big(\delta_2 W_2^{\top}\big) \odot \sigma'(Z_1) \qquad\text{where}\qquad \sigma'(Z_1) = A_1 \odot (1 - A_1)$$

$\odot$ is elementwise multiplication. The two factors have different jobs. $\delta_2W_2^\top$ divides the blame: a hidden unit with a large weight gets a large part of it. $\sigma'(Z_1)$ measures how responsive that unit was. A saturated unit has $\sigma' \approx 0$, so it gets nothing, however much blame it deserves.

$$\frac{\partial \mathcal{L}}{\partial W_1} = X^{\top}\delta_1 \qquad \frac{\partial \mathcal{L}}{\partial b_1} = \sum_i \delta_{1,i}$$

This is the same pattern, one layer lower. That is the full algorithm:

  1. Calculate $\delta$ at the top.
  2. Multiply by a weight matrix to move down one layer.
  3. Multiply by an activation derivative to go through a non-linearity.
  4. At each layer, collect a weight gradient. Then go back to step 2.

And once more, for the hidden layer

This repeats the steps on purpose, because this is where people stop. $W_1$ is (2, 4): two input features go into four hidden units. Thus its gradient has eight entries, one for each weight, in exactly that shape:

[ W1[0,0] W1[0,1] W1[0,2] W1[0,3] ] W1 = [ W1[1,0] W1[1,1] W1[1,2] W1[1,3] ] shape (2, 4) [ dL/dW1[0,0] dL/dW1[0,1] dL/dW1[0,2] dL/dW1[0,3] ] dL/dW1= [ dL/dW1[1,0] dL/dW1[1,1] dL/dW1[1,2] dL/dW1[1,3] ] (2, 4)

Entry $(i, j)$ asks the same concrete question as before: make a small change to the weight between input feature $i$ and hidden unit $j$; what happens to the loss? You calculate it in the same way, with a sum over the batch:

$$\frac{\partial\mathcal{L}}{\partial W_1[i,j]} \;=\; \sum_{n} X[n, i]\;\delta_1[n, j]$$ 
dW1 = np.zeros_like(W1)                 # (2, 4), same shape as W1
for i in range(2):                      # every input feature
    for j in range(4):                  # every hidden unit
        total = 0.0
        for n in range(4):              # every example in the batch
            total += X[n, i] * d1[n, j]
        dW1[i, j] = total

dW1 = X.T @ d1                          # the same eight numbers, one line

Compare the two results. The pattern is exact. For $W_2$, the input was $A_1$ and the thing that must change was $\delta_2$. That gives $A_1^\top\delta_2$. For $W_1$, the input was $X$ and the thing that must change was $\delta_1$. That gives $X^\top\delta_1$. It is the same sentence for a different layer. The only work specific to $W_1$ was the calculation of $\delta_1$. From the previous section, that is $(\delta_2W_2^\top)\odot\sigma'(Z_1)$: the two extra factors that the nesting diagram predicted.

The same steps, for any number of layers

Each layer did the same three things. Thus you can write the backward pass one time, for a network of any depth. Number the layers $l = 1, \dots, k$, and let $A_0 = X$. Each layer calculates $Z_l = A_{l-1}W_l + b_l$ and $A_l = f(Z_l)$.

FORWARD A0 = X for l = 1 .. k: Z_l = A_(l-1) W_l + b_l keep A_(l-1) and Z_l A_l = f(Z_l) L = loss(A_k, Y) BACKWARD delta_k = dL/dZ_k from the loss: (A_k - Y)/N here for l = k down to 1: dL/dW_l = A_(l-1)^T delta_l what came in, transposed, times delta dL/db_l = delta_l.sum(axis=0) b_l was broadcast over the batch if l > 1: delta_(l-1) = (delta_l W_l^T) * f'(Z_(l-1)) * is elementwise UPDATE each parameter <- parameter - eta * its gradient (next section)

Each line of the backward pass comes from one rule in Chapter 00:

  • $\delta_k$ comes from the logarithm rule and the chain rule. The $\sigma'$ cancels, as in Start at the output.
  • The weight gradient comes from the partial-derivative rule (each weight multiplies one input) and the sum over paths (each weight is used for each example).
  • The bias gradient is the gradient of a broadcast: a sum over the batch axis.
  • The next $\delta$ comes from two chain-rule steps: through the matrix product (multiply by the other factor, transposed), then through $f$ (multiply entry by entry by $f'$).
Key concept — why the order is backward

Look at what each $\delta_l$ does. It gives two gradients, and it makes the next $\delta$. Thus each $\delta$ is calculated one time and used three times. Now suppose you calculated $\partial\mathcal{L}/\partial W_1$ separately, from the loss. You must multiply through every layer above it. Then for $\partial\mathcal{L}/\partial W_2$, you must do almost the same product again.

k layers, one chain-rule step per layer crossed each gradient separately: k + (k-1) + ... + 1 = k(k+1)/2 steps (5,050 for k = 100) backward, keeping delta: k steps (100 for k = 100)

The cost of the saving is memory. The backward pass needs each $A_{l-1}$ and each $Z_l$, so the forward pass must keep all of them. That is why training uses much more memory than inference, and why the memory increases with depth and with batch size.

What you are multiplying by, and what it is called

Each step of the backward pass multiplied the incoming gradient by something. That something has a name. The name occurs frequently from here on, and texts rarely explain it.

When one number depends on one number, the derivative is one number. When a vector of outputs depends on a vector of inputs, there is a derivative for each pair: each output with respect to each input. The natural place to put all of them is a grid:

for an operation taking m inputs to n outputs, the derivative is an n x m matrix, and entry (i, j) is d(output i) / d(input j) that matrix is called the JACOBIAN of the operation.

Thus a Jacobian is not a new type of mathematics. It is a table of ordinary partial derivatives, as in Chapter 00. The table has this arrangement so that you move a gradient back through an operation with one matrix multiplication by that table. That is the only reason it exists. It changes "apply the chain rule to each pair of things" into one product.

Key concept — and why elementwise functions are cheap

Think about the Jacobian of an elementwise function like ReLU or sigmoid. Output $i$ depends on input $i$ and on nothing more. Thus each off-diagonal entry is zero. For example, output 3 does not change when input 7 changes:

Jacobian of an elementwise f, for 3 values: [ f'(z1) 0 0 ] [ 0 f'(z2) 0 ] [ 0 0 f'(z3) ]

A multiplication by a diagonal matrix is the same as a multiplication entry by entry. That is why $f'(Z)$ occurs in the backward pass with a $\odot$, and not with a matrix product. It is also why the backward pass through an activation costs almost nothing. When a later chapter says that a gradient was "multiplied by a Jacobian per step", think of one of these matrices. A later chapter also says that the Jacobian of the softmax is $\operatorname{diag}(p) - pp^{\top}$. Note that the softmax is not elementwise. Thus its off-diagonal entries are not zero, and it costs more.

You can recover every line from the shapes alone

Do this one time. After that, you never have to memorize the backward pass. You can make it again on a whiteboard from only the forward shapes.

$\partial\mathcal{L}/\partial W_2$ must have the same shape as $W_2$, which is (h, K). You have two things: $A_1$ at (N, h) and $\delta_2$ at (N, K). There is exactly one way to multiply them and get (h, K): transpose $A_1$ and put it on the left. In the same way, $\partial\mathcal{L}/\partial A_1$ must be (N, h). The only arrangement of $\delta_2$ (N, K) and $W_2$ (h, K) that gives that shape is $\delta_2 W_2^\top$. The shapes give you no choice. That is why the transpose section of Chapter 00 said that transposes come from the backward pass.

Gradient descent

Backpropagation gives $\partial\mathcal{L}/\partial\theta$ for each parameter $\theta$. Now use it. This section derives the update rule from two facts in Chapter 00: the gradient and the dot product.

Which direction decreases the loss fastest

Put all the parameters in one long vector $\theta$. Change them by a small vector $\Delta$. For a small change, each parameter changes the loss by its partial derivative times its own change, and these changes add:

$$\mathcal{L}(\theta + \Delta) \;\approx\; \mathcal{L}(\theta) + \sum_i \frac{\partial\mathcal{L}}{\partial\theta_i}\,\Delta_i \;=\; \mathcal{L}(\theta) + \nabla\mathcal{L}\cdot\Delta$$

This is the first-order approximation. It is only the definition of the derivative, used for all the parameters at the same time. Check it with the function from Chapter 00, $f(x, y) = x^2y + 3y$, at $(2, 1)$, where $\nabla f = [4, 7]$. Increase $x$ by 0.01. The approximation says that $f$ increases by $4 \times 0.01 = 0.04$. The real change is $f(2.01, 1) - f(2, 1) = 0.0401$.

Now look at the form of the change: $\nabla\mathcal{L}\cdot\Delta$ is a dot product. Chapter 00 showed that $\mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\phi$, where $\phi$ is the angle between the two vectors. Select a step length $\varepsilon$, so that $\|\Delta\| = \varepsilon$. Then only the angle can change. The dot product is most negative when $\cos\phi = -1$, that is, when $\Delta$ points opposite to $\nabla\mathcal{L}$.

Example — five steps of the same length, five results

Start at $(2, 1)$ with $\nabla f = [4, 7]$ and $\|\nabla f\| = 8.062$. Take a step of length 0.01 in five directions:

direction step predicted real change ∇f · step of f +∇f (uphill) [ 0.00496, 0.00868] +0.0806 +0.0808 −x only [−0.01, 0 ] −0.0400 −0.0399 −y only [ 0, −0.01 ] −0.0700 −0.0700 perpendicular to ∇f [−0.00868, 0.00496] 0.0000 −0.0001 −∇f (downhill) [−0.00496, −0.00868] −0.0806 −0.0804 ← the largest decrease

A step perpendicular to the gradient changes almost nothing. A step along $-\nabla f$ decreases $f$ more than any other step of the same length.

Thus the best step is $\Delta = -\varepsilon\,\nabla\mathcal{L}/\|\nabla\mathcal{L}\|$. Write $\eta = \varepsilon/\|\nabla\mathcal{L}\|$, and you get the update rule:

$$\theta \;\leftarrow\; \theta - \eta\,\nabla\mathcal{L} \qquad\text{one entry at a time:}\qquad W \;\leftarrow\; W - \eta\,\frac{\partial\mathcal{L}}{\partial W}$$

$\eta$ is the learning rate. It sets the size of the step, and it is the most important number in training. Put the step into the approximation, and you get the predicted change of the loss:

$$\mathcal{L}(\theta - \eta\nabla\mathcal{L}) - \mathcal{L}(\theta) \;\approx\; \nabla\mathcal{L}\cdot(-\eta\nabla\mathcal{L}) \;=\; -\eta\,\|\nabla\mathcal{L}\|^2 \;\le\; 0$$

Two facts follow. First, a small enough step always decreases the loss, unless the gradient is zero. If the gradient is zero, you are at a minimum, a maximum or a flat point, and the method stops. Second, the length of the step is $\eta\,\|\nabla\mathcal{L}\|$. Near a minimum, the gradient becomes small, so the steps become small automatically.

How large the learning rate can be

The first-order approximation ignores the curvature, so it is correct only for small steps. Add the next term to see the limit. For one parameter, with $\mathcal{L}''$ the second derivative (the curvature):

$$\mathcal{L}(w + \Delta) \;\approx\; \mathcal{L}(w) + \mathcal{L}'\Delta + \tfrac{1}{2}\mathcal{L}''\Delta^2$$

Put in the step $\Delta = -\eta\mathcal{L}'$:

$$\mathcal{L}(w - \eta\mathcal{L}') - \mathcal{L}(w) \;\approx\; -\eta\mathcal{L}'^2 + \tfrac{1}{2}\mathcal{L}''\eta^2\mathcal{L}'^2 \;=\; -\eta\,\mathcal{L}'^2\Big(1 - \frac{\eta\,\mathcal{L}''}{2}\Big)$$

The loss decreases only if the factor in brackets is positive. Thus $\boxed{\eta < 2/\mathcal{L}''}$. A sharp valley (large curvature) needs a small learning rate.

Example — one step, by hand
L(w) = (w − 4)² L′ = 2(w − 4) L″ = 2 limit: η < 2/2 = 1 w = 1, η = 0.1: L′(1) = −6 w ← 1 − 0.1(−6) = 1.6 L(1.0) = 9.00 L(1.6) = 5.76 predicted change: −0.1 × 36 × (1 − 0.1) = −3.24 real: 5.76 − 9.00 = −3.24 ✓ w = 1, η = 1.0 (at the limit): w ← 1 + 6 = 7 L(7) = 9 the same loss, on the other side of the minimum

The prediction is exact here, because this loss is a quadratic and has no higher terms. For a real network, it is only an approximation. Also, a network has a different curvature in each direction, and the sharpest direction sets the limit for all of them. That is the problem that Adam solves: it gives each parameter its own effective step size.

Push Step and watch. At a small learning rate, the ball moves downhill reliably but slowly. The left valley has a curvature of approximately 4.4 at its bottom, so the limit is $2/4.4 \approx 0.45$. At 0.5, the ball jumps from one wall of the valley to the other and never settles. Above approximately 0.6, the first step goes too far. The gradient at the new point is larger and points back the other way. Each step goes farther out, and the loss goes to infinity in a few iterations. When the loss is nan five steps into training, this is usually the cause. A lower learning rate is usually the fix.

Note also that this landscape has two minima. The start point and the step size decide which one you get to. From the default start, a learning rate of 0.2 gets to the left minimum, and 0.3 gets to the right one. Real loss surfaces have very many minima. That is why weight initialization is important, and why two runs of the same code give different results. It is also why we initialize $W$ randomly and not at zero. If all the weights are the same, each hidden unit calculates the same thing and gets the same gradient. Thus the units stay the same forever. This failure is called symmetry, and random initialization does the symmetry breaking. Biases can start at zero, because the random weights already break the symmetry.

The algorithm, in full
  1. Do the forward pass. Calculate the loss, and keep each intermediate result.
  2. Do the backward pass. Get $\partial\mathcal{L}/\partial\theta$ for each parameter.
  3. Update each parameter: $\theta \leftarrow \theta - \eta\,\partial\mathcal{L}/\partial\theta$.
  4. Do steps 1 to 3 again, until the loss stops decreasing.

The loss is a mean over the examples. Thus, by the sum rule, its gradient is also a mean over the examples. A random batch of examples gives an estimate of that mean, at a much lower cost. Gradient descent with a random batch at each step is stochastic gradient descent (SGD). Chapter 02 uses it.

One full step by hand: XOR, every entry written out

The derivation above uses letters. This section uses one real network and real numbers, and it does one complete step of training: forward, backward and update. It also makes one idea explicit, and the rest of the book depends on it. You do not need a picture of nodes and arrows to understand a network. A network is a short list of matrices. The backward pass is a second list of matrices, with the same shapes. Each entry of each matrix is one short formula that you can write down and calculate by hand.

Key concept — a network is matrices, and so is its gradient

The forward pass makes five matrices from the input. The backward pass makes six more. Each one has a fixed shape, and each entry has a formula:

FORWARD BACKWARD Z1 = X W1 + b1 (4,2) δ2 = dL/dZ2 (4,1) A1 = sigma(Z1) (4,2) dL/dW2 (2,1) same shape as W2 Z2 = A1 W2 + b2 (4,1) dL/db2 (1,) same shape as b2 A2 = sigma(Z2) (4,1) δ1 = dL/dZ1 (4,2) L = mean BCE scalar dL/dW1 (2,2) same shape as W1 dL/db1 (2,) same shape as b1

The network diagram in Chapter 00 shows how to read one: each line is one entry of a $W$, and each circle (a "unit" or "neuron") is one column of an activation matrix such as $A_1$. Think in matrices, and backpropagation becomes a list of entries to fill in.

Step 2 — the backward pass, entry by entry

The method is the same for each matrix. Write the formula for one entry. Find which numbers that entry affects. Apply the chain rule to that one entry. Then look at the formula again, and recognize the matrix product that calculates all the entries at the same time.

$\delta_2 = \partial L/\partial Z_2$, shape (4, 1). $Z_2[n]$ affects only the loss term of example $n$, and that term has weight $1/4$ in the mean. From Start at the output, the sigmoid and the BCE cancel, and each entry is the error divided by the batch size:

δ2[n] = (A2[n] - Y[n]) / 4 δ2 = [ (0.36425 - 0)/4 ] [ 0.09106 ] too high: push example 1 down [ (0.48107 - 1)/4 ] = [ -0.12973 ] too low: push example 2 up [ (0.48107 - 1)/4 ] [ -0.12973 ] too low: push example 3 up [ (0.36425 - 0)/4 ] [ 0.09106 ] too high: push example 4 down

$\partial L/\partial W_2$, shape (2, 1). $W_2[j]$ occurs in all four rows of $Z_2$, one time for each example. In row $n$, it multiplies $A_1[n,j]$. Thus there are four paths from $W_2[j]$ to the loss, and the sum over paths adds them:

dL/dW2[j] = A1[1,j] δ2[1] + A1[2,j] δ2[2] + A1[3,j] δ2[3] + A1[4,j] δ2[4] dL/dW2[1] = 0.26894(0.09106) + 0.73106(-0.12973) + 0.73106(-0.12973) + 0.95257(0.09106) = 0.02449 - 0.09484 - 0.09484 + 0.08674 = -0.07845 dL/dW2[2] = 0.04743(0.09106) + 0.26894(-0.12973) + 0.26894(-0.12973) + 0.73106(0.09106) = 0.00432 - 0.03489 - 0.03489 + 0.06657 = 0.00111

Now look at the formula. Entry $j$ is column $j$ of $A_1$, dot product with $\delta_2$. Column $j$ of $A_1$ is row $j$ of $A_1^\top$. Thus all the entries together are one matrix product: $\partial L/\partial W_2 = A_1^\top \delta_2$. The matrix product does not add a new idea. It is the sum over the four examples, done for each entry at the same time.

Note the second entry, 0.00111. It is almost zero, but no individual term is small. Examples 2 and 3 want $W_2[2]$ to change in one direction, and examples 1 and 4 want the opposite. A gradient is a sum over the batch, and here the examples almost cancel.

$\partial L/\partial b_2$, shape (1,). $b_2$ is added to each row of $Z_2$ with a multiplier of 1. Thus its gradient is the sum of $\delta_2$:

dL/db2 = δ2[1] + δ2[2] + δ2[3] + δ2[4] = 0.09106 - 0.12973 - 0.12973 + 0.09106 = -0.07734

$\partial L/\partial A_1$, shape (4, 2). Now go one layer down. $A_1[n,j]$ occurs in only one place: row $n$ of $Z_2$, where $W_2[j]$ multiplies it. Thus each entry has one path and one product:

dL/dA1[n,j] = δ2[n] W2[j] [ δ2[1]W2[1] δ2[1]W2[2] ] [ 0.1821 -0.1821 ] dL/dA1 = [ δ2[2]W2[1] δ2[2]W2[2] ] = [ -0.2595 0.2595 ] [ δ2[3]W2[1] δ2[3]W2[2] ] [ -0.2595 0.2595 ] [ δ2[4]W2[1] δ2[4]W2[2] ] [ 0.1821 -0.1821 ]

Each row is $\delta_2[n]$ times the row vector $W_2^\top$. Thus the full matrix is $\delta_2W_2^\top$: a (4, 1) column times a (1, 2) row. The output weight decides how much error each hidden unit gets. Unit 2 has a negative output weight, so its error has the opposite sign.

$\delta_1 = \partial L/\partial Z_1$, shape (4, 2). $A_1[n,j] = \sigma(Z_1[n,j])$ depends only on the one entry $Z_1[n,j]$. Thus the chain rule multiplies each entry by one local derivative, $\sigma'(Z_1[n,j]) = A_1[n,j](1 - A_1[n,j])$. There is no sum here:

δ1[n,j] = dL/dA1[n,j] * A1[n,j] (1 - A1[n,j]) [ 0.1966 0.0452 ] sigma'(Z1) = [ 0.1966 0.1966 ] = A1 * (1 - A1), entry by entry [ 0.1966 0.1966 ] [ 0.0452 0.1966 ] [ 0.1821(0.1966) -0.1821(0.0452) ] [ 0.0358 -0.0082 ] δ1 = [ -0.2595(0.1966) 0.2595(0.1966) ] = [ -0.0510 0.0510 ] [ -0.2595(0.1966) 0.2595(0.1966) ] [ -0.0510 0.0510 ] [ 0.1821(0.0452) -0.1821(0.1966) ] [ 0.0082 -0.0358 ]

In matrix form, $\delta_1 = (\delta_2W_2^\top) \odot \sigma'(Z_1)$. The $\odot$ means entry by entry, because each hidden output depends on only one pre-activation. Note the two entries with 0.0452. There, $|Z_1| = 3$ and the sigmoid is starting to saturate. Thus those entries get approximately four times less gradient than the entries with $|Z_1| = 1$.

$\partial L/\partial W_1$, shape (2, 2). $W_1[i,j]$ occurs in column $j$ of $Z_1$, in all four rows. In row $n$, it multiplies $X[n,i]$. Thus there are four paths, and we add them, exactly as for $W_2$:

dL/dW1[i,j] = X[1,i] δ1[1,j] + X[2,i] δ1[2,j] + X[3,i] δ1[3,j] + X[4,i] δ1[4,j] X has many zeros, so many terms disappear: dL/dW1[1,1] = 0 + 0 + 1(-0.0510) + 1( 0.0082) = -0.0428 dL/dW1[1,2] = 0 + 0 + 1( 0.0510) + 1(-0.0358) = 0.0152 dL/dW1[2,1] = 0 + 1(-0.0510) + 0 + 1( 0.0082) = -0.0428 dL/dW1[2,2] = 0 + 1( 0.0510) + 0 + 1(-0.0358) = 0.0152 [ -0.0428 0.0152 ] dL/dW1 = [ -0.0428 0.0152 ] = X^T δ1

This is the same pattern as $\partial L/\partial W_2 = A_1^\top \delta_2$. The input to the layer, transposed, multiplies the error at the output of the layer. The only difference is the input: $X$ for layer 1, and $A_1$ for layer 2.

$\partial L/\partial b_1$, shape (2,). $b_1[j]$ is added to each row of column $j$ of $Z_1$. Thus its gradient is the sum of column $j$ of $\delta_1$:

dL/db1[1] = 0.0358 - 0.0510 - 0.0510 + 0.0082 = -0.0580 dL/db1[2] = -0.0082 + 0.0510 + 0.0510 - 0.0358 = 0.0580

Step 3 — one update, and a check

Take one gradient descent step with $\eta = 1$. Subtract each gradient matrix from its parameter matrix, entry by entry:

W1 <- [ 2 + 0.0428 2 - 0.0152 ] = [ 2.0428 1.9848 ] [ 2 + 0.0428 2 - 0.0152 ] [ 2.0428 1.9848 ] b1 <- [ -1 + 0.0580 -3 - 0.0580 ] = [ -0.9420 -3.0580 ] W2 <- [ 2 + 0.0785 -2 - 0.0011 ]^T = [ 2.0785 -2.0011 ]^T b2 <- -1 + 0.0773 = -0.9227 new predictions: A2 = [ 0.3943 0.5317 0.5317 0.4115 ] targets [ 0 1 1 0 ] new loss: L = 0.5737 was 0.5923

The loss decreased. Also, all four predictions are now on the correct side of 0.5. The step made the OR unit stronger and the AND unit more strict, and it moved the output threshold.

Two more observations:

  • The two rows of $W_1$ stay equal. The two inputs have the same role in XOR, so their gradients are always equal. For XOR, this is satisfactory, because OR and AND are also symmetric in their inputs. In general, equal rows or columns that stay equal are the symmetry problem. Random initialization prevents it.
  • Each value agrees with autograd. A finite-difference check on one entry also agrees. Change $W_1[1,1]$ by $\pm 0.001$, and the loss changes from 0.592391 to 0.592305. Thus the slope is $(0.592305 - 0.592391)/0.002 = -0.0428$, the same as the formula.

The training loop

for epoch in range(10000):
    # forward
    z1 = X @ W1 + b1
    a1 = sigmoid(z1)
    z2 = a1 @ W2 + b2
    a2 = sigmoid(z2)

    # loss (for monitoring; the gradients below are already differentiated)
    loss = -np.mean(y * np.log(a2) + (1 - y) * np.log(1 - a2))

    # backward
    d2 = (a2 - y) / len(X)          # (4, 1)
    dW2 = a1.T @ d2                 # (4, 1)
    db2 = d2.sum(axis=0, keepdims=True)
    d1 = (d2 @ W2.T) * a1 * (1 - a1)  # (4, 4)
    dW1 = X.T @ d1                  # (2, 4)
    db1 = d1.sum(axis=0, keepdims=True)

    # update
    W2 -= lr * dW2; b2 -= lr * db2
    W1 -= lr * dW1; b1 -= lr * db1

Ten thousand epochs seems like too many for four data points. The cause is the small gradients of the sigmoid and a modest learning rate. The structure is what is important: forward, loss, backward, update. Each training loop in the rest of this book has these four steps. Chapter 02 replaces the six backward lines with loss.backward(), and the four update lines with optimizer.step(). But the structure of the loop never changes again.

Put one training example through a 2→2→1 network. The numbers are chosen so that each sigmoid gives a value from the list.

x = [1, 0] y = 1 learning rate η = 0.5 W1 = [[ 0.5, -0.5], b1 = [0, 0] [ 0.5, 0.5]] (rows = inputs, cols = hidden units) W2 = [[1.0], b2 = [0] [1.0]] σ(0) = 0.500 σ(0.5) = 0.622 σ(-0.5) = 0.378 σ(1.0) = 0.731
  1. Do the forward pass: calculate $z_1$, $a_1$, $z_2$ and $a_2$.
  2. Calculate the BCE loss. Use $\ln 0.731 \approx -0.313$.
  3. Do the backward pass: calculate $\delta_2$, then $\partial\mathcal{L}/\partial W_2$.
  4. Calculate $\delta_1$ and $\partial\mathcal{L}/\partial W_1$.
  5. Apply one gradient descent step to $W_2$. Did the update move the prediction toward the target?
Worked solution

1. Forward. With $x = [1, 0]$, the second input adds nothing. Thus $z_1$ is the first row of $W_1$:

z1 = [1, 0] @ W1 + b1 = [0.5, -0.5] a1 = [σ(0.5), σ(−0.5)] = [0.622, 0.378] z2 = a1 @ W2 + b2 = 0.622(1.0) + 0.378(1.0) = 1.000 a2 = σ(1.000) = 0.731

2. Loss. $y = 1$, so only the first BCE term stays: $\mathcal{L} = -\ln(0.731) = \mathbf{0.313}$.

3. Output layer. With $N = 1$:

δ2 = a2 − y = 0.731 − 1 = −0.269 ∂L/∂W2 = a1ᵀ δ2 = [0.622, 0.378]ᵀ × (−0.269) = [[−0.167], [−0.102]]

Both values are negative. Thus both weights must increase. This makes sense: the prediction is too low, and both hidden units give positive values.

4. Hidden layer. First, send the error back through $W_2$:

δ2 W2ᵀ = −0.269 × [1.0, 1.0] = [−0.269, −0.269] σ′(z1) = a1 ⊙ (1 − a1) = [0.622(0.378), 0.378(0.622)] = [0.235, 0.235] δ1 = [−0.269, −0.269] ⊙ [0.235, 0.235] = [−0.0632, −0.0632] ∂L/∂W1 = xᵀ δ1 = [1, 0]ᵀ × [−0.0632, −0.0632] = [[−0.0632, −0.0632], [ 0.0000, 0.0000]]

The second row is exactly zero because $x_2 = 0$. An input that added nothing to the forward pass gets no gradient. This is not an approximation. It is the chain rule. It is also why the weights of a dead input feature never change.

Note also the magnitude. $\delta_1$ is 0.063 and $\delta_2$ is 0.269. That is 4.3 times smaller after one sigmoid. The factor of 0.235 is $\sigma'$ near its maximum of 0.25. Multiply it ten times, and you have the vanishing gradient problem in one number.

5. Update.

W2 ← W2 − 0.5 × [[−0.167], [−0.102]] = [[1.0 + 0.0835], [1.0 + 0.0510]] = [[1.0835], [1.0510]] new z2 = 0.622(1.0835) + 0.378(1.0510) = 1.0713 new a2 = σ(1.0713) ≈ 0.745

The prediction moved from 0.731 to 0.745, toward the target of 1. The loss decreases from 0.313 to $-\ln(0.745) = 0.294$. That is one step of learning, calculated fully by hand. In the next chapter, loss.backward(); optimizer.step() does exactly this for you.

By hand — exercise 01.2

This is a short proof with no arithmetic. Show that a network with no activation function cannot solve XOR, at any depth.

  1. Write the two-layer network without activations: $\hat{y} = (XW_1 + b_1)W_2 + b_2$. Expand it and collect the terms.
  2. What family of functions can the network express?
  3. In one sentence, explain why this rules out XOR.
Worked solution

1. Expand with the distributive law:

$$\hat{y} = XW_1W_2 + b_1W_2 + b_2$$

2. Let $W' = W_1W_2$ (one (2, 1) matrix) and $b' = b_1W_2 + b_2$ (one scalar). Then $\hat{y} = XW' + b'$. That is a normal linear model, and the hidden layer is gone. This is true at any depth, because a product of matrices is a matrix.

3. The decision boundary of a linear model is a straight line. The two classes of XOR are on opposite diagonals of a square, and no straight line separates them. Thus depth without non-linearity gives exactly nothing. The non-linearity is not a detail of the architecture. It is the architecture.

The steps become smaller, because the gradient decreases as $w$ moves near the minimum. Each step is exactly 0.4× the step before it. The reason: $w_{t+1} - 2 = w_t - 2 - 6\eta(w_t - 2) = (1-6\eta)(w_t - 2)$, and $1 - 6\eta = 0.4$.

3. $\mathcal{L}'' = 6$, so $\eta < 2/6 = \mathbf{1/3}$. At $\eta = 1/3$: $w = 0 - \frac{1}{3}(-12) = \mathbf{4}$, and $\mathcal{L}(4) = 12$. This is the same loss as at the start, on the other side of the minimum. The ratio $1 - 6\eta$ is $-1$, so $w$ moves between 0 and 4 forever.

4. The ratio is $1 - 3 = -2$:

w₀ = 0 (distance 2) L = 12 w₁ = 6 (distance 4) L = 48 w₂ = −6 (distance 8) L = 192

The distance doubles at each step, and the loss becomes four times larger. Within ten steps, the values go to inf and then to nan. The problem itself is correct. Only $\eta$ is wrong.

5. $\eta = \mathbf{1/6}$, which makes the ratio $1 - 6\eta = 0$. One step: $w = 0 - \frac{1}{6}(-12) = 2$, which is the minimum. In general, the best rate for a quadratic is $1/\mathcal{L}''$, half of the limit. A real network has a different curvature in each direction, so no single $\eta$ is best for all of them. That is the problem that Adam solves.

By hand — exercise 01.4 · XOR, one entry of each gradientRecommended

Use the matrices from the XOR section. For each item, write the one-entry formula first. Then put in the numbers.

  1. Calculate entry $(4, 1)$ of $\delta_1$ directly from $\delta_2$, $W_2$ and $A_1$. Do not use the $\partial L/\partial A_1$ matrix.
  2. Calculate entry $(2, 2)$ of $\partial L/\partial W_1$. Which examples contribute, and why do the others give zero?
  3. Entry $(1, 2)$ of $\delta_1$ is $-0.0082$, and entry $(2, 2)$ is $0.0510$. Both come from hidden unit 2. Find the two factors that make the first one smaller.
  4. Suppose that $W_2[2]$ was 0, not $-2$. Which gradient entries become exactly zero? Does $\partial L/\partial W_2[2]$ become zero?
Worked solution

1. $\delta_1[4,1] = \delta_2[4]\,W_2[1]\,A_1[4,1](1-A_1[4,1])$:

δ1[4,1] = 0.09106 x 2 x 0.9526 x (1 - 0.9526) = 0.18212 x 0.0452 = 0.0082 ✓

2. $\partial L/\partial W_1[2,2] = \sum_n X[n,2]\,\delta_1[n,2]$. Column 2 of $X$ is $[0, 1, 0, 1]$. Thus only examples 2 and 4 contribute: $0.0510 + (-0.0358) = 0.0152$ ✓. Examples 1 and 3 have $X[n,2] = 0$. Input 2 was off for them, so a change to its weight could not change their output.

3. The first factor is the error. $|\delta_2[1]| = 0.0911$ and $|\delta_2[2]| = 0.1297$, so example 1 is less wrong. The second factor is the sigmoid slope. $Z_1[1,2] = -3$ gives $\sigma' = 0.0452$, but $Z_1[2,2] = -1$ gives $\sigma' = 0.1966$. The saturation factor is the larger effect: it is approximately 4.3 times, and the error is approximately 1.4 times.

4. Column 2 of $\partial L/\partial A_1$ is $\delta_2[n]\,W_2[2]$, so it becomes zero. Thus column 2 of $\delta_1$, column 2 of $\partial L/\partial W_1$, and $\partial L/\partial b_1[2]$ all become zero. Hidden unit 2 gets no gradient, because its output has no effect on the loss. But $\partial L/\partial W_2[2] = \sum_n A_1[n,2] \delta_2[n]$ does not use $W_2[2]$, so it does not become zero. (With the new $\delta_2$, it is 0.0827.) Thus the output weight can grow again, and then unit 2 starts to learn again.

By hand — exercise 01.5 · backpropagation in matrices, with softmaxMust do

Use one example, two inputs, two hidden units, two classes and ReLU in the middle. It is small enough to do fully on paper, and it is a complete training step of a real network.

X = [ 1 2 ] W1 = [ 1 0 ] W2 = [ 1 -1 ] [ 0 1 ] [ 0 2 ] biases are zero correct class is the FIRST one, so Y = [ 1 0 ] e^1 = 2.718 e^3 = 20.086 ln(0.1192) = -2.127
  1. Do the forward pass. Calculate $Z_1$, $A_1$ and $Z_2$, then $P = \operatorname{softmax}(Z_2)$ and the loss.
  2. Calculate $\delta_2 = (P - Y)/N$ with $N = 1$. ($P - Y$ is the gradient of softmax with cross-entropy, from Chapter 00.)
  3. Calculate $\partial\mathcal{L}/\partial W_2 = A_1^\top \delta_2$. Before you calculate an entry, make sure that the shape is (2, 2).
  4. Calculate $\delta_2 W_2^\top$, then $\delta_1$. What does the derivative of ReLU do here? When would it cause a problem?
  5. Calculate $\partial\mathcal{L}/\partial W_1 = X^\top \delta_1$.
  6. Which entry of $\partial\mathcal{L}/\partial W_1$ has the largest magnitude? Which input causes this?
Worked solution

1. $W_1$ is the identity, so $Z_1 = [1, 2]$. Both values are positive, so ReLU does not change them: $A_1 = [1, 2]$.

Z2 = A1 W2 = [ 1(1) + 2(0) , 1(-1) + 2(2) ] = [ 1 , 3 ] softmax: e^1 = 2.718, e^3 = 20.086, sum = 22.804 P = [ 2.718/22.804 , 20.086/22.804 ] = [ 0.1192 , 0.8808 ] L = -ln(0.1192) = 2.127

The model gives 12% to the correct class. Thus the loss is much larger than the value from a random guess, $\ln 2 = 0.69$. The model is wrong, and it is confident.

2. $\delta_2 = [0.1192 - 1,\ 0.8808 - 0] = [-0.8808,\ 0.8808]$. Its sum is zero. This is true for each softmax-with-cross-entropy gradient.

3. $A_1^\top$ is (2, 1) and $\delta_2$ is (1, 2). Thus the product is (2, 2), which is the shape of $W_2$, as it must be.

dL/dW2 = [ 1 ] [ -0.8808 0.8808 ] = [ -0.8808 0.8808 ] [ 2 ] [ -1.7616 1.7616 ]

4.

δ2 W2^T = [ -0.8808 0.8808 ] [ 1 0 ] = [ -1.7616 1.7616 ] [ -1 2 ]

The derivative of ReLU is 1 where the pre-activation was positive. Both entries of $Z_1$ were positive. Thus $f'(Z_1) = [1, 1]$ and $\delta_1 = [-1.7616,\ 1.7616]$. The elementwise step changes nothing. Now suppose that an entry of $Z_1$ was negative. Then the gradient for that coordinate is multiplied by zero, and the matching row of $W_1$ gets nothing from this example. That is a dead ReLU.

5.

dL/dW1 = X^T δ1 = [ 1 ] [ -1.7616 1.7616 ] [ 2 ] = [ -1.7616 1.7616 ] [ -3.5232 3.5232 ]

6. The bottom row, at $\pm 3.5232$. It is exactly two times the top row. The second input was 2 and the first input was 1. $X^\top \delta_1$ multiplies each row of the weight gradient by the matching input. Thus each weight changes in proportion to the contribution of its input. That is why feature scaling is important. It is also why an input that is always zero cannot change its own weights.

Each number above agrees with autograd to the last printed digit.

In the wild

Nobody writes the six backward lines in production code. After this chapter, you know exactly what the framework replaces: 

model = nn.Sequential(nn.Linear(2, 4), nn.Sigmoid(),
                      nn.Linear(4, 1))
loss = nn.BCEWithLogitsLoss()(model(X), y)   # replaces the loss + clipping
loss.backward()                              # replaces d2, dW2, db2, d1, dW1, db1
optimizer.step()                             # replaces the four updates

The framework gives you correct derivatives for any graph, fused and numerically stable kernels, and GPU execution. It hides three facts. First, $\delta_2$ is prediction minus target. Second, a saturated unit gets nothing. Third, a dead input feature never changes. With those three facts, you can debug a model that trains but does not learn. From the framework side, you cannot see them.

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. You write a 3-class network from scratch. The first loss that it prints is 1.099. Is that good or bad?
  2. You have ten sigmoid layers. What is the largest possible product of their derivatives? What does that tell you about training the first layer?
  3. The first loss on a 10-class problem is 6.9. What one thing is most probably wrong?
Answers

1. $\ln 3 = 1.0986$. That is exactly correct. The network is correctly confused, as an untrained network should be.

2. $0.25^{10} = 9.5\times10^{-7}$. And that is the best case, with $z = 0$ for each unit. The first layer gets a maximum of one millionth of the signal that the last layer gets. This is a limit, not a tendency. Thus no learning rate can fix it.

3. $\ln 10 = 2.30$. Thus 6.9 means that the network starts confident and wrong. It puts most of its probability on incorrect classes. Almost always, the initial weights are too large. A network that starts at 6.9 must use its first steps to cancel its own initialization.

The habit. Predict the first loss before you run anything. It is the cheapest bug detector in this book, and it costs one logarithm.

Say it backRecommended

Explain this to your favorite LLM, in your own words: how does the backward pass work, and why is computing it right-to-left the thing that makes it affordable? Then ask it to correct you. Ask it to question each part where you were vague, not only the parts where you were wrong, because the gaps are in the vague parts. Do not use the word backpropagation at all.

What a good answer covers — open this afterwards, not before
  1. The forward pass calculates intermediate values and keeps them, because the backward pass needs them.
  2. The loss is one scalar. Each parameter has a partial derivative of that one number.
  3. When you apply the chain rule from right to left, you calculate each shared sub-expression one time, not one time for each parameter. That reuse is all of the saving.
  4. Each layer needs its own stored input to make its weight gradient. That is why memory increases with depth and batch size.
  5. It is the chain rule plus a strategy to keep intermediate results. It uses no new calculus.

Most common miss. An answer explains what the backward pass calculates, but not why the sequence is important. If your explanation is also true for a calculation of each partial derivative separately from the start, you described differentiation, not the backward pass.
