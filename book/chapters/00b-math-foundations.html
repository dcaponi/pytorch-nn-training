Mathematical Foundations

Three areas of mathematics carry all the weight in this book. Linear algebra is what a network computes. Calculus is how it learns. Probability is what its outputs mean, and where every loss function comes from. This chapter covers exactly as much of each as the rest of the book needs — and no more — with a worked example beside every idea.

If you have seen this material before, skim to the by-hand exercises and check whether you can do them cold. That is a better test of readiness than a feeling of familiarity, because the specific things a network needs from these subjects are narrow and sometimes surprising: shapes matter more than proofs, the chain rule matters more than integration, and one distribution does most of the work.

Part 1 · Linear Algebra: What a Network Computes

A neural network is, mechanically, a sequence of matrix multiplications with non-linear functions squeezed between them. So the operations below are not background material — they are the forward pass.

Vectors, and the dot product as similarity

A vector is an ordered list of numbers. In this book a vector almost always represents one thing: a word's embedding, a token's hidden state, one example's features.

The single most important operation on two vectors is the dot product:

$$\mathbf{a} \cdot \mathbf{b} = \sum_{i=1}^{n} a_i b_i$$
Example
a = [2, 0, 1] b = [3, 4, −2] a · b = (2)(3) + (0)(4) + (1)(−2) = 6 + 0 − 2 = 4

The formula is trivial; the interpretation is what matters. The dot product also equals

$$\mathbf{a}\cdot\mathbf{b} = \|\mathbf{a}\|\,\|\mathbf{b}\|\cos\theta$$

where $\|\mathbf{a}\| = \sqrt{\sum a_i^2}$ is the length and $\theta$ the angle between them. So the dot product is large and positive when two vectors point the same way, zero when they are perpendicular, and negative when they oppose. It is a similarity score.

Example — the same fact, three ways
[1, 0] · [1, 0] = 1 same direction → large [1, 0] · [0, 1] = 0 perpendicular → zero [1, 0] · [−1, 0] = −1 opposite → negative

This is not a curiosity. When attention computes $QK^\top$, every entry is a dot product asking "how relevant is this position to that one?" — and the answer is literally an angle between two learned vectors. The entire attention mechanism is this one geometric fact, applied to every pair.

Matrix multiplication is a grid of dot products

For $A$ of shape (m, n) and $B$ of shape (n, p), the product $C = AB$ has shape (m, p) with

$$C_{ij} = \sum_{k=1}^{n} A_{ik}B_{kj} = (\text{row } i \text{ of } A) \cdot (\text{column } j \text{ of } B)$$
Example
A (2×3) B (3×2) C (2×2) [ 1 2 0 ] [ 1 0 ] [ 0 1 3 ] @ [ 2 −1 ] = [ ? ? ] [ 0 1 ] [ ? ? ] C₁₁ = row1 · col1 = (1)(1) + (2)(2) + (0)(0) = 5 C₁₂ = row1 · col2 = (1)(0) + (2)(−1) + (0)(1) = −2 C₂₁ = row2 · col1 = (0)(1) + (1)(2) + (3)(0) = 2 C₂₂ = row2 · col2 = (0)(0) + (1)(−1) + (3)(1) = 2 C = [ 5 −2 ] [ 2 2 ]

Two rules are worth more than any amount of theory here.

The inner dimensions must match, and they vanish. (m, n) @ (n, p) → (m, p). If they do not match, you get an error — and this is the error you will see most often in this book. Reading a shape mismatch is a skill: mat1 and mat2 shapes cannot be multiplied (64x128 and 256x512) means you produced 128 features and something expected 256.

Matrix multiplication does not commute. $AB \ne BA$ in general — often the shapes do not even permit both. Order is meaning.

Key concept

A linear layer nn.Linear(n_in, n_out) computes $XW^\top + b$. Reading the shapes tells you what it does:

X (batch, n_in) one row per example Wᵀ (n_in, n_out) one column per output unit XWᵀ (batch, n_out) one row per example, one column per unit + b (n_out,) broadcast across every row

Output unit $j$'s value for example $i$ is the dot product of example $i$'s features with unit $j$'s weights: a weighted vote over all inputs. Every linear layer in the book is that sentence.

Elementwise operations, and the $\odot$ symbol

$A \odot B$ multiplies corresponding entries and requires identical shapes. It is completely different from $AB$, and the book uses it constantly — in backpropagation through activations, in LSTM gates, and in masking.

Example — the distinction that matters
a = [1, 2, 3] b = [4, 5, 6] a · b (dot) = 4 + 10 + 18 = 32 a scalar a ⊙ b (elementwise) = [4, 10, 18] a vector, same shape

When an LSTM's forget gate does $f_t \odot c_{t-1}$, each memory slot is scaled by its own gate value independently. A dot product would collapse the whole memory into one number, destroying it.

Transpose

$A^\top$ swaps rows and columns: $(A^\top)_{ij} = A_{ji}$, so (m, n) becomes (n, m). It shows up in every backward pass, for a reason that is worth understanding rather than memorising: if the forward pass sent information through $W$ from $n$ inputs to $m$ outputs, the backward pass must send gradient the other way, from $m$ back to $n$ — and $W^\top$ is the operator with the right shape to do it.

Broadcasting

When shapes differ, NumPy and PyTorch stretch dimensions of size 1 to match. Align shapes from the right; each dimension must be equal, or one of them must be 1.

Example — including the one that bites
(4, 3) + (3,) → (4, 3) the vector is added to every row ✓ (4, 3) + (4, 1) → (4, 3) the column is added to every column ✓ (4, 3) + (4,) → ERROR 3 and 4 are neither equal nor 1 (4, 1) + (1, 3) → (4, 3) BOTH stretch — and this one is the trap

The last case is legal, silent, and almost never what you meant. A (4, 1) where you intended (1, 4) produces a 4×4 grid of nonsense rather than an error. When a loss looks wrong for no visible reason, print your shapes.

Part 2 · Calculus: How a Network Learns

Training means adjusting parameters to reduce a loss. The derivative is the only tool that tells you which way to adjust, so this section covers derivatives, partial derivatives, and — above all — the chain rule, which is backpropagation.

The derivative as a rate of change

$f'(x)$ is the slope of $f$ at $x$: how much $f$ changes per unit change in $x$.

$$f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$$
Example — verify a rule numerically

Take $f(x) = x^2$, whose derivative is $2x$. At $x = 3$, so $f'(3) = 6$. Check with a small $h$:

h = 0.001 (f(3.001) − f(3)) / 0.001 = (9.006001 − 9) / 0.001 = 0.006001 / 0.001 = 6.001 ≈ 6 ✓

This is more than a sanity check — it is gradient checking, the standard way to verify a hand-written backward pass. If your analytic gradient and a finite-difference estimate disagree, your analytic gradient is wrong. The notebook uses exactly this to verify the softmax gradient.

The four rules this book uses, and nothing else:

RuleStatementWhere it appears
Power$\frac{d}{dx}x^n = nx^{n-1}$MSE: $\frac{d}{de}e^2 = 2e$
Exponential$\frac{d}{dx}e^x = e^x$softmax, sigmoid
Logarithm$\frac{d}{dx}\ln x = \frac{1}{x}$every cross-entropy loss
Chain$\frac{d}{dx}f(g(x)) = f'(g(x))\,g'(x)$all of backpropagation

The chain rule, which is the whole of backpropagation

When functions are composed, multiply their derivatives. If $y = f(u)$ and $u = g(x)$, then

$$\frac{dy}{dx} = \frac{dy}{du}\cdot\frac{du}{dx}$$
Example — a two-link chain

Let $y = (3x + 1)^2$. Set $u = 3x+1$, so $y = u^2$.

dy/du = 2u = 2(3x + 1) du/dx = 3 dy/dx = 2(3x + 1) × 3 = 6(3x + 1) = 18x + 6 check at x = 2: dy/dx = 42 numerically: ((3(2.001)+1)² − (3(2)+1)²) / 0.001 = (49.042 − 49) / 0.001 = 42.0 ✓
Key concept

A neural network is a composition of many functions: $\mathcal{L}(a_2(z_2(a_1(z_1(x)))))$. The chain rule says the derivative of the whole with respect to anything inside is the product of the derivatives along the path.

∂L/∂z₁ = ∂L/∂a₂ · ∂a₂/∂z₂ · ∂z₂/∂a₁ · ∂a₁/∂z₁ └──────────── one factor per layer crossed ───────────┘

Backpropagation is nothing more than evaluating that product from left to right, caching each partial result so the shared prefix is not recomputed for every parameter. Two consequences follow immediately, and they explain most of the architectural history in this book: if the factors are typically below 1 the product decays geometrically with depth (vanishing gradients), and if above 1 it explodes.

Partial derivatives and the gradient

With several inputs, $\partial f/\partial x$ measures the change in $f$ per unit change in $x$ while holding everything else fixed. The gradient $\nabla f$ collects them into a vector.

Example

Let $f(x, y) = x^2y + 3y$.

∂f/∂x: treat y as a constant → 2xy ∂f/∂y: treat x as a constant → x² + 3 ∇f = [2xy, x² + 3] at (x, y) = (2, 1): ∇f = [4, 7]

Read that: at this point, moving $y$ changes $f$ almost twice as fast as moving $x$. The gradient points in the direction of steepest increase, which is why gradient descent steps in the direction $-\nabla f$.

When a variable has several paths, sum them

This is the multivariable chain rule, and it is the one rule people most often get wrong. If $x$ influences $L$ through more than one route, the total derivative is the sum over all paths.

Example — a variable used twice
a = w · x b = a + w ← w reaches b directly AND through a L = b² with w = 3, x = 2: a = 6, b = 9, L = 81 ∂L/∂b = 2b = 18 path 1 (w → a → b → L): ∂a/∂w · ∂b/∂a · ∂L/∂b = 2 × 1 × 18 = 36 path 2 (w → b → L): ∂b/∂w · ∂L/∂b = 1 × 18 = 18 total ∂L/∂w = 54

This is exactly why PyTorch accumulates into .grad rather than overwriting: a parameter used at several points in the graph must collect a contribution from each. It is also why zero_grad() is mandatory — the accumulation has no idea where one backward pass ends and the next begins. The same summation is what makes weight sharing work in convolutions and recurrent networks.

Gradient descent

$$\theta \leftarrow \theta - \eta\,\frac{\partial \mathcal{L}}{\partial \theta}$$
Example — one step, by hand
L(w) = (w − 4)² current w = 1 learning rate η = 0.1 dL/dw = 2(w − 4) = 2(1 − 4) = −6 w ← 1 − 0.1(−6) = 1 + 0.6 = 1.6 check: L(1.0) = 9.00 L(1.6) = 5.76 ↓ better next step: dL/dw = 2(1.6 − 4) = −4.8 → w = 2.08 L = 3.69 then: dL/dw = −3.84 → w = 2.464 L = 2.36

Notice the steps shrink as the slope flattens — descent slows down automatically near a minimum. Notice also what would happen at $\eta = 1.0$: the step would be $+6$, landing at $w = 7$, which is further from 4 than where it started. That is divergence, and it is a property of the learning rate, not of the problem.

Part 3 · Probability: What the Output Means

With the machinery in place, the question becomes what a network should output, and how to score it. The answer to both is probability.

Why a model must output a belief, not an answer

Consider a classifier reading a film review. The naive design outputs a decision: positive or negative. That is a dead end, for a reason that has nothing to do with neural networks — a discrete answer cannot be improved by a small amount, and a step function has zero derivative everywhere it is defined. Section 2 just established that a zero derivative offers no advice about which direction to move.

So the model outputs a belief: $\hat{y} \in (0,1)$, read as "the probability this review is positive". Now wrongness has degrees, and degrees have derivatives.

Example — why degrees matter
true label: positive (y = 1) model A says 0.51 → correct decision, barely model B says 0.99 → correct decision, confidently model C says 0.10 → wrong A discrete "positive/negative" output cannot distinguish A from B at all, and gives no signal for how far C must move. A probability does both.

The three distributions that cover this book

Bernoulli — one yes/no outcome with probability $p$ of being 1:

$$P(y \mid p) = p^{y}(1-p)^{1-y}$$
Example — the exponent trick
p = 0.7 y = 1: P = 0.7¹ × 0.3⁰ = 0.7 × 1 = 0.7 y = 0: P = 0.7⁰ × 0.3¹ = 1 × 0.3 = 0.3

The exponents are an if statement written as an expression. Whichever branch does not apply is raised to the power 0 and becomes 1, dropping out of the product. This matters because an if is not differentiable and this is.

Categorical — one outcome from $K$ classes:

$$P(y \mid p) = \prod_{k=1}^{K} p_k^{\,y_k}$$
Example
3 classes, model says p = [0.2, 0.5, 0.3] true class is 1 (the middle), so one-hot y = [0, 1, 0] P = 0.2⁰ × 0.5¹ × 0.3⁰ = 1 × 0.5 × 1 = 0.5

Same trick, generalised: the product collapses to the single probability assigned to the true class. This is the distribution behind sentiment classification and behind every token a language model predicts.

Gaussian — a real-valued measurement with noise:

$$P(y \mid \mu, \sigma^2) = \frac{1}{\sqrt{2\pi\sigma^2}}\exp\!\left(-\frac{(y-\mu)^2}{2\sigma^2}\right)$$

Used when the target is a number rather than a label — the sine-wave regression, for instance. The model predicts $\mu$; $\sigma$ is assumed fixed and, as we will see, disappears entirely.

Likelihood: reading a distribution backwards

Here is the pivot the chapter turns on. $P(y \mid \theta)$ is normally read forwards: parameters known, outcome uncertain. Training reverses it. You observed the data; the parameters are what you do not know.

The same expression with $y$ fixed and $\theta$ varying is the likelihood of $\theta$. It is not a distribution over $\theta$ — it does not integrate to 1 and is not trying to. It is a score: how well does this setting of the parameters explain what I saw?

Example — the same numbers, read two ways

You flip a coin 3 times and see heads, heads, tails.

FORWARD (p known, outcome uncertain), with p = 0.5: P(HHT) = 0.5 × 0.5 × 0.5 = 0.125 BACKWARD (outcome known, p uncertain) — score candidate values of p: p = 0.2 : 0.2 × 0.2 × 0.8 = 0.032 p = 0.5 : 0.5 × 0.5 × 0.5 = 0.125 p = 0.67: 0.67 × 0.67 × 0.33 = 0.148 ← highest p = 0.9 : 0.9 × 0.9 × 0.1 = 0.081

The best explanation of "2 heads in 3 flips" is $p = 2/3$ — which is exactly the observed frequency. That is maximum likelihood estimation, and the fact that it recovers the obvious answer on an easy problem is what licenses trusting it on a hard one.

For $N$ independent examples the likelihood of the dataset is the product:

$$\mathcal{l}(\theta) = \prod_{i=1}^{N} P(y_i \mid x_i, \theta)$$

Why the logarithm is not optional

That product is unusable as written, for two independent reasons.

It underflows. A batch of 64 examples at probability 0.1 each gives $10^{-64}$. The smallest positive float32 is about $10^{-38}$. Your likelihood is not small — it is exactly zero, and so is its gradient.

Products differentiate badly. The product rule compounds across all $N$ terms; sums differentiate term by term.

The logarithm fixes both. It is strictly increasing, so the maximiser is unchanged, and it turns products into sums. Flip the sign to minimise and divide by $N$ to make batches comparable:

$$\mathcal{L}(\theta) = -\frac{1}{N}\sum_{i=1}^{N}\log P(y_i \mid x_i, \theta)$$
Example — the underflow, concretely
64 examples, each at probability 0.1 product : 0.1⁶⁴ = 1e−64 → float32 stores this as exactly 0.0 sum of logs : 64 × ln(0.1) = 64 × (−2.303) = −147.4 → perfectly fine The second number is representable, differentiable, and carries the same ordering information. The first is a zero that stops training dead.
Key concept Every loss in this book is that one formula with a different distribution substituted in. Bernoulli gives binary cross-entropy. Categorical gives cross-entropy. Gaussian gives mean squared error. They are not three unrelated recipes — they are one recipe with three ingredients.

Part 4 · Deriving the Losses

Bernoulli → binary cross-entropy

$$\mathcal{L} = -\frac{1}{N}\sum_i \log\!\big[\hat{y}_i^{\,y_i}(1-\hat{y}_i)^{1-y_i}\big] = -\frac{1}{N}\sum_i\big[y_i\log\hat{y}_i + (1-y_i)\log(1-\hat{y}_i)\big]$$
Example
y = 1, ŷ = 0.9 → −[1 · ln(0.9) + 0 · ln(0.1)] = −ln(0.9) = 0.105 y = 0, ŷ = 0.2 → −[0 · ln(0.2) + 1 · ln(0.8)] = −ln(0.8) = 0.223

One term is always multiplied by zero, so the loss is always just $-\log(\text{probability assigned to the truth})$.

Categorical → cross-entropy

$$\mathcal{L} = -\frac{1}{N}\sum_i\sum_{k} y_{ik}\log\hat{y}_{ik} = -\frac{1}{N}\sum_i \log\hat{y}_{i,c_i}$$

The sum over classes collapses because $y$ is one-hot — which is why nn.CrossEntropyLoss takes integer class indices rather than one-hot vectors. The one-hot was only ever selecting a term.

Two features of that curve determine how classifiers train. Near $p = 1$ it is flat, so a model that is already right receives almost no gradient and spends its capacity elsewhere. Near $p = 0$ it is unbounded, so confident wrongness is punished without limit. That asymmetry is deliberate.

Gaussian → mean squared error

$$-\log P(y \mid \mu,\sigma^2) = \frac{(y-\mu)^2}{2\sigma^2} + \tfrac{1}{2}\log(2\pi\sigma^2)$$

The second term does not involve $\mu$, so it has zero gradient with respect to the model and cannot move the minimum — drop it. A fixed $\sigma$ is a constant scale absorbed into the learning rate. What survives is $\mathcal{L} = \frac{1}{N}\sum(y_i - \hat{y}_i)^2$.

So MSE is not a neutral choice of "how far off am I". It asserts that your targets are the truth plus symmetric, constant-width, bell-shaped noise — and it misbehaves in exactly the ways that assumption predicts when it is wrong.

Why MSE fails on classification

This is where derivation pays off. With $\hat{y} = \sigma(z)$ and MSE loss, the chain rule from Part 2 gives

$$\frac{\partial\mathcal{L}}{\partial z} = 2(\hat{y}-y)\,\sigma'(z)$$
Example — the failure, in numbers
truth y = 1, and the model is confidently wrong: z = −8, ŷ = 0.000335 MSE : 2(0.000335 − 1) × σ′(−8) = 2(−0.9997) × 0.000335 = −0.00067 ← essentially no gradient BCE : ŷ − y = 0.000335 − 1 = −0.9997 ← full-strength gradient ratio: about 1,500×

Under MSE, the more confidently wrong the model is, the less it learns. Training stalls precisely where it needs to move fastest. Cross-entropy is built so the $\sigma'$ factor cancels exactly — see the boxed result below.

The same reasoning sorts the regression losses. MSE's gradient is $2e$ and grows without bound, so one mislabelled point with error 50 contributes a gradient of 100 and dominates the batch. MAE's is $\operatorname{sign}(e)$ — constant magnitude, completely indifferent to how bad an outlier is. Huber is quadratic near zero and linear in the tails. Tick show gradients above: the loss curves are pretty, but the gradients are what training feels.

Softmax and the gradient that makes it all work

$$\hat{y}_k = \frac{e^{z_k}}{\sum_j e^{z_j}}$$
Example — softmax by hand
z = [2.0, 1.0, 0.0] exponentiate: e² = 7.389, e¹ = 2.718, e⁰ = 1.000 sum: 11.107 ŷ = [7.389/11.107, 2.718/11.107, 1.000/11.107] = [0.665, 0.245, 0.090] sums to 1.000 ✓

Now subtract 2 from every logit, giving $[0,-1,-2]$: $e^0 = 1$, $e^{-1} = 0.368$, $e^{-2} = 0.135$, sum 1.503, and $\hat{y} = [0.665, 0.245, 0.090]$ — identical. Softmax is invariant to adding a constant, because $e^c$ cancels between numerator and denominator. That invariance is free insurance: subtract the maximum before exponentiating and the largest exponent becomes $e^0 = 1$, so overflow is impossible. Without it, a logit of 800 becomes inf and the whole distribution becomes nan.

The cancellation

Combine softmax with cross-entropy, differentiate with respect to the logits, and nearly everything cancels:

$$\boxed{\;\frac{\partial\mathcal{L}}{\partial z_k} = \hat{y}_k - y_k\;}$$
Example
ŷ = [0.665, 0.245, 0.090] true class c = 1, y = [0, 1, 0] ∂L/∂z₀ = 0.665 − 0 = +0.665 push logit 0 DOWN hard ∂L/∂z₁ = 0.245 − 1 = −0.755 push logit 1 UP hard ∂L/∂z₂ = 0.090 − 0 = +0.090 push logit 2 down a little sum = 0

Predicted probability minus true probability — no saturation factor, no attenuation. And the gradients sum to zero necessarily, because adding a constant to every logit changes nothing, so the gradient can have no component in that direction. Only relative logits are learnable.

Key concept Softmax and cross-entropy are designed as a pair; their derivatives cancel to leave the error itself. This is why you pass raw logits to nn.CrossEntropyLoss and nn.BCEWithLogitsLoss rather than applying softmax or sigmoid yourself. The fused implementation is numerically stabler and faster, and doing it manually is a silent correctness bug — the loss still runs, the numbers still go down, and the model trains worse than it should.
The derivation, in full

Let $S = \sum_j e^{z_j}$, so $\hat{y}_k = e^{z_k}/S$. The diagonal case $k = c$, by the quotient rule:

$$\frac{\partial \hat{y}_c}{\partial z_c} = \frac{e^{z_c}S - e^{z_c}e^{z_c}}{S^2} = \hat{y}_c(1-\hat{y}_c)$$

and the off-diagonal case $k \ne c$, where the numerator does not depend on $z_k$:

$$\frac{\partial \hat{y}_c}{\partial z_k} = \frac{0 \cdot S - e^{z_c}e^{z_k}}{S^2} = -\hat{y}_c\hat{y}_k$$

With $\mathcal{L} = -\log\hat{y}_c$ we have $\partial\mathcal{L}/\partial\hat{y}_c = -1/\hat{y}_c$, so for $k = c$:

$$\frac{\partial\mathcal{L}}{\partial z_c} = -\frac{1}{\hat{y}_c}\hat{y}_c(1-\hat{y}_c) = \hat{y}_c - 1$$

and for $k \ne c$:

$$\frac{\partial\mathcal{L}}{\partial z_k} = -\frac{1}{\hat{y}_c}(-\hat{y}_c\hat{y}_k) = \hat{y}_k$$

Since $y_c = 1$ and $y_k = 0$, both cases are the single expression $\hat{y}_k - y_k$.

The information-theoretic reading

A second derivation reaches the same formula from a different direction, and explains the name.

Surprisal of an event of probability $p$ is $-\log p$ — in base 2, literally the number of bits an optimal code spends on it. Entropy $H(p) = -\sum p_k\log p_k$ is its expectation under the truth. Cross-entropy $H(p,q) = -\sum p_k\log q_k$ is what you pay encoding reality $p$ with beliefs $q$. Their difference is the KL divergence, the pure penalty for being wrong:

$$D_{\mathrm{KL}}(p\parallel q) = H(p,q) - H(p) \ge 0$$
Example — the cost of a wrong belief, in bits
It rains half of all days: p = [0.5, 0.5] Your model claims: q = [0.25, 0.75] H(p) = −(0.5 log₂0.5 + 0.5 log₂0.5) = 1.000 bits H(p,q) = −(0.5 log₂0.25 + 0.5 log₂0.75) = −(0.5(−2) + 0.5(−0.415)) = 1.208 bits KL(p‖q) = 1.208 − 1.000 = 0.208 bits per day

Over a year, 76 wasted bits — the price of a wrong model, in the currency of message length.

The punchline: $H(p)$ depends only on the data, not on the model. So minimising cross-entropy is minimising KL divergence from the truth. The maximum-likelihood story and the information-theory story are the same story told twice.

Perplexity A language model's perplexity is $e^{\mathcal{L}}$ for cross-entropy in nats. A perplexity of 40 means the model is as uncertain as if choosing uniformly among 40 words. When Chapter 10 reports a loss of 1.51 over 73 characters, that is a perplexity of 4.5 — the model has narrowed 73 possible characters down to about four or five plausible ones. Loss curves are hard to read; perplexity is not.

By-hand exercises

By hand — exercise 00.1 · shapes and dot products

Nothing here needs a calculator, and every one of these shapes appears in Chapter 01.

A is (4, 2) B is (2, 3) C is (3, 3) v is (3,)
  1. Which of these are legal, and what shape does each produce? A@B, B@A, A@B@C, B@C, C@B.
  2. What shape is (A@B) + v? Explain via the broadcasting rules.
  3. Compute $\mathbf{a}\cdot\mathbf{b}$ for $\mathbf{a} = [3, -1, 2]$, $\mathbf{b} = [1, 2, 4]$. Is the angle between them acute, right, or obtuse?
  4. A batch of 32 examples with 10 features each passes through nn.Linear(10, 64) then nn.Linear(64, 3). Give every intermediate shape and the total parameter count.
Worked solution

1. Inner dimensions must match and vanish.

A@B (4,2)@(2,3) → (4, 3) ✓ 2 matches 2 B@A (2,3)@(4,2) → ERROR ✗ 3 ≠ 4 A@B@C (4,3)@(3,3) → (4, 3) ✓ left-to-right B@C (2,3)@(3,3) → (2, 3) ✓ C@B (3,3)@(2,3) → ERROR ✗ 3 ≠ 2

Note that A@B is legal while B@A is not — the clearest possible demonstration that matrix multiplication does not commute.

2. A@B is (4, 3) and v is (3,). Aligning from the right, 3 matches 3; v has no second dimension, so it is treated as (1, 3) and stretched across all 4 rows. Result: (4, 3). This is exactly how a bias vector is added to a batch — every example gets the same bias.

3. $(3)(1) + (-1)(2) + (2)(4) = 3 - 2 + 8 = \mathbf{9}$. Positive, so $\cos\theta > 0$ and the angle is acute — the vectors broadly agree in direction.

4.

input (32, 10) after Linear(10,64) (32, 64) 10×64 + 64 = 704 params after Linear(64,3) (32, 3) 64×3 + 3 = 195 params total 899 params

The batch dimension 32 passes through untouched at every step. That is universal: layers transform features, never the batch.

This is the exercise that makes attention feel inevitable rather than arbitrary. Three "word embeddings" in two dimensions:

cat = [ 1.0, 0.0 ] dog = [ 0.8, 0.6 ] idea = [−0.6, 0.8 ] useful: √1.00 = 1.00 0.8² + 0.6² = 1.00 (−0.6)² + 0.8² = 1.00
  1. Confirm all three vectors have length 1. (This makes the next part easier — for unit vectors the dot product is the cosine.)
  2. Compute all three pairwise dot products: cat·dog, cat·idea, dog·idea.
  3. Rank the pairs by similarity. Does the ranking match your intuition about the words?
  4. A query vector $q = [0.9, 0.4]$ arrives. Compute its score against each of the three keys, then apply softmax with no scaling. Which word does it attend to most?
  5. Now scale $q$ up to $[9, 4]$ — same direction, ten times longer. Recompute the softmax. What happened, and which part of the attention formula exists to prevent it?
Worked solution

1. $\|cat\| = \sqrt{1 + 0} = 1$; $\|dog\| = \sqrt{0.64 + 0.36} = 1$; $\|idea\| = \sqrt{0.36 + 0.64} = 1$ ✓.

2.

cat · dog = (1.0)(0.8) + (0.0)(0.6) = 0.80 cat · idea = (1.0)(−0.6) + (0.0)(0.8) = −0.60 dog · idea = (0.8)(−0.6) + (0.6)(0.8) = 0.00

3. cat–dog (0.80) > dog–idea (0.00) > cat–idea (−0.60). Two concrete animals are similar; "idea" is perpendicular to "dog" (unrelated) and points away from "cat" (actively opposed). This is what a learned embedding space does — arrange vectors so that the dot product reports semantic similarity — and it is why every attention score is a dot product.

4.

q · cat = (0.9)(1.0) + (0.4)(0.0) = 0.90 q · dog = (0.9)(0.8) + (0.4)(0.6) = 0.96 q · idea = (0.9)(−0.6) + (0.4)(0.8) = −0.22 e^0.90 = 2.460 e^0.96 = 2.612 e^{−0.22} = 0.803 sum = 5.875 softmax = [0.419, 0.445, 0.137]

It attends most to dog, but only just — 0.445 against 0.419. The distribution is soft, which means gradients flow to all three.

5. Scaling $q$ by 10 multiplies every score by 10: $[9.0, 9.6, -2.2]$.

e^9.0 = 8103 e^9.6 = 14765 e^{−2.2} = 0.111 sum = 22868 softmax = [0.354, 0.646, 0.0000049]

The direction of $q$ has not changed at all, so the ranking is identical — but the distribution has become far peakier, and "idea" has been annihilated to five parts in a million. Push the scaling further and the row goes fully one-hot, at which point the softmax gradient is ~0 and the layer stops learning entirely.

This is exactly what the $1/\sqrt{d_k}$ factor in $\operatorname{softmax}(QK^\top/\sqrt{d_k})V$ prevents. Dot-product magnitude grows with dimension — $\operatorname{Var}(q\cdot k) = d_k$ for unit-variance components — so without the correction, simply making your model wider would saturate every attention layer in it. See Chapter 06.

By hand — exercise 00.3 · the chain rule as backpropagation

A one-neuron network, computed forwards and then backwards. This is a complete training step in miniature.

x = 2.0 w = 0.5 b = 0.1 true label y = 1 z = wx + b (linear) a = σ(z) = 1/(1+e⁻ᶻ) (sigmoid) L = −ln(a) (BCE, with y = 1) σ(1.1) = 0.750 ln(0.750) = −0.288
  1. Forward pass: compute $z$, $a$, and $\mathcal{L}$.
  2. Compute $\partial\mathcal{L}/\partial a$.
  3. Compute $\partial a/\partial z$ using $\sigma'(z) = a(1-a)$.
  4. Chain them to get $\partial\mathcal{L}/\partial z$. Simplify, and compare with $a - y$.
  5. Compute $\partial\mathcal{L}/\partial w$ and $\partial\mathcal{L}/\partial b$, then take one gradient-descent step at $\eta = 0.5$ and verify the loss decreased.
Worked solution

1. $z = 0.5(2.0) + 0.1 = 1.1$; $a = \sigma(1.1) = 0.750$; $\mathcal{L} = -\ln(0.750) = \mathbf{0.288}$.

2. $\frac{d}{da}(-\ln a) = -1/a = -1/0.750 = \mathbf{-1.333}$.

3. $a(1-a) = 0.750 \times 0.250 = \mathbf{0.1875}$.

4. Multiplying the two:

∂L/∂z = (−1.333)(0.1875) = −0.250 and a − y = 0.750 − 1 = −0.250 ← identical

Algebraically: $-\frac{1}{a}\cdot a(1-a) = -(1-a) = a - 1 = a - y$. The $\sigma'$ factor cancels against the $1/a$ from the log exactly. This is the cancellation from the boxed result above, appearing here in its simplest possible instance — and it is why sigmoid pairs with BCE and not with MSE.

5. Since $z = wx + b$, we have $\partial z/\partial w = x$ and $\partial z/\partial b = 1$:

∂L/∂w = (∂L/∂z)(∂z/∂w) = (−0.250)(2.0) = −0.500 ∂L/∂b = (∂L/∂z)(∂z/∂b) = (−0.250)(1.0) = −0.250 w ← 0.5 − 0.5(−0.500) = 0.75 b ← 0.1 − 0.5(−0.250) = 0.225 new z = 0.75(2.0) + 0.225 = 1.725 new a = σ(1.725) ≈ 0.849 new L = −ln(0.849) = 0.164 was 0.288 ✓ decreased

Note that $\partial\mathcal{L}/\partial w$ is twice $\partial\mathcal{L}/\partial b$, purely because $x = 2$. A larger input produces a larger weight gradient — which is why unnormalised input features with wildly different scales make training difficult, and why feature scaling helps.

By hand — exercise 00.4 · summing over paths

A parameter used twice — the case that explains PyTorch's gradient accumulation.

u = w² v = u + w L = 3v with w = 2
  1. Compute $u$, $v$, and $\mathcal{L}$.
  2. Identify every path from $w$ to $\mathcal{L}$ in the computation graph.
  3. Compute the derivative along each path, and sum.
  4. Verify numerically with $h = 0.001$.
  5. What would w.grad contain if you called backward() twice without zero_grad()?
Worked solution

1. $u = 4$, $v = 4 + 2 = 6$, $\mathcal{L} = 18$.

2. Two paths: $w \to u \to v \to \mathcal{L}$, and the direct $w \to v \to \mathcal{L}$.

3.

∂L/∂v = 3 ∂v/∂u = 1 ∂u/∂w = 2w = 4 ∂v/∂w = 1 (the direct edge) path 1: 4 × 1 × 3 = 12 path 2: 1 × 3 = 3 ─── ∂L/∂w = 15

4. At $w = 2.001$: $u = 4.004001$, $v = 6.005001$, $\mathcal{L} = 18.015003$. Then $(18.015003 - 18)/0.001 = \mathbf{15.003} \approx 15$ ✓.

5. It would contain 30 — the sum of two independent backward passes, which is the derivative of nothing in particular. Note how plausible 30 looks: nothing crashes, no warning is issued, and the model trains steadily towards the wrong thing. This is why zero_grad() is not optional, and why the accumulation default that causes this bug is also the feature that makes gradient accumulation and weight sharing work.

By hand — exercise 00.5 · gradient descent, and the learning rate

Minimise $\mathcal{L}(w) = (w-4)^2$, starting from $w_0 = 1$.

  1. Write $d\mathcal{L}/dw$. What is it at $w = 1$?
  2. Take three steps at $\eta = 0.1$, tabulating $w$ and $\mathcal{L}(w)$ each time. Is the step size growing or shrinking, and why?
  3. Take one step at $\eta = 1.0$. Where do you land, and what is the loss?
  4. Take one step at $\eta = 1.5$, then a second. Describe the pattern.
  5. Solve for the exact value of $\eta$ at which a step overshoots the minimum by precisely as much as it started away from it — the boundary between converging and diverging.
Worked solution

1. $d\mathcal{L}/dw = 2(w-4)$, which at $w=1$ is $2(-3) = \mathbf{-6}$. Negative, so $w$ should increase — correct, since the minimum is at 4.

2. Each step is $w \leftarrow w - 0.1 \cdot 2(w-4)$:

step w dL/dw Δw = −η·grad L(w) 0 1.000 −6.000 9.000 1 1.600 −4.800 +0.600 5.760 2 2.080 −3.840 +0.480 3.686 3 2.464 −3.072 +0.384 2.359

The steps shrink (0.600 → 0.480 → 0.384), because the gradient itself shrinks as $w$ approaches the minimum. Gradient descent slows down automatically near an optimum — no schedule required. Note also that each step is exactly 0.8× the previous one: the update is $w_{t+1} - 4 = (1 - 2\eta)(w_t - 4)$, a geometric sequence with ratio $1 - 2\eta = 0.8$.

3. At $\eta = 1.0$: $w = 1 - 1.0(-6) = \mathbf{7}$, and $\mathcal{L}(7) = 9$ — the same loss it started with, on the opposite side. The ratio is $1 - 2(1.0) = -1$: it will oscillate between 1 and 7 forever, never converging and never diverging.

4. At $\eta = 1.5$, ratio $= 1 - 3 = -2$:

w₀ = 1 (distance 3 from the optimum) L = 9 w₁ = 1 − 1.5(−6) = 10 (distance 6) L = 36 w₂ = 10 − 1.5(12) = −8 (distance 12) L = 144

The distance doubles every step and the loss quadruples. Within ten steps you are at $|w| \approx 3000$ and heading for inf, then nan. This is what a loss that explodes in the first few iterations looks like, and nothing about the problem is wrong — only $\eta$.

5. From the recurrence above, the step preserves the distance exactly when $|1 - 2\eta| = 1$, i.e. $\eta = 1$ (part 3). Convergence requires $|1-2\eta| < 1$, so $\mathbf{0 < \eta < 1}$, with the fastest possible convergence at $\eta = 0.5$ where $1-2\eta = 0$ and a single step lands exactly on the minimum.

The general result is that stable convergence needs $\eta < 2/L$ where $L$ is the curvature (here $\mathcal{L}'' = 2$, giving $\eta < 1$ ✓). Real loss surfaces have wildly different curvature in different directions, and that is precisely the problem Adam solves by giving each parameter its own effective step size.

By hand — exercise 00.6 · binary cross-entropy on a batch
example true y predicted ŷ 1 1 0.9 2 0 0.2 3 1 0.4 ln 0.9 ≈ −0.105 ln 0.8 ≈ −0.223 ln 0.4 ≈ −0.916
  1. Write the per-example loss, simplifying away the term multiplied by zero.
  2. Evaluate each and average to get the batch loss.
  3. Which example contributes most, and by how much?
  4. Example 2 is 0.2 away from perfect and example 3 is 0.6 away — three times the error. Is the loss three times larger? What does the answer tell you about how batches are dominated?
Worked solution

1 & 2.

example 1: y=1 → −ln(0.9) = 0.105 example 2: y=0 → −ln(1 − 0.2) = 0.223 example 3: y=1 → −ln(0.4) = 0.916 batch loss = (0.105 + 0.223 + 0.916)/3 = 1.244/3 = 0.415

3. Example 3, at 0.916, is 74% of the total.

4. No — it is 4.1× larger for 3× the error. The log makes the loss superlinear in the error, so a single badly-classified example dominates the batch gradient. That is usually what you want (hard examples deserve attention) and occasionally a disaster (a mislabelled example also dominates). It is the same mechanism that makes MSE fragile to outliers, seen from the classification side.

By hand — exercise 00.7 · softmax, cross-entropy, and its gradient
z = [2.0, 1.0, 0.0] true class c = 1 (the middle one) e⁰ = 1.000 e¹ = 2.718 e² = 7.389
  1. Apply the max-subtraction trick and confirm it cannot change the answer.
  2. Compute $\operatorname{softmax}(z)$ to three decimals.
  3. Compute the loss $-\log\hat{y}_c$, and compare it with the loss of a uniform guess.
  4. Compute $\partial\mathcal{L}/\partial z_k$ for all three logits. Check they sum to zero and explain why they must.
  5. If you added 100 to every logit, what would change about the loss and the gradients?
Worked solution

1. Subtracting 2 gives $[0, -1, -2]$. Since $e^{z_k - m}/\sum_j e^{z_j - m} = (e^{-m}e^{z_k})/(e^{-m}\sum_j e^{z_j})$, the $e^{-m}$ cancels and the distribution is identical.

2. $\sum = 7.389 + 2.718 + 1.000 = 11.107$, so

ŷ = [0.665, 0.245, 0.090] sums to 1.000 ✓

3. $\mathcal{L} = -\ln(0.245) = \mathbf{1.406}$ nats. A uniform guess over 3 classes costs $-\ln(1/3) = 1.099$, so this model is worse than guessing on this example — it put most of its mass on the wrong class. That comparison is the cheapest possible sanity check on any classifier's loss.

4. With $y = [0,1,0]$:

∂L/∂z₀ = 0.665 − 0 = +0.665 ∂L/∂z₁ = 0.245 − 1 = −0.755 ∂L/∂z₂ = 0.090 − 0 = +0.090 sum = 0.000

They must sum to zero because softmax outputs are constrained to sum to 1: shifting every logit equally changes nothing, so the gradient can have no component along that direction.

5. Nothing at all. Both the loss and every gradient are unchanged — this is the invariance from part 1, and part 4 is its fingerprint in the gradients. What would change is the naive implementation's behaviour: $e^{102}$ is fine, but at $+800$ it overflows to inf and the distribution becomes nan. The mathematics is invariant; the floating-point arithmetic is not.

By hand — exercise 00.8 · entropy, cross-entropy, and KL

A weather model claims rain with probability $q = 0.25$ every day. It actually rains half the time, $p = 0.5$. Work in bits, with $\log_2 3 \approx 1.585$.

  1. Compute $H(p)$.
  2. Compute $H(p,q)$.
  3. Compute $D_{\mathrm{KL}}(p\parallel q)$ and say what the number means physically.
  4. Compute $D_{\mathrm{KL}}(q\parallel p)$. Why is it different?
  5. Training minimises $H(p,q)$, not $D_{\mathrm{KL}}$. Why does that make no difference to where the minimum is?
Worked solution

1. $H(p) = -(0.5\log_2 0.5 + 0.5\log_2 0.5) = 1$ bit — a fair coin, maximal uncertainty for a binary event.

2. $\log_2 0.25 = -2$ and $\log_2 0.75 = \log_2 3 - 2 \approx -0.415$, so $H(p,q) = -(0.5(-2) + 0.5(-0.415)) = \mathbf{1.208}$ bits.

3. $1.208 - 1 = \mathbf{0.208}$ bits. Physically: encoding real weather using this model's beliefs costs 0.21 extra bits per day — about 76 wasted bits a year. That is the concrete price of a wrong model, measured in message length.

4. $D_{\mathrm{KL}}(q\parallel p) = 0.25\log_2(0.5) + 0.75\log_2(1.5) = -0.25 + 0.75(0.585) = \mathbf{0.189}$ bits. Different because the two average the discrepancy under different distributions — "how surprised will I be" depends on who is doing the expecting. The asymmetry is a feature: forward and reverse KL produce famously different behaviours (mass-covering versus mode-seeking) when used as objectives.

5. Because $D_{\mathrm{KL}}(p\parallel q) = H(p,q) - H(p)$ and $H(p)$ depends only on the data, not on the model. Subtracting a constant shifts a function without moving its minimum, so $\arg\min_\theta H(p,q_\theta) = \arg\min_\theta D_{\mathrm{KL}}(p\parallel q_\theta)$. Minimising cross-entropy is minimising divergence from the truth — you simply cannot compute the constant, and do not need to.

By hand — exercise 00.9 · choosing the loss

No arithmetic. For each, name the loss and justify it from the distribution.

  1. Predicting apartment rents, where 2% of the dataset is luxury penthouses at 30× the median.
  2. Tagging a photo with any of 20 labels; a photo can have several.
  3. Predicting the next word from a 50,000-word vocabulary.
  4. Detecting a rare disease present in 0.5% of patients.
Worked solution

1. MAE or Huber. MSE is the Gaussian NLL, and this data has heavy tails, so the assumption is simply false. Under MSE the penthouses' squared errors dominate the gradient and distort predictions for ordinary apartments. Huber is usually best: quadratic near zero for smooth convergence, linear in the tail for robustness.

2. BCE per label (BCEWithLogitsLoss over 20 logits), not cross-entropy. Cross-entropy assumes the categorical distribution, in which exactly one class occurs — the softmax forces the 20 outputs to compete for a fixed probability budget. Multi-label means 20 independent Bernoulli events, so each gets its own sigmoid and its own BCE term. This is a genuinely common mistake.

3. Cross-entropy over 50,000 logits. Categorical: exactly one word comes next. Report perplexity rather than raw loss — $e^{\mathcal{L}}$ is interpretable, and the uniform baseline is $\ln(50000) = 10.8$ nats.

4. BCE with pos_weight. The loss itself is correct — Bernoulli, one binary outcome — but with 0.5% positives the maximum-likelihood solution really is "always predict negative", which achieves 99.5% accuracy and is useless. The loss is not malfunctioning; it is answering the question you asked. Reweighting the positive class changes the question to one you actually care about. Report precision and recall, never accuracy.
