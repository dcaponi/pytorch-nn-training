Front matter

How to read this book

This book is the companion to the pytorch_nn_training notebooks. You type code in the notebooks. You learn why that code works in this book. Keep both open.

Most machine-learning tutorials fail in one of two ways. Some give you working code but do not explain the mathematics. You can run that code, but you cannot reason about it, and you cannot fix it when it breaks. Others give you the mathematics but do not show you how to write a training loop. This book and its notebooks close that gap from both sides. Each idea appears in four different forms:

  1. As mathematics, in this book. We derive each result. We do not just state it.
  2. As arithmetic that you do yourself, in the By hand exercises. Each exercise is small enough for paper and large enough to be real.
  3. As code, in the notebook for that chapter. You complete the code and run it.
  4. As a library call, in the In the wild boxes. These boxes show what production code uses instead, what it adds, and what it hides.

The fourth form is more important than it looks. The goal is not to avoid libraries. The goal is that you can read a paper, find the equation that is new, implement it, and compare a library's version with your own. The Appendix helps with that step. It maps each component in this book to its production API. It also tells you how to read research papers, and it describes the main changes in the field since 2017.

Many people skip the by-hand step. Do not skip it, because it does most of the work. After you calculate a gradient once with a pencil, it is no longer just a symbol. It is a number that you know how to check. If your loss becomes nan at three in the morning, that skill is the difference between a fix and a guess.

The rhythm

Each chapter of this book goes with one lesson folder. Use this sequence for each chapter:

  1. Read the full chapter before you open the notebook. Read it from start to end. One chapter takes twenty to forty minutes.
  2. Do the By hand exercises. Do not read a solution first. An error that you find and understand teaches you more than a correct answer that you read.
  3. Do the Feel for the numbers box on paper. It is short. After you do it, you read $\mathcal{L} = 2.30$ as this model has learned nothing, not only as a symbol.
  4. Do the Say it back box before you look at other material. When you explain a mechanism from memory, you find gaps that you do not see when you read again.
  5. Open prompt.ipynb in the matching folder and complete the TODOs. You will know each formula, because you just calculated it by hand.
  6. Compare your work with solution.ipynb. Its cells already contain their outputs, so you can read the results without running the notebook.

There is one exception. Chapter 12 contains the capstone projects. It has one notebook and no solutions, because each of its five projects has many correct answers.

It is there because the later chapters are much easier when this material is fresh. If you have a technical background, read it quickly and read the Key concept boxes. Interactive figures

Where a picture is better than a paragraph, this book has a live figure. Each widget uses the same arithmetic as the text near it. Nothing is fake, and nothing is drawn by hand. Move the sliders. The interesting behavior is usually at the two ends of a slider.

That figure comes from Mathematical Foundations, and it is a good example of what the widgets do. Cross-entropy loss has no upper limit. You can read that sentence and forget it. Or you can move a point along the curve, and then you will remember it.

What you need

You need a laptop and nothing more. You do not need a data-center GPU, an API key or a large model download. No model in these lessons has more than a few million parameters. The largest single download is an NLTK corpus of a few dozen megabytes.

EnoughComfortable
Memory8 GB16 GB
CPUany 64-bit chip from roughly the last five years4 cores or more
Diskabout 2 GB, nearly all of it PyTorch—
GPUnoneApple Silicon, or an NVIDIA card with CUDA

We measured that memory value. The largest job in the book is the full GPT training run. It uses a maximum of about 860 MB of resident memory. Thus 8 GB gives it sufficient space next to a browser, an editor and your other applications. With 16 GB, memory is never a problem.

A GPU makes some runs faster, but you do not need one. Each notebook selects its device automatically. It tries Apple Silicon's Metal backend first, then CUDA, then the CPU. Thus the code is the same on each machine, and you do not configure anything.

For the smallest models, the CPU is faster than a GPU. The time to move tensors to a GPU is more than the time that the GPU saves on the arithmetic. The GPU starts to help at approximately Chapter 03, and it helps more after that. A 16 GB M1 is sufficient for the full book. An RTX card is also sufficient. An older desktop CPU is also sufficient. On that CPU, the two or three longest runs take some minutes longer, but no run takes hours.

Setup — macOS, Windows and Linux

There is no Docker image and no requirements.txt. One tool, uv, controls the virtual environment, the dependencies and the Python version. This project needs Python 3.13 or newer, but you do not have to install or upgrade Python first. If uv cannot find a correct interpreter, it downloads one into its own directory. It does not change your system Python.

1. Install uv. On macOS or Linux:

curl -LsSf https://astral.sh/uv/install.sh | sh

On Windows, in PowerShell:

irm https://astral.sh/uv/install.ps1 | iex

If your execution policy blocks that command, run this command from a normal prompt: powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

On each platform, you can also use a package manager: brew install uv, winget install astral-sh.uv, or pipx install uv. Then close your terminal and open it again. This puts the new uv on your path.

2. Get the notebooks and make the environment. Use the same three lines on each platform:

git clone https://github.com/dcaponi/pytorch-nn-training.git
cd pytorch-nn-training
uv sync

uv sync makes .venv/ and installs PyTorch, NumPy, Matplotlib, NLTK and Jupyter in it. If you do not have Python 3.13, it also gets one. The download is a few hundred megabytes and takes one or two minutes. Most of it is PyTorch. You do not have to activate the environment, because uv run does that for each command.

3. Open a notebook.

uv run jupyter notebook     # then open a lesson folder

Each corpus downloads the first time you use it, and stays in ~/nltk_data/. Chapter 11 needs no more dependencies. We implement quantization and LoRA from scratch, because that implementation is the lesson.

If you are not on a Mac All the code runs without changes. Only the device selection is different. Each notebook selects the first device that it finds, in this sequence: mps, cuda, cpu. On Windows, uv installs a CPU-only wheel from PyPI. That is satisfactory here, because each model in this course is small. It trains on a CPU in minutes, not hours. If you have an NVIDIA card and want CUDA, install torch from the PyTorch index instead. Use the selector at pytorch.org. You do not change anything else in the project.

Notation

The book uses each symbol consistently, and the notebooks write tensor shapes consistently. The Appendix lists both conventions. Look at it now, and look at it again when you cannot read a formula. Here is the short version:

SymbolMeansIn code
$x$, $\mathbf{x}$a scalar input; a vector of inputsx
$W$, $b$weight matrix, bias vectorself.linear.weight, .bias
$z$pre-activation ("logit"): $z = Wx + b$logits
$a = \sigma(z)$post-activationa, h
$\hat{y}$the model's predictionpred, out
$\mathcal{L}$the loss, a single scalarloss
$\eta$learning ratelr
$B, T, C$batch, time/sequence, channel/feature(B, T, C)

The notebooks show tensor shapes in comments next to the code. This book writes them like (B, T, d_model). Shape errors are the most common bug in this material. Thus, follow the shapes as you read. It is the easiest good habit that you can make.
