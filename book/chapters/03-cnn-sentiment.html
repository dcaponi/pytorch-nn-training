Convolutions over Text

Two thousand real film reviews, and the first architecture in this book with an inductive bias: the assumption that local phrases carry meaning wherever they appear. That assumption is what a convolution encodes, and understanding it as an assumption — rather than as a piece of machinery — is what lets you predict when it will work.

From words to numbers

A network consumes vectors of floats. A review is a list of words. Three steps bridge the gap, and each is a design decision with consequences.

Tokenise. Split text into units. Here, lowercased whitespace-and-punctuation tokens from NLTK. Simple, and it makes "Don't" and "dont" different words, which is a real cost. Chapter 10 introduces subword tokenisation, which fixes it properly.

Build a vocabulary. Map the most frequent $V$ tokens to integer indices, reserving index 0 for <PAD> and 1 for <UNK>. Everything outside the top $V$ becomes <UNK>. Vocabulary size trades coverage against parameters: the embedding table alone is $V \times d$ numbers, so at $V = 10{,}000$ and $d = 100$ that is a million parameters before any actual model.

Pad or truncate to a fixed length. Tensors are rectangular; reviews are not. Every sequence becomes exactly $L$ tokens, cut if longer, filled with <PAD> if shorter. This is pure bookkeeping overhead, and Chapter 08 shows how much compute it can waste.

Leakage Build the vocabulary from the training split only. Building it from the full corpus lets test-set vocabulary influence the model and quietly inflates your reported accuracy. It is the most common way to accidentally lie to yourself in NLP, and the symptom — excellent test numbers that collapse on genuinely new data — appears far too late to be useful.

Embeddings: geometry learned from the task

One-hot vectors are the obvious encoding and a bad one: a 10,000-dimensional vector that is all zeros except a single 1, in which every pair of words is exactly equidistant. "Excellent" is as far from "superb" as it is from "the". No structure to exploit.

An embedding replaces this with a dense, learned vector — typically 50 to 300 numbers. nn.Embedding(V, d) is a $V \times d$ lookup table: 

emb = nn.Embedding(vocab_size, 100, padding_idx=0)
x = emb(token_ids)      # (B, L) -> (B, L, 100)
Key concept An embedding layer is a linear layer applied to a one-hot vector — multiplying a one-hot by a matrix just selects a row. It is implemented as a lookup because doing the multiplication would be absurd, but this equivalence is why gradients flow through it normally: the backward pass scatters gradient into the rows that were used, leaving every other row untouched. Words that do not appear in a batch receive no update.
Example — a lookup is a matrix multiply

A 4-word vocabulary with 3-dimensional embeddings:

E (4×3) one-hot for "good" (index 2) the [ 0.1, 0.0, −0.2 ] h = [0, 0, 1, 0] a [ 0.3, −0.1, 0.1 ] good [ 0.9, 0.8, −0.5 ] h @ E = 0·row0 + 0·row1 + 1·row2 + 0·row3 bad [−0.8, −0.7, 0.6 ] = [0.9, 0.8, −0.5] which is exactly E[2] — the lookup, with 9 pointless multiplications.

The equivalence also explains the backward pass. Since $h$ selects one row, the gradient $h^\top\delta$ is zero everywhere except row 2, which receives $\delta$. Only words that actually appeared get updated — and a word appearing three times in a batch accumulates three contributions, exactly as summing over paths requires.

Because the vectors are learned by gradient descent on this task, they arrange themselves according to what this task needs. Train on sentiment and "boring", "tedious", and "dull" drift together — not because the model knows they are synonyms, but because they predict the same label. padding_idx=0 pins the pad row at zero and excludes it from updates, so padding contributes nothing.

The convolution

Now the architectural claim. A phrase like "not bad" means the same thing at the start of a review as at the end. A model that had to learn it separately for each position would need far more data than we have. A convolution builds that assumption in structurally: one small set of weights is applied at every position.

Drag the window along. The kernel weights never change — only which tokens they multiply. Each position produces one number, and the sequence of those numbers is the feature map. A kernel is a phrase detector, and the same detector fires wherever its phrase occurs. That property is called translation invariance, and it is the entire reason CNNs are data-efficient.

Shapes, and the transpose that catches everyone

nn.Conv1d expects (B, C_in, L) — channels before length — while nn.Embedding produces (B, L, d). You must transpose: 

x = self.embedding(x)        # (B, L, d)
x = x.transpose(1, 2)        # (B, d, L)   <- d is now the channel dim
x = self.conv(x)             # (B, n_filters, L_out)

The embedding dimension becomes the input channel count: the kernel spans all $d$ dimensions at once and slides only along length. A kernel of width $k$ therefore holds $d \times k$ weights per filter — it is genuinely reading whole word vectors, not individual numbers.

Output length follows the standard formula, worth committing to memory:

$$L_{\text{out}} = \left\lfloor \frac{L_{\text{in}} + 2p - k}{s} \right\rfloor + 1$$

with padding $p$, kernel width $k$, stride $s$. With the defaults here ($p=0$, $s=1$) it is just $L - k + 1$: a width-3 kernel over 200 tokens gives 198 positions.

Several kernel widths at once

Language does not have one characteristic phrase length. So run three convolutions in parallel — widths 3, 4, and 5, say — and concatenate their outputs. Width 3 catches "not very good"; width 5 catches longer constructions. Each contributes its own filters to a shared representation.

Global max pooling

Each feature map is one number per position, but the classifier needs a fixed-size vector. Take the maximum: 

x = F.relu(conv(x))              # (B, n_filters, L_out)
x = F.max_pool1d(x, x.size(2))   # (B, n_filters, 1)
x = x.squeeze(2)                 # (B, n_filters)

The semantics are exactly right for this problem: did this phrase pattern appear anywhere in the review, and how strongly? Position is discarded deliberately. For sentiment that is the correct trade — a review is negative whether the damning phrase is in sentence one or sentence twelve.

It is also the model's ceiling. Max pooling cannot represent order between detected phrases, so "the acting saved a terrible script" and "a terrible script saved the acting" reduce to the same bag of activations. Fixing that is what attention is for.

Dropout

Two thousand reviews against a model with a million-plus parameters is an invitation to memorise. Dropout is the counter: during training, zero each activation independently with probability $p$, and scale the survivors by $1/(1-p)$ so the expected sum is unchanged.

The usual intuition is that this prevents co-adaptation — no unit can rely on a specific partner being present, so features must be individually useful. A second reading: it trains an exponentially large ensemble of subnetworks that share weights, and averages them at test time. Both are fair; both predict the same practical rule, which is that dropout must be off at evaluation. That is what model.eval() does, and forgetting it gives you noisy, pessimistic, irreproducible test numbers.

Batching and the train/test split

Dataset tells PyTorch how to fetch one example; DataLoader handles batching, shuffling, and parallel loading. Shuffling matters more than it looks: the movie review corpus is sorted by label, so an unshuffled loader delivers 1,000 negative reviews followed by 1,000 positive ones. The model would learn "always negative", then catastrophically unlearn it.

The held-out test set is the only honest number you have. Training accuracy measures memorisation; test accuracy measures learning. A gap of a few points is normal, and a large and widening gap is the definition of overfitting — which is exactly what Chapter 09 runs into, and handles by keeping the weights from the best validation epoch.

By hand — exercise 03.1

A one-dimensional embedding (so each token is a single number) and a width-3 kernel.

sentence: the film was not bad at all embedding: 0.1 0.3 0.0 −0.9 −0.6 0.1 0.0 kernel w = [−1.0, 1.0, 0.5] bias b = 0.1 stride 1, no padding, ReLU after
  1. How many output positions are there? Use the formula.
  2. Compute the pre-activation value at each position.
  3. Apply ReLU, then global max pooling. Which window won?
  4. The kernel has learned $-w_1 + w_2$ — it fires on a rise from a negative token to a positive one. Explain, in terms of this sentence, why the winning window is a sensible thing for a sentiment model to detect.
Worked solution

1. $L_{\text{out}} = (7 + 0 - 3)/1 + 1 = \mathbf{5}$ positions.

2. Each is $-1.0\,e_i + 1.0\,e_{i+1} + 0.5\,e_{i+2} + 0.1$:

pos 0 "the film was": −0.1 + 0.3 + 0.00 + 0.1 = 0.30 pos 1 "film was not": −0.3 + 0.0 − 0.45 + 0.1 = −0.65 pos 2 "was not bad": 0.0 − 0.9 − 0.30 + 0.1 = −1.10 pos 3 "not bad at": 0.9 − 0.6 + 0.05 + 0.1 = 0.45 pos 4 "bad at all": 0.6 + 0.1 + 0.00 + 0.1 = 0.80

3. ReLU gives [0.30, 0, 0, 0.45, 0.80]; max pooling returns 0.80, from window 4, "bad at all".

4. The kernel responds to a transition out of a negative token. "bad at all" is the tail of the construction "not bad at all" — a phrase whose sentiment is the opposite of its most negative word. A unigram model sees "bad" and predicts negative; this kernel sees the local context in which "bad" is negated and can fire positively instead. Detecting that requires looking at neighbouring positions together, which is precisely what the convolution provides and what a bag-of-words model structurally cannot do.

Note also what was lost: after max pooling, the model knows this pattern fired at strength 0.80 somewhere, and has no idea it was at position 4.

By hand — exercise 03.2

Parameter counting for the real architecture in the notebook.

vocab V = 10,000 embedding d = 100 sequence length L = 200 three parallel Conv1d layers, kernel widths 3, 4, 5, 100 filters each then Linear(300 → 2)
  1. Parameters in the embedding table.
  2. Parameters in one Conv1d of width $k$ with 100 filters. (Remember the kernel spans all input channels, and each filter has a bias.) Sum over the three widths.
  3. Parameters in the final linear layer, and why its input is 300.
  4. Total. What fraction is the embedding — and what does that suggest about where overfitting will come from?
Worked solution

1. $10{,}000 \times 100 = \mathbf{1{,}000{,}000}$.

2. One filter of width $k$ holds $d \times k$ weights plus one bias, so 100 filters cost $100(100k + 1)$:

k=3: 100 × 301 = 30,100 k=4: 100 × 401 = 40,100 k=5: 100 × 501 = 50,100 120,300

3. Each conv contributes 100 pooled features and there are three, so the concatenated vector is 300 long. $300 \times 2 + 2 = \mathbf{602}$.

4. Total $\approx \mathbf{1{,}120{,}902}$, of which the embedding is 89%.

That is the important observation. Nearly the whole model is a lookup table, and a lookup table is the easiest thing in machine learning to overfit — with 2,000 reviews, many of those 10,000 rows are updated only a handful of times and will happily memorise the single review they appeared in. It also tells you where to intervene: shrink the vocabulary, shrink $d$, initialise from pretrained vectors, or freeze the embedding entirely. Tuning the convolutions, which hold 11% of the parameters, would be attacking the wrong end of the model.

In the wild

Word-level vocabularies with an <UNK> bucket are a teaching device. Production text pipelines use subword tokenisation, which has no unknown tokens at all — every string decomposes into pieces that are in the vocabulary: 

from tokenizers import Tokenizer, models, trainers, pre_tokenizers

tok = Tokenizer(models.BPE(unk_token=None))
tok.pre_tokenizer = pre_tokenizers.ByteLevel()
tok.train_from_iterator(corpus, trainers.BpeTrainer(vocab_size=8000))

tok.encode("antidisestablishmentarianism").tokens
# ['anti', 'dis', 'establish', 'ment', 'arian', 'ism']  — nothing is

The consequences run deeper than coverage. A byte-level BPE vocabulary can encode any byte string, which is why a modern model handles code, emoji, and languages it never saw in training. It also decouples vocabulary size from corpus vocabulary, which is what makes the embedding table a design choice rather than a consequence of your data. Building BPE from scratch is the first extension in Chapter 12, and it is the single largest gap between this curriculum and a production language model.
