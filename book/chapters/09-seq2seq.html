Encoder–Decoder Translation

Each model until now mapped a sequence to one label or number. Translation maps a sequence to another sequence. That sequence has a different length, a different language and a different word order. This chapter builds the architecture that does it. It also faces the new problem that generation causes: the model must use its own output as input.

The same thing, three names This chapter says encoder–decoder, because that name tells you the parts. You will see the name seq2seq much more frequently for the same architecture. It is short for sequence-to-sequence, from the 2014 paper of that name by Sutskever, Vinyals and Le. That paper did this with LSTMs, before transformers existed. Papers also say sequence transduction, which is the name in "Attention Is All You Need". All three names mean a model that reads one full sequence and writes another. The lesson folder is 09_seq2seq_translation because you will see that term in real work. There is no difference between them. If someone asks whether your model is seq2seq, they ask whether it has this shape.

Two stacks with different jobs

The encoder reads the source sentence. It makes one contextual vector for each source token. Together, these vectors are the memory. The encoder is exactly the encoder of Chapter 08, with no change. It uses bidirectional (unmasked) attention, because the full source is available at the same time.

The decoder generates the target sentence one token at a time. It is different from the encoder in two ways, and both are necessary:

  1. Its self-attention has a causal mask: position $t$ cannot see $t+1$. At generation time, those tokens do not exist yet.
  2. It has a third sub-layer, cross-attention. This is how the source sentence gets in.

Causal masking

The mask is an upper-triangular boolean matrix. True means "block this": 

def make_causal_mask(L, device):
    return torch.triu(torch.ones(L, L, dtype=torch.bool, device=device), diagonal=1)

diagonal=1 starts the triangle one place above the main diagonal. Thus position $t$ can attend to itself and to each position before it, but to nothing after it. Apply it as scores.masked_fill(mask, float('-inf')) before the softmax, as in Chapter 06.

Select causal mask. The upper triangle becomes dark, and the weights that stay in each row normalize again to sum to 1.

Key concept Masking lets the decoder train in parallel. Without it, you would have to run the decoder one time for each output position: $T$ sequential forward passes for each example. With it, the model calculates all $T$ positions in one pass. Each position sees exactly the prefix that it will have at generation time. The mask makes a parallel calculation simulate a sequential one. It is the reason that transformers train orders of magnitude faster than RNNs.
Example — counting the forward passes
A batch of 64 sentences, each 18 tokens long. WITHOUT masking you would have to run the decoder once per output position, feeding it a progressively longer prefix each time: 18 sequential forward passes per batch. WITH the causal mask, all 18 positions go through in ONE pass. Row t of the attention matrix sees exactly tokens 1..t — the same prefix that pass number t would have supplied. 64 × 18 = 1,152 supervised predictions, one forward pass.

The mask is not a restriction added to attention. It is the method that lets the model calculate a sequential objective in parallel. Generation is still sequential, and it always will be. But training, which uses most of the compute, is not.

Cross-attention

This one line makes the model a translator: 

ca_out, _ = self.cross_attn(tgt, memory, memory)   # Q=tgt, K=V=memory

The query comes from the decoder. It asks: what do I need to make the next French word? The keys and the values come from the memory of the encoder. The attention matrix that results has shape (B, heads, T_tgt, S_src). It is a soft alignment between target positions and source positions.

No mask applies here, and a mask here would be wrong. The full source sentence is known from the start. Also, word order is different between languages. To make the first French word, the model can need the last English word. Statistical machine translation spent two decades on explicit alignment models. Cross-attention learns alignment as a side effect of learning to translate, and you can read the alignment directly from the attention weights. The notebook plots exactly this.

Teacher forcing

Training a generator has a chicken-and-egg problem. To predict token $t$, the decoder needs tokens $1..t-1$. But early in training, the tokens of the model are garbage. Thus it would learn to continue nonsense.

Teacher forcing gives the decoder the true prefix instead. The implementation is a shift of one token: 

logits = model(src, tgt[:, :-1])              # input:  <SOS> w1 w2 ... w_{T-1}
loss   = criterion(logits.reshape(-1, V),
                   tgt[:, 1:].reshape(-1))    # target: w1 w2 ... w_{T-1} <EOS>

The decoder input is the target shifted right, with <SOS> at the start. The prediction target is the target shifted left, with <EOS> at the end. Position $t$ of the input aligns with position $t$ of the output. The causal mask makes sure that no position can see its own answer.

Exposure bias Training always gives a perfect prefix. Generation never does. Thus the model has never seen its own errors, and it does not know how to recover from them. After one wrong token, it is in a state that never occurred in training. This is exposure bias. It is why an undertrained translation model often goes into loops ("de la session de la session…"). Train the notebook model for only a few epochs, and you will see it. Some fixes exist: scheduled sampling, sequence-level objectives and beam search. But the mismatch is part of teacher forcing, and each autoregressive model in production has it.

Autoregressive decoding

memory  = model.encode(src)          # once — the source never changes
tgt_ids = [SOS_IDX]
for _ in range(max_len):
    out = model.decode(torch.tensor([tgt_ids]), memory)
    next_token = model.fc_out(out)[0, -1].argmax().item()
    tgt_ids.append(next_token)
    if next_token == EOS_IDX:
        break

Note three points:

  • The encoder runs one time. People often calculate it again at each step, and that is an expensive error.
  • The loop uses only the logits of the last position. The earlier positions predict again the tokens that the loop already selected.
  • Generation stops at <EOS>, and the model must learn to give it. Thus <EOS> must be in the training targets. A model that never learns it will run to max_len each time.

This loop also does a quadratic amount of wasted work. At step $t$, it encodes the full prefix $1..t-1$ again, but those representations have not changed. Chapter 10 fixes that with a KV cache.

Greedy versus beam search

If you take the argmax at each step, that is greedy decoding. It sees only the next step. The best token now can lead to a poor sentence overall. Beam search keeps the $k$ best partial sequences, ranked by total log-probability, and expands all of them at each step. It reliably improves translation quality by one or two BLEU points. But it usually makes open-ended generation worse: there it gives bland, repetitive text. Translation has approximately one correct answer. Storytelling does not.

Evaluating a translation

Cross-entropy measures how well the model predicts the reference when it gets a perfect prefix. That is not the same as a good translation, and you cannot compare it across vocabularies. BLEU is the standard alternative. It compares the $n$-gram overlap between the hypothesis and the reference for $n = 1..4$, and takes a geometric mean. Then it applies a brevity penalty, so that it does not reward an output of three safe words.

BLEU is a crude tool. It does not know about synonyms or grammar. But in aggregate, it correlates well enough to be useful. For a model of this size, the honest evaluation is to read twenty outputs yourself.

A dataset trap worth remembering The comtrans corpus of NLTK has three alignment files: German–English, German–French and English–French. If you call comtrans.aligned_sents() with no argument, it concatenates all three. Thus a model that seems to learn English→French really trains on three language pairs at the same time. It will give English where you expected French. Always name the file: aligned_sents('alignment-en-fr.txt'). Check your data: print a few pairs and read them. This lesson is general. Almost each corpus has a trap like this, and to print ten examples is the cheapest bug detector in machine learning.

Worked solution

1.

decoder input = tgt[:-1] = [<SOS>, le, chat, dort] = [1, 7, 12, 23] prediction tgt = tgt[1:] = [le, chat, dort, <EOS>] = [7, 12, 23, 2]

2. The upper triangle above the main diagonal:

j=0 j=1 j=2 j=3 i=0 False True True True i=1 False False True True i=2 False False False True i=3 False False False False

3.

pos 0: sees [<SOS>] → predicts "le" pos 1: sees [<SOS>, le] → predicts "chat" pos 2: sees [<SOS>, le, chat] → predicts "dort" pos 3: sees [<SOS>, le, chat, dort] → predicts <EOS>

Each position sees exactly the prefix that it will have at generation time. That match is the full reason for the mask.

4. Without the shift, the input at position $t$ contains the token that it must predict. The causal mask lets a position attend to itself. Thus the model learns the identity function: copy the input to the output. The loss goes to almost zero within one or two epochs.

That is exactly why this bug is dangerous. Almost zero training loss looks like a great success. Here is the sign: validation loss also looks very good (the same trick works there), but the generated output is garbage. At generation time, the input is not the answer, and the model learned nothing else. Each time the loss of a sequence model decreases unrealistically fast, check your shift first.

Calculate a cross-attention alignment, and then interpret it.

source (English): [ the, red, house ] encoder memory keys give these raw scores for the decoder query at target position 2 (generating the word after "la"): score(la → the) = 0.0 score(la → red) = 2.0 score(la → house) = 1.0 d_k = 4, so the scale factor is 1/√4 = 0.5 e^0 = 1.000 e^0.5 = 1.649 e^1 = 2.718
  1. Apply the scale, and calculate the attention distribution over the three source words.
  2. The correct French is "la maison rouge". With that word order, is this alignment sensible for the word that the decoder will make next?
  3. The value vectors are $v_{\text{the}} = [1,0]$, $v_{\text{red}} = [0,1]$ and $v_{\text{house}} = [1,1]$. Calculate the cross-attention output.
  4. The self-attention of the decoder has a mask. Why is it correct that no causal mask applies here?
Worked solution

1. The scaled scores are $[0.0, 1.0, 0.5]$. Apply the exponential: $[1.000, 2.718, 1.649]$. The sum is 5.367.

weights = [0.186, 0.506, 0.307]

2. French puts the adjective after the noun: "la maison rouge". Thus, after "la", the next word must be "maison", which aligns to house, not red. This distribution puts the most weight (0.506) on red. Thus the model would probably make "rouge" next and give "la rouge maison": English word order with French words. That is a known failure of an undertrained translation model. You diagnose it exactly by reading cross-attention weights.

3.

out = 0.186[1,0] + 0.506[0,1] + 0.307[1,1] = [0.186 + 0 + 0.307, 0 + 0.506 + 0.307] = [0.493, 0.813]

4. The mask prevents a position from seeing information that it will not have at generation time. The own future tokens of the decoder are exactly that type of information. The source sentence is not. The model gets all of it before generation starts. A mask on it would stop the model from using source words that come later than the current output position. That makes no sense across languages with different word orders. This exercise is an example: to make the second French word, the model needs the third English word.

How the decoder's loss reaches the encoder

One question is left, and it decides how this architecture trains at all. The model calculates the loss only on the output of the decoder. The encoder has no loss of its own: no reconstruction objective, no auxiliary head, nothing. Thus, by what route does it learn anything?

There is exactly one route. Write $M$ for the memory, which is the output of the top encoder layer. In decoder layer $\ell$, cross-attention makes:

$$Q_\ell = H_\ell W_\ell^{Q}, \qquad K_\ell = M W_\ell^{K}, \qquad V_\ell = M W_\ell^{V}$$

Here $H_\ell$ is the hidden states of the decoder. In the computational graph, $M$ has edges out to $K_\ell$ and $V_\ell$, and to nothing else. Thus the gradient that it gets is:

$$\frac{\partial L}{\partial M} = \sum_{\ell=1}^{N}\left( \frac{\partial L}{\partial K_\ell}W_\ell^{K\top} + \frac{\partial L}{\partial V_\ell}W_\ell^{V\top}\right)$$

That sum is the full training signal of the encoder. Three results follow. They are usually left implicit, so here they are explicitly:

  • There is no $W^Q$ term. The query projections of cross-attention are decoder parameters, trained from $H_\ell$. The source sentence never gives a query. Thus no gradient goes back to the encoder along that edge. The asymmetry in cross_attn(tgt, memory, memory) is not a convention. It decides which half of the model each of those three matrices belongs to.
  • Each decoder layer contributes, and the contributions add. This is the fan of arrows in the stack diagram above, read in reverse. The top encoder layer gets one summed gradient, built from all $N$ decoder layers. That is also why an encoder–decoder is difficult to pipeline across devices. The encoder cannot take its optimizer step until each decoder layer has finished its backward pass.
  • The self-attention of the decoder sends the encoder nothing directly. It contributes only by changing $H_\ell$, which changes $\partial L/\partial K_\ell$. In a real sense, the encoder learns to be useful for lookups. The only feedback that it ever gets is how well its output worked as keys and values.
Key concept This is the general shape of end-to-end training, and you should take the phrase literally. No component of a transformer has a target of its own. Encoders learn representations, heads learn to specialize, and embeddings learn geometry. All of it is a result of one scalar at the far end of the graph, sent back along the edges that exist. When you design a new architecture, ask "what gradient does this part get, and along which edges?". That question usually tells you more than "what is this part supposed to do?".

Teacher forcing severs the recurrence

There is one more difference from the recurrent models of Chapter 04, and it is larger than it looks. With teacher forcing, the input of the decoder is the true prefix. That is a constant, with no gradient of its own. Thus there is no path from the prediction at position $t$ back to the input at position $t+1$. The forward pass connects the positions through causal self-attention. But the graph has no edge at all from the output of one timestep to the input of the next.

The result is that a transformer has no backpropagation through time. Its graph depth is the number of layers, and nothing more. It is not layers times sequence length. An RNN over 200 timesteps multiplies 200 Jacobians on the way back: 200 matrices of partial derivatives, one for each step. A 6-layer decoder over 200 timesteps multiplies 6 sub-layer Jacobians, and it does all 200 positions in parallel. Attention pays $O(L^2)$ memory for this. It gets the short path length of Chapter 06. It also gets a backward pass whose cost does not grow with sequence length.

The severed edge is also the problem When you cut that edge, exposure bias grows in its place. No gradient ever goes from one generated token to the next. Thus the model never gets a penalty for a token that makes the rest of the sentence difficult. It gets a penalty only for a token that is wrong after a perfect prefix. To restore the edge, you must give the model its own output again. But the argmax that selects that token has a zero derivative almost everywhere. That one fact is why sequence-level training needs tools from a completely different area: policy gradients, Gumbel-softmax relaxations and minimum-risk training. It is also why none of these is a small change to the training loop.

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. Validation loss is 2.0 over a vocabulary of 10,000 words. What is the perplexity? How does it compare with chance?
  2. Teacher-forced loss is a healthy 1.8, but generated sentences loop: "de la session de la session…". What does that loss not measure?
  3. A colleague reports BLEU 65 on their dev set. Should you believe it?
Answers

1. $e^{2.0} = 7.4$, against a chance perplexity of 10,000. The model decreased ten thousand options to seven. That is really good, and it is much easier to read than "loss 2.0".

2. Its own errors. The data gave a perfect prefix for each number in that loss. The model never got a score on a state that it made itself. Thus nothing in training gave a penalty for a loop. A low teacher-forced loss and broken generations are completely consistent.

3. No. BLEU 65 is higher than the agreement between most human translators. The most probable explanations are test data that leaked into training, or an evaluation on the training split. A number that is too good tells you about your pipeline, not about your model.

The habit. For each metric, learn three reference values: the chance value, the usable value, and the value that is too good to be true. The third one has saved more projects than the second.

Say it backRecommended

Explain this to your favorite LLM, in your own words: how does the source sentence actually get into the decoder, and why is teacher forcing both necessary and a problem? Then ask it to correct you. Ask it to question each part where you were vague, not only the parts where you were wrong, because the gaps are in the vague parts.

What a good answer covers — open this afterwards, not before
  1. The encoder makes one vector for each source token. Together they are the memory. The model uses only the output of the top encoder layer.
  2. Cross-attention takes its query from the decoder, and its keys and values from that memory. That asymmetry makes it a translator and not a language model.
  3. Teacher forcing gives the true prefix. Thus the model can score all target positions in one parallel pass, not one at a time.
  4. It is necessary because, early in training, the output of the model is noise. If the model learns to continue noise, it learns nothing.
  5. It is a problem because the model never gets a score on its own errors. Thus it cannot learn to recover from one. That is exposure bias.

Most common miss. An answer describes teacher forcing as "just faster training". The speed is a result. The reason for it is that the alternative has no useful signal early in training. The cost is a specific, named failure at generation time.
