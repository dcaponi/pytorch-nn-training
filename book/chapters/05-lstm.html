LSTMs: Gated Memory

The vanishing gradient of Chapter 04 came from repeated multiplication by the same matrix. The LSTM solves this with a second state. The network mostly adds to this state and does not transform it. Thus gradients can move along it without becoming smaller. The network also learns when to write to it, when to forget, and when to read.

Two states, not one

An LSTM cell carries a hidden state $h_t$ and a cell state $c_t$. The cell state is the long-term memory. The hidden state is the working output that goes to the next layer and the next timestep. Three gates control the flow between them. Each gate is a small linear layer and a sigmoid. It gives a vector of numbers in $(0,1)$. This is a soft, differentiable switch, with one value for each memory slot.

$$f_t = \sigma\big(W_f[h_{t-1}, x_t] + b_f\big) \qquad \text{forget: what to keep}$$ $$i_t = \sigma\big(W_i[h_{t-1}, x_t] + b_i\big) \qquad \text{input: what to write}$$ $$o_t = \sigma\big(W_o[h_{t-1}, x_t] + b_o\big) \qquad \text{output: what to expose}$$ $$\tilde{c}_t = \tanh\big(W_c[h_{t-1}, x_t] + b_c\big) \qquad \text{candidate content}$$

Then come the two important lines:

$$\boxed{\;c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t\;} \qquad\qquad h_t = o_t \odot \tanh(c_t)$$

Read the boxed equation carefully. Its shape is the full reason for the architecture. The forget gate scales the old cell state, and the new content is added. No weight matrix multiplies $c_{t-1}$. The path from $c_{t-1}$ to $c_t$ goes through one elementwise multiplication and nothing more.

Key concept In a plain RNN, the backward path is $\prod W_{hh}^\top \operatorname{diag}(\tanh')$. That is a product of matrices, and each one makes the signal smaller. In an LSTM, the matching path along the cell state is $\prod f_t$. That is a product of numbers that the network selects. If a memory slot is important, the network can learn $f_t \approx 1$ for it. Then the gradient goes through that slot almost unchanged for hundreds of steps. Vanishing does not become impossible. It becomes optional, and the network controls it.

This is the same widget as in the last chapter, but read it differently. There, $W_{hh}$ and $\tanh'$ set the multiplier. Here, the multiplier is $f_t$, which the network learns. Set it to 1.0, and the gradient stays flat forever. The forget gate can select that regime.

Why the forget-gate bias starts at 1 A common and useful initialization trick is to set $b_f$ to 1, not 0. Then $\sigma(b_f) \approx 0.73$ at step zero. The cell then remembers by default, and it must learn to forget. A start near zero gives the opposite default. Memory decays before the network has learned that anything is worth keeping, and early training becomes much slower. PyTorch does not do this for you.

Reading the gates as behavior

Gates are vectors. Thus different slots can do different things at the same time. This is one cell, but it is not one memory.

$f$$i$Effect on that slotA use for it
≈1≈0hold the old value, ignore inputremember an open quote across a sentence
≈0≈1discard and overwritereset at a sentence boundary
≈1≈1accumulaterunning count or intensity
≈0≈0clear to zeroend of a phrase, nothing to carry

The output gate is separate for a reason. The cell can hold information that it does not show at that time. Consider a slot that records "we are inside a parenthesis". That slot is important for the closing bracket later. But it is not important for the prediction of the next normal word. $o_t$ lets the cell keep that information but not show it.

The GRU, briefly

The Gated Recurrent Unit combines the forget gate and the input gate into one update gate ($i_t = 1 - f_t$, so a write is also a forget). It has no separate cell state. It has approximately 25% fewer parameters, and on most tasks its accuracy is similar. If you have an LSTM that works, try a GRU. It usually gives free speed, and the same intuition applies.

Using nn.LSTM

self.lstm = nn.LSTM(input_size, hidden_size, num_layers=2,
                    batch_first=True, dropout=0.2)

out, (h_n, c_n) = self.lstm(x)   # x: (B, L, input_size)
#   out : (B, L, hidden_size)    -- h_t at every timestep
#   h_n : (num_layers, B, hidden_size)  -- final h per layer
#   c_n : (num_layers, B, hidden_size)  -- final c per layer

Three details cause most of the confusion:

batch_first=True is not the default. The native layout of PyTorch is (L, B, H), with the sequence first. All other code in this book puts the batch first. Thus set it explicitly, and set it consistently. If you mix the conventions, the model runs and trains, but it silently transposes your batch and your sequence.

out or h_n. Use out when you need a prediction at each timestep (language modeling). Use h_n[-1] when you need one summary of the full sequence (classification, or the regression in this notebook). Note that out[:, -1, :] is equal to h_n[-1] for a unidirectional LSTM. It is the same tensor, reached in two ways.

The dropout argument applies only between layers. It has no effect when num_layers=1, and PyTorch warns you about exactly that. It also never applies to the output of the final layer. If you want dropout there, add your own nn.Dropout after the LSTM.

On Apple MPS, nn.LSTM dropout is broken In PyTorch 2.12 on the MPS backend, the dropout argument of nn.LSTM does not work. It is not applied as random dropout, and a stacked LSTM with dropout>0 fails to train. On the sine task of this chapter, the test MSE stays near 0.4, against approximately 0.0002 on the CPU. nn.RNN and nn.GRU are not affected. On a Mac, train a stacked LSTM with dropout on the CPU, or set dropout=0. The notebook does the first.

Bidirectionality

bidirectional=True runs a second LSTM backward over the sequence and concatenates the outputs. This doubles the output width. It helps a lot for classification, where the full sequence is available. It is impossible for generation, because you cannot read backward from text that does not exist yet. That difference, full context against causal context, comes back in Chapter 09. There it is the main architectural split between the encoder and the decoder.

The task: sine wave prediction

The notebook changes from text to a regression problem. Given 50 samples of a sine wave, predict the 51st. The target is a continuous number. Thus, by the reasoning of Chapter 00, the loss is MSE, which is the Gaussian negative log-likelihood.

This looks like a toy, but it is a good choice. Here are four reasons:

  • A sine wave has a real long-range dependency: the phase, which continues across the full window.
  • The correct answer is exactly known, so you can see exactly how wrong the model is.
  • It needs no corpus.
  • It shows a failure that text hides. If you run the model autoregressively on its own predictions, small errors grow. After a few dozen steps, the wave moves out of phase. This is the same exposure-bias problem that teacher forcing causes in translation.
By hand — exercise 05.1

Do one step of an LSTM cell. It is one-dimensional, so each gate is a single number.

c₀ = 0.8 h₀ = 0.5 x₁ = 1.0 pre-activations already computed for you: forget gate z_f = 2.0 input gate z_i = −1.0 output gate z_o = 0.0 candidate z_c = 1.0 σ(2.0) = 0.881 σ(−1.0) = 0.269 σ(0.0) = 0.500 tanh(1.0) = 0.762 tanh(0.909) = 0.721
  1. Calculate $f_1$, $i_1$, $o_1$ and $\tilde{c}_1$.
  2. Calculate $c_1$. How much of it came from memory, and how much from the new input?
  3. Calculate $h_1$.
  4. Calculate $\partial c_1 / \partial c_0$. Compare it with the plain-RNN factor of approximately 0.25–0.5 from exercise 04.1.
  5. Suppose that this same $f$ stays for 20 steps. What fraction of $c_0$ stays? What if the network had learned $f = 0.99$?
Worked solution

1. $f_1 = \sigma(2.0) = 0.881$, $i_1 = \sigma(-1.0) = 0.269$, $o_1 = \sigma(0) = 0.500$ and $\tilde{c}_1 = \tanh(1.0) = 0.762$.

2.

c₁ = f₁ c₀ + i₁ c̃₁ = 0.881(0.8) + 0.269(0.762) = 0.705 + 0.205 = 0.909

Memory gives 0.705, and the new input gives 0.205. The gates kept 88% of the old value and let in only 27% of the candidate. That is a cell in "hold" mode.

3. $h_1 = o_1 \tanh(c_1) = 0.5 \times \tanh(0.909) = 0.5 \times 0.721 = \mathbf{0.361}$. Note that $h_1$ (0.361) is much smaller than $c_1$ (0.909). The cell holds more than it shows. That is exactly the job of the output gate.

4. Differentiate $c_1 = f_1c_0 + i_1\tilde{c}_1$ with respect to $c_0$. Treat the gates as fixed:

∂c₁/∂c₀ = f₁ = 0.881

There is no weight matrix and no $\tanh'$. There is only the forget gate. Compare the RNN value of 0.273 from exercise 04.1. The LSTM keeps 3.2 times more gradient at each step. Also, unlike the RNN factor, the network can change it.

5. Over 20 steps at $f = 0.881$: $0.881^{20} = 0.079$. Thus approximately 8% stays. This is decay, but it is slow enough to learn through. At $f = 0.99$: $0.99^{20} = \mathbf{0.818}$. Even at 200 steps, $0.99^{200} = 0.134$. The network can really select to remember something for hundreds of timesteps. Compare the RNN, where $0.5^{20} = 10^{-6}$, and that choice did not exist.

By hand — exercise 05.2

Count the parameters, and find one result of the count.

  1. An LSTM cell calculates four pre-activations. Each one comes from the concatenation $[h_{t-1}, x_t]$. For input size $n$ and hidden size $m$, how many parameters is that in total (weights and biases)?
  2. Calculate it for $n = 1$ and $m = 64$, as in the notebook.
  3. How many parameters does a plain RNN with the same sizes have? What is the ratio, and where does it come from?
  4. The LSTM has 4 times the parameters for each unit. Give one argument why a comparison of an LSTM and an RNN at equal hidden size is not fair. What would you do instead?
Worked solution

1. Each of the four gates has a weight matrix over the concatenated input of width $n + m$. It gives $m$ outputs, and it has $m$ biases:

$$4\big[m(n + m) + m\big] = 4m(n + m + 1)$$

2. $4 \times 64 \times (1 + 64 + 1) = 256 \times 66 = \mathbf{16{,}896}$. (PyTorch reports 17,152. nn.LSTM stores two bias vectors, b_ih and b_hh, so its count is $4m(n + m + 2)$. The second bias is redundant, because the two biases always add.)

3. A plain RNN has one of these blocks, not four: $64 \times 66 = 4{,}224$ (PyTorch: 4,288, for the same reason). The ratio is exactly 4×. It comes from the three gates: the single transformation of the RNN, plus $f$, $i$ and $o$.

4. At equal hidden size, the LSTM has four times the capacity. Thus, if it beats the RNN, that proves little. Some of the gain can come from parameters, not from gating. A fair comparison keeps the parameter count fixed. This means that you give the RNN approximately two times the hidden units ($m_{\text{RNN}} \approx 2m_{\text{LSTM}}$, because parameters increase as $m^2$). The LSTM usually still wins on long sequences, but by less. The gap that stays is the part that really comes from gated memory, not from size. Apply this generally: almost each architecture comparison in the literature is confounded by parameter count, unless it explicitly says otherwise.

Feel for the numbersMust do

The LSTM replaces the fixed $\lambda$ of Chapter 04 with $f_t$, a number that the network selects for each slot at each step. The exponential arithmetic is the same. But now you can ask what value the gate needs to hold a memory for a given span, and check that the gate can get to it.

QuantityFloorTypicalCeilingRead it as
Gate output00.5 at init1a soft switch, one value per memory slot
$\sigma(b_f = 1)$—0.731—the "remember by default" initialization
$\prod f_t$, $f = 0.99$, 100 steps—0.366—a third survives — usable
$\prod f_t$, $f = 0.95$, 100 steps—0.0059—already most of the way gone
$\prod f_t$, $f = 1$—11perfect retention — the regime the gate can select
Cell-state path—one multiply, one add—no weight matrix anywhere on it

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. To keep half of a memory over 200 steps, what must $f$ be?
  2. At $f = 0.95$, what is the half-life of a memory in steps?
  3. Compare 50 steps of retention with the forget bias at 0 ($f \approx 0.5$) and with a bias of 1 ($f \approx 0.731$). Why is that one line of initialization so important?
Answers

1. $f = 0.5^{1/200} = 0.99654$. Note how close to 1 it must be. Also note that a sigmoid gets to 0.9965 only at a pre-activation of approximately 5.7. Long memory needs the gate to be driven hard. That is a real thing to learn, not a default.

2. $\ln(0.5)/\ln(0.95) = 13.5$ steps. A gate that looks almost fully open loses half its signal within fourteen words.

3. $0.5^{50} = 8.9\times10^{-16}$ against $0.731^{50} = 1.6\times10^{-7}$. That is nine orders of magnitude from one added constant. The network can learn its way out of either one. But only one of them leaves a gradient large enough to learn with.

The habit. When an architecture gives the network control of a quantity, find the value that it needs for the behavior that you want. Then ask if that value is easy to get to. Often the answer explains an initialization trick.

Say it backRecommended

Explain this to your favorite LLM, in your own words: what does the cell state do that a hidden state cannot, and why does that solve Chapter 04's problem? Then ask it to correct you. Ask it to question each part where you were vague, not only the parts where you were wrong, because the gaps are in the vague parts.

What a good answer covers — open this afterwards, not before
  1. The cell state changes by scaling and addition. A weight matrix never multiplies it.
  2. Thus the backward path along it multiplies only by $f_t$, not by a Jacobian at each step.
  3. The network learns $f_t$ for each slot. Thus it can hold a value near 1 for the important slots and forget in the other slots, at the same time.
  4. Vanishing therefore becomes optional and controllable. It is no longer structural. The network can select not to vanish.
  5. The output gate is separate, so the cell can keep something that it does not show at that time. A single hidden state cannot do that.

Most common miss. An answer lists the three gates and their names. The mechanism is the shape of the cell-state update, not the number of gates. If you can name all three but cannot say why addition is more important than gating, you have the words but not the idea.
