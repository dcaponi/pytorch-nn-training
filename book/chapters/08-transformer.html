The Transformer Encoder

Attention alone is not a model. It cannot see order, it is shallow, and a simple stack of it does not train. This chapter adds three components that change the mechanism of Chapter 06 into an architecture: positional encoding, residual connections with layer normalization, and a position-wise feed-forward network.

Attention is permutation-equivariant

Start with the gap. Take the attention formula and permute the input rows. Each $q_i$, $k_j$ and $v_j$ moves with its token, and each pairwise score stays the same. The output rows are permuted in exactly the same way, and their contents do not change.

Thus "dog bites man" and "man bites dog" give the same set of representations. For a task where word order carries meaning, which is every task, that is fatal. An RNN gets order automatically from the sequential recurrence. Attention removed recurrence, so we must tell it the order.

Positional encoding

The fix is to add a vector that depends on position to each token embedding, before the first attention layer. The original transformer uses fixed sinusoids:

$$PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right) \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$

Even dimensions get sines, and odd dimensions get cosines. The wavelength increases exponentially with the dimension index, from $2\pi$ at $i=0$ up to $10000 \cdot 2\pi$ at the top.

The picture explains the design better than the formula. The columns on the left oscillate quickly, and they tell neighboring positions apart. The columns on the right oscillate slowly, and they encode the approximate location in the sequence. Together they make a multi-resolution code. It is much like a binary counter, where the low bit changes at each step and the high bit changes one time for each half of the sequence. Each position gets a different fingerprint, and positions near each other get similar fingerprints.

Here is the really clever property. For any fixed offset $k$, $PE_{pos+k}$ is a linear function of $PE_{pos}$. It is a rotation, by the angle-addition identities for sine and cosine. Thus a model can learn to attend "three positions back" as one linear operation, applied in the same way at each position. It does not need to memorize each absolute pair. The model can learn relative position.

Why add rather than concatenate It seems that an addition of position to content would damage the content, and you could reasonably expect concatenation. There are two answers. In practice, concatenation costs dimensions that you would prefer to use for meaning. In structure, a high-dimensional space lets a learned embedding keep the two types of information in subspaces that are almost orthogonal, and trained models do exactly that. Modern alternatives mostly perform better than sinusoids. One is learned absolute embeddings. Another is rotary embeddings (RoPE), which rotate $Q$ and $K$ by an angle that depends on position, inside each attention layer. Current large language models use RoPE.

Residual connections

The model does not apply each sub-layer directly. It wraps each one:

$$x \leftarrow \operatorname{LayerNorm}\big(x + \operatorname{Sublayer}(x)\big)$$

The x + is a residual connection, and it makes depth possible. Differentiate it: $\partial(x + f(x))/\partial x = 1 + f'(x)$. Thus the gradient that gets to the input is the gradient from above plus a correction. Even if $f'$ is very small, the 1 stays. Thus gradients have a clear path from the loss to each layer, however deep the stack is.

Key concept This is the same structural idea as the LSTM cell state in Chapter 05: an additive path where gradients do not go through repeated multiplication. The LSTM puts a gate on it. The transformer leaves it open. Each deep architecture that trains successfully has some version of this. The problem of the product of Jacobians in Chapter 04 (one matrix of partial derivatives for each step, all multiplied together) is universal. It is not specific to recurrence.
Example — 24 layers, with and without the skip

Suppose that the Jacobian of each sub-layer has a typical magnitude of $f' = 0.8$. That is not an extreme value. It is only slightly contractive.

WITHOUT residuals: the gradient scales as 0.8²⁴ = 0.0047 layer 1 receives 0.5% of the signal. WITH residuals: each factor is (1 + f′) instead of f′. Even if every f′ were exactly 0, the product of the 1-terms is 1 — layer 1 still receives 100%.

The exact arithmetic is not the point. The structure is. The additive term makes 1 the minimum, not the maximum. Without it, depth multiplies the signal away. With it, depth cannot starve any layer. That is why networks stopped at approximately 20 layers before residual connections, and went past 150 layers immediately after. Nothing else about the training changed.

There is a second way to read it. Each sub-layer calculates a correction to the running representation. It does not replace it. A block that learned nothing useful can give approximately zero, and then it is the identity. Thus more layers are almost harmless. That is why transformer depth scales so easily.

Layer normalization

For each token independently, normalize across the feature dimension:

$$\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$$

$\mu$ and $\sigma^2$ come from the $d_{\text{model}}$ features of that token. $\gamma$ and $\beta$ are a learned scale and shift for each feature. Repeated addition of attention outputs to residuals lets the magnitude of the activations drift. Layer norm sets the scale again at each step. This keeps the network in the range where both its non-linearities and its optimizer behave well.

Compare it with batch normalization. Batch norm calculates statistics across the batch for each feature. Thus the output of each example depends on the other examples in its batch. It needs different behavior in training and in evaluation, and it becomes much worse at small batch sizes. Layer norm looks only at the features of one token. Batch size has no effect, sequence length has no effect, training and evaluation are the same, and inference on one example works without a change. For sequence data with variable length, that is the deciding factor.

Post-norm and pre-norm

The formula above is post-norm, as in the original paper. Modern models almost always use pre-norm:

$$x \leftarrow x + \operatorname{Sublayer}\big(\operatorname{LayerNorm}(x)\big)$$

The difference is whether the residual path goes through a normalization. In pre-norm, it does not. The skip connection is a completely clear path from input to output. Thus deep stacks train without learning-rate warmup, and much more stably. With careful tuning, post-norm sometimes gets slightly better final quality. The notebook uses post-norm to match the original paper. The GPT of Chapter 10 uses pre-norm, as GPT-2 and later models do.

The residual stream is the road back

That is what residual connections do in the forward direction. What makes them necessary is what they do in the backward direction, so look at it now. In a twelve-layer model, there are approximately fifty sub-layers between the loss and the weights of layer 1. At an addition $y = x + f(x)$, the gradient divides into two parts. It does not go through a bottleneck:

$$\frac{\partial L}{\partial x} = \frac{\partial L}{\partial y} + f'(x)^{\top}\frac{\partial L}{\partial y}$$

The first term carries the gradient forward without a change. Expand that across $N$ blocks. One of the terms that results is the pure identity path: the loss gradient gets to layer 1, and nothing multiplied it on the way. Attention blocks and feed-forward blocks add their corrections to that stream. They are not gates that it must go through.

LayerNorm's backward is a projection

One sub-layer does interfere with the stream, and you should know exactly how. Let $\hat{x} = (x - \mu)/\sigma$ over the $d$ features of a token, and write $u = \partial L/\partial \hat{x}$. Then the gradient with respect to the input is:

$$\frac{\partial L}{\partial x} = \frac{1}{\sigma}\Big(u - \operatorname{mean}(u) - \hat{x}\,\operatorname{mean}(u \odot \hat{x})\Big)$$

The two subtractions are projections. The first removes the component of the gradient along the all-ones direction. The second removes the component along $\hat{x}$ itself. Thus LayerNorm discards each part of the gradient that only wants to shift the mean of a token or change its length. That is correct, because normalization would cancel such a change. But it means that each normalization really loses gradient information. It does not only rescale it.

That is the argument for pre-norm in one line. In post-norm, the output of each block goes through this projection on the residual path itself. Thus the identity term above is not really an identity. It is $1/\sigma$ times a projection, $N$ times. In pre-norm, the normalization is inside the branch, and nothing touches the stream. That is why post-norm transformers need learning-rate warmup and pre-norm transformers mostly do not. It is the full difference between the two formulas above.

The feed-forward network

$$\operatorname{FFN}(x) = W_2\,\operatorname{ReLU}(W_1x + b_1) + b_2$$

The model applies it in the same way, independently, at each position. It is really a (1×1) convolution. By convention, the inner dimension is $4d_{\text{model}}$: expand, apply a non-linearity, and project back.

Why is it there at all? Apart from its softmax weights, attention is a linear operation on values. It moves and mixes information, but it does not transform it non-linearly. A stack of attention layers without an FFN is an expensive linear map. The FFN gives the non-linear processing at each position. It also holds approximately two thirds of the parameters in a transformer block ($8d^2$ against $4d^2$ for attention). Recent interpretability research reads it as a key-value memory. The first matrix detects patterns, and the second writes learned facts related to them.

The full encoder block

class TransformerEncoderLayer(nn.Module):
    def __init__(self, d_model, n_heads, d_ff, dropout=0.1):
        super().__init__()
        self.attn  = MultiHeadAttention(d_model, n_heads)
        self.ff    = nn.Sequential(nn.Linear(d_model, d_ff), nn.ReLU(),
                                   nn.Linear(d_ff, d_model))
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.drop  = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        attn_out, _ = self.attn(x, x, x, mask)          # self-attention: Q=K=V=x
        x = self.norm1(x + self.drop(attn_out))
        x = self.norm2(x + self.drop(self.ff(x)))
        return x

That is the full architecture. Stack $N$ of these. Add embeddings and positional encoding at the bottom, and put a task head on top. Each transformer that you know is this block, repeated, at scale. The new ideas since 2017 are about efficiency, position encoding, the location of normalization, and data. They are not about the block.

Note self.attn(x, x, x). The query, the key and the value all come from the same sequence. That is what makes it self-attention. In Chapter 09, the cross-attention of the decoder gives a different tensor for the query. That one change turns the block into a translator.

Pooling for classification

The encoder gives one vector for each token. Classification needs one vector for each sequence. The simple option is a mean over the positions that are not padding, and it works well. BERT adds a [CLS] token at the start and uses its final representation. This is reasonable, because attention lets that position collect information from all positions. It also gives the model a dedicated place for a summary, so the model does not have to use an average.

Pool with the mask x.mean(dim=1) also averages over padding. Thus a 10-token review padded to 200 gets 95% of its representation from <PAD> embeddings. Multiply by the mask, and divide by the true length. This bug silently decreases accuracy. The model still trains, but it trains worse, and nothing in the output tells you why.
By hand — exercise 08.1

Do layer normalization on one token with four features.

x = [2.0, 4.0, 4.0, 6.0] γ = [1, 1, 1, 1] β = [0, 0, 0, 0] ε ≈ 0
  1. Calculate the mean $\mu$ and the variance $\sigma^2$ across the four features.
  2. Normalize each feature.
  3. Make sure that the result has mean 0 and variance 1.
  4. Now let $\gamma = [2,2,2,2]$ and $\beta = [1,1,1,1]$. What is the output? Why would a network ever want to cancel the normalization that it just did?
  5. Suppose that you had applied batch norm to a batch with this token and three others. Which numbers would have gone into the mean? What fails at inference on one example?
Worked solution

1. $\mu = (2+4+4+6)/4 = 4$. The squared deviations are $4, 0, 0, 4$, so $\sigma^2 = 8/4 = 2$ and $\sigma = 1.414$.

2.

(2 − 4)/1.414 = −1.414 (4 − 4)/1.414 = 0.000 (4 − 4)/1.414 = 0.000 (6 − 4)/1.414 = 1.414

3. Mean $= (-1.414 + 0 + 0 + 1.414)/4 = 0$ ✓. Variance $= (2 + 0 + 0 + 2)/4 = 1$ ✓.

4. Output $= 2 \times [-1.414, 0, 0, 1.414] + 1 = \mathbf{[-1.828, 1, 1, 3.828]}$.

Now the reason. Unit variance for each representation is a strong constraint. Sometimes the correct answer really needs a feature with a large magnitude or a mean that is not zero. $\gamma$ and $\beta$ let the network get back any scale and shift that it needs. Thus normalization makes training stable without a decrease in what the model can express. In the extreme case, the network can learn $\gamma = \sigma$ and $\beta = \mu$ and cancel the operation completely. Normalization is a useful default, not a restriction.

5. Batch norm would average feature 0 across all four tokens in the batch: $x_0$ of token 1, $x_0$ of token 2, and so on. It makes four means, one for each feature. At inference on one example, there is no batch to calculate statistics from. Thus batch norm must use running averages from training. That is why it needs different behavior in training and evaluation. Layer norm does not have this problem. The statistics come from inside the token, so one example works exactly like a thousand.

Calculate positional encoding directly.

d_model = 4, so dimension pairs are i = 0 (dims 0,1) and i = 1 (dims 2,3) PE(pos, 2i) = sin(pos / 10000^{2i/4}) PE(pos, 2i+1) = cos(pos / 10000^{2i/4}) 10000^{0} = 1 10000^{0.5} = 100 sin 0 = 0 cos 0 = 1 sin 1 = 0.841 cos 1 = 0.540 sin 2 = 0.909 cos 2 = −0.416 sin 0.01 = 0.010 cos 0.01 = 1.000 sin 0.02 = 0.020 cos 0.02 = 1.000
  1. Calculate $PE(0)$, $PE(1)$ and $PE(2)$. Each one is a 4-vector.
  2. Which dimensions clearly tell position 1 from position 2? Which ones almost do not change?
  3. At what position does dimension 2 complete a full cycle back to $\sin = 0$?
  4. Explain what would go wrong with $d_{\text{model}} = 4$ and a sequence of length 50,000.
Worked solution

1. For $i = 0$ the divisor is 1. For $i = 1$ it is 100.

PE(0) = [sin 0, cos 0, sin 0, cos 0 ] = [0.000, 1.000, 0.000, 1.000] PE(1) = [sin 1, cos 1, sin 0.01, cos 0.01 ] = [0.841, 0.540, 0.010, 1.000] PE(2) = [sin 2, cos 2, sin 0.02, cos 0.02 ] = [0.909, −0.416, 0.020, 1.000]

2. Dimensions 0 and 1 change sharply: the cosine goes from 0.540 to −0.416 between two neighboring positions. Dimensions 2 and 3 almost do not move (0.010 → 0.020, and 1.000 → 1.000 to three decimals). Fast dimensions resolve local position, and slow dimensions carry global position, exactly as the widget above shows.

3. Dimension 2 has $\sin(pos/100)$. Thus a full cycle needs $pos/100 = 2\pi$, which is $pos \approx \mathbf{628}$.

4. Here, the slowest dimension has a wavelength of only approximately 628, and the fast dimensions repeat every 6.3 positions. Over 50,000 positions, many pairs of positions far apart get almost the same code. For example, positions 100 and 13,923 have codes that agree to approximately two decimal places in all four dimensions. The model could not tell them apart. Thus $d_{\text{model}}$ must be large enough that the slowest wavelength ($2\pi \times 10000 \approx 62{,}800$ at realistic sizes) is more than your longest sequence. This also shows why it is difficult to extend the context window of a trained model. The model has never seen the position codes past the training range.

Feel for the numbersMust do

The parameter count of a transformer block is one formula. If you know it, you can size a model, or check a claim about one, without opening a file. It is $12d^2$ for each block, and you derive it from four numbers that you already have.

QuantityFloorTypicalCeilingRead it as
Attention block—$4d^2$—four projections; independent of heads and length
Feed-forward, $d_{ff} = 4d$—$8d^2$—twice the attention block — the FFN is where the parameters are
One whole block—$12d^2$—3.15M at $d = 512$; 7.08M at $d = 768$
LayerNorm parameters—$2d$—negligible, and often forgotten in counts
LayerNorm output, per tokenmean 0—var 1by construction, before $\gamma$ and $\beta$
Embedding table—$V \cdot d$—compares against all the blocks together

Now do these on paper. Where you can, do them in your head. You can use a calculator for the logarithms. The goal is to know which number to use.

  1. GPT-2 small has $d = 768$ and 12 layers. How many parameters are in the transformer blocks?
  2. What fraction of one block is the feed-forward network?
  3. People say that GPT-2 small has 124M parameters. Add the token embedding ($V = 50{,}257$) and the learned position table (1024 slots). Does the total agree?
Answers

1. $12 \times 768^2 = 7.08$M for each block. Multiply by 12 layers to get 84.9M.

2. $8/12 = 67\%$. Two thirds of each transformer is the part with no attention in it. Remember this when someone describes these models as "attention-based".

3. The token embedding is $50{,}257 \times 768 = 38.6$M. The positions are $1024 \times 768 = 0.8$M. The total is $84.9 + 38.6 + 0.8 = \mathbf{124.3}$M. It agrees. The output head adds nothing, because GPT-2 ties it to the input embedding. If you can do this, you can check any model card that someone gives you.

The habit. Calculate again the published parameter count of a model that you did not build. When it agrees, you understand the architecture. When it does not agree, you found the part where you were wrong.

Say it backRecommended

Explain this to your favorite LLM, in your own words: why can you not just stack attention layers — what do the residual connection and the normalization each contribute? Then ask it to correct you. Ask it to question each part where you were vague, not only the parts where you were wrong, because the gaps are in the vague parts.

What a good answer covers — open this afterwards, not before
  1. Attention alone is permutation-equivariant. Thus something must add position before the first layer.
  2. The residual connection puts an identity term, which nothing touches, on the gradient path from the loss to each layer. Thus depth no longer makes the signal smaller.
  3. Normalization sets the activation scale again. Without it, repeated additions would let the scale drift.
  4. The model uses LayerNorm, not BatchNorm, because LayerNorm looks only at the features of one token. Thus batch size and sequence length have no effect, and training and evaluation behave the same.
  5. The feed-forward sublayer holds most of the parameters and does most of the calculation for each position. Attention moves information between positions. The FFN transforms it in place.

Most common miss. An answer says that residuals "help with vanishing gradients" but does not give the mechanism. The point is specific, and you can prove it. When you differentiate $x + f(x)$, a 1 stays. Thus there is a path where nothing multiplies the gradient.
